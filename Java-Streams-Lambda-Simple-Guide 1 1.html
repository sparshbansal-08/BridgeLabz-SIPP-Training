1. Lambda Expression

Definition

"A lambda expression is a short, anonymous (unnamed) block of code that takes parameters and returns a value. It is a concise way to provide the implementation of a functional interface."

Purpose / Why we need it

Before lambdas, providing a small piece of behaviour required writing a full anonymous class, which was long and noisy. Lambdas let us pass behaviour as if it were data, with far less code, making programs shorter and easier to read.

In simple words

A lambda is just a short way to write a small function (a block of code that does something).

The benefit

We avoid writing long code for a simple job. Less typing, easier to read.
Simple example to picture it: Imagine telling a friend a job. The long way: "Take a number, and give me that number plus one." The short way (lambda): n -> n + 1. Same meaning, fewer words.

The shape of a lambda:

(input)  ->  what to do with it

The OLD long way (before lambda) just to add two numbers:

// We had to create a whole class/method to say "add"
interface Adder {
    int add(int a, int b);
}

Adder adder = new Adder() {
    public int add(int a, int b) {
        return a + b;
    }
};
System.out.println(adder.add(2, 3));
5

The NEW short way with a lambda — same result:

Adder adder = (a, b) -> a + b;   // this is the lambda
System.out.println(adder.add(2, 3));
5

One line instead of many. That is the whole point of a lambda.

2. Functional Interface

Definition

"A functional interface is an interface that contains exactly one abstract method. Because it has a single abstract method, it can be implemented by a lambda expression. It may also be marked with the @FunctionalInterface annotation."

Purpose / Why we need it

A lambda expression needs a target type. The single abstract method of a functional interface defines the exact shape of that lambda (its parameters and return type). In short, the functional interface is the "contract" that the lambda fulfils.

Important point: it must be exactly one abstract method — not just any method. A functional interface can still have default methods and static methods; those do not count, because they already have a body. Only the count of abstract methods must be exactly one.

In simple words

A functional interface is an interface with exactly one abstract method. It is the "shape" or "slot" that a lambda fits into.

The benefit

It gives a lambda its type. Think of it this way: the lambda is the plug, the functional interface is the socket.
Simple example to picture it: A wall socket has a fixed shape with one job: give power. Any matching plug fits in. A functional interface is the socket (one job = one abstract method); the lambda is the plug you push in.

In topic 1, Adder was already a functional interface — it had just one abstract method add. We add @FunctionalInterface on top to make our intention clear (Java will then report an error if we accidentally add a second abstract method):

@FunctionalInterface            // label: "this has exactly one abstract method"
interface Greeting {
    String sayHi(String name);   // the ONE abstract method (the slot)
}

// The lambda fills that one slot:
Greeting g = name -> "Hello, " + name + "!";
System.out.println(g.sayHi("Ravi"));
Hello, Ravi!

You do not always need to write your own — Java provides ready-made ones

Java already includes the most common functional interfaces in java.util.function. You will see these everywhere in streams, so it is worth learning these four common ones:

NameIts single abstract methodIn plain wordsTiny example
Predicate<T>boolean test(T)Asks a yes/no questionn -> n > 10
Function<T,R>R apply(T)Takes one thing, returns anothern -> n * n
Consumer<T>void accept(T)Takes a thing, returns nothing (just uses it)x -> print(x)
Supplier<T>T get()Takes nothing, gives a thing() -> "Hi"

All four in action with real data:

import java.util.function.*;

Predicate<Integer> isAdult = age -> age >= 18;     // yes/no
Function<String, Integer> length = s -> s.length();  // String -> its length
Consumer<String> printer = msg -> System.out.println(msg); // uses, returns nothing
Supplier<String> greeter = () -> "Welcome!";        // gives a value

System.out.println(isAdult.test(20));    // is 20 >= 18?
System.out.println(length.apply("Java")); // length of "Java"
printer.accept(greeter.get());        // get the value, then print it
true 4 Welcome!
Easy memory trick: Predicate = Pass/fail (yes/no) • Function = Fetch a new value • Consumer = Consumes & keeps quiet (no return) • Supplier = Supplies out of nowhere.

3. Stream

Definition

"A Stream is a sequence of elements from a source (such as a collection) that supports a pipeline of operations to process those elements. A stream does not store data; it carries elements from a source through a series of operations."

Purpose / Why we need it

Streams let us process collections in a clear, declarative way — we describe what we want (keep some, transform all, total them) instead of writing the step-by-step loop mechanics. This produces shorter, more readable code and supports easy chaining of operations.

In simple words

A Stream lets you take a list and process every item one by one, step by step.

The benefit

You can do things like "keep some", "change all", "add them up" — without writing long loops.
Simple example to picture it: Think of a conveyor belt in a factory. You put items on the belt, and each machine on the belt does one job (clean it, paint it, pack it). A Stream is that belt. Each step (filter, map, and so on) is a machine.
List → .stream() → filter → map → collect

Our data (we will reuse this list a lot):

List<Integer> numbers = List.of(1, 2, 3, 4, 5, 6);

To start the conveyor belt, you call .stream() on the list. By itself it does nothing useful yet — the real work is the next steps (filter, map, and so on).

4. filter()

Definition

"filter is an intermediate stream operation that takes a condition (a Predicate) and returns a new stream containing only the elements that satisfy that condition."

Purpose / Why we need it

To select a subset of the data — we keep only the elements we care about and discard the rest, for example only even numbers, only adults, or only paid orders.

In simple words

filter keeps only the items that pass a condition and throws away the rest.

The benefit

You get only some items, for example only even numbers, only adults, only paid orders.
Simple example to picture it: A sieve or tea strainer. You pour everything in; only what matches passes through. The rest stays back.

Example: Keep only the even numbers.

List<Integer> numbers = List.of(1, 2, 3, 4, 5, 6);

List<Integer> evens = numbers.stream()
        .filter(n -> n % 2 == 0)   // keep if remainder is 0 (even)
        .collect(Collectors.toList());

System.out.println(evens);
[2, 4, 6]

What happened: each number was checked. 1 is odd, so it was removed. 2 is even, so it was kept, and so on. The condition n -> n % 2 == 0 is a lambda (from topic 1), and it acts as a Predicate (from topic 2).

Input itemCondition n % 2 == 0Result
1false (odd)Removed
2true (even)Kept
3falseRemoved
4trueKept
5falseRemoved
6trueKept

5. map()

Definition

"map is an intermediate stream operation that applies a given function to every element and returns a new stream of the transformed elements. It produces exactly one output element for each input element."

Purpose / Why we need it

To transform data — to convert each element into a different value or a different type, for example squaring each number, converting names to uppercase, or extracting the price from each order.

In simple words

map transforms every item into something else. The count stays the same (one in, one out).

The benefit

You can change each item, for example square each number, make names uppercase, or get the price of each order.
Simple example to picture it: A juicer machine. Put in one orange, get one glass of juice. Put in six oranges, get six glasses. Each item becomes a new item, and the count stays the same.

Example 1: Square every number.

List<Integer> numbers = List.of(1, 2, 3, 4);

List<Integer> squares = numbers.stream()
        .map(n -> n * n)        // change each number into its square
        .collect(Collectors.toList());

System.out.println(squares);
[1, 4, 9, 16]
Inputmap: n * nOutput
11 x 11
22 x 24
33 x 39
44 x 416

Example 2: Make names uppercase.

List<String> names = List.of("ravi", "anu", "kiran");

List<String> big = names.stream()
        .map(name -> name.toUpperCase())
        .collect(Collectors.toList());

System.out.println(big);
[RAVI, ANU, KIRAN]

6. flatMap()

Definition

"flatMap is an intermediate stream operation that transforms each element into a stream, and then flattens all those streams into a single combined stream."

Purpose / Why we need it

To flatten nested data. When each element is itself a collection (a list of lists), flatMap merges everything into one single, flat stream so it can be processed as one continuous sequence.

In simple words

flatMap is used when each item is itself a list (a box). It opens all the boxes and puts everything into one single list.

The benefit

When you have a list of lists, you get back one flat list of all the items together.
Simple example to picture it: You have three boxes of chocolates. Each box is a list. flatMap opens every box and pours all chocolates onto one single plate. Now it is one flat list, not boxes inside a list.

Our data: a list that contains three small lists inside it.

// A list OF lists (boxes inside a box)
List<List<Integer>> boxes = List.of(
        List.of(1, 2),
        List.of(3, 4),
        List.of(5, 6)
);

Using flatMap to get one flat list:

List<Integer> flat = boxes.stream()
        .flatMap(box -> box.stream())   // open each box into a stream
        .collect(Collectors.toList());

System.out.println(flat);
[1, 2, 3, 4, 5, 6]

What happened: the three inner lists were merged into a single list of six items. The boxes are gone — everything is on one plate now.

7. map vs flatMap — the key difference

This is the part that often causes confusion. Here is the simplest way to remember it:

map = change each item and keep the same shape (if the input had boxes, the output still has boxes).
flatMap = change each item and remove the boxes (flatten into one list).

Same data, see the difference in output:

List<List<Integer>> boxes = List.of(
        List.of(1, 2),
        List.of(3, 4)
);

// map keeps the boxes (list of lists)
System.out.println(
    boxes.stream().map(box -> box).collect(Collectors.toList())
);

// flatMap removes the boxes (one flat list)
System.out.println(
    boxes.stream().flatMap(box -> box.stream()).collect(Collectors.toList())
);
[[1, 2], [3, 4]] <-- map: still boxes [1, 2, 3, 4] <-- flatMap: one flat list
mapflatMap
JobChange each itemChange each item + flatten
Use whenSimple items (number, name)Each item is a list/box
Result shapeSame shape (boxes stay)Flat single list (boxes gone)
Memory word"transform""transform + merge"

8. A few more simple Stream features 🧰

These are small, very useful steps you can add to your "conveyor belt". Each one is shown with the same simple data so you can focus on what changes.

List<Integer> numbers = List.of(5, 3, 8, 1, 3, 9);

sorted() — put items in order

What: arranges items small → big (or your own order). Why: when you need a sorted result.

List<Integer> sorted = numbers.stream()
        .sorted()                // small to big
        .collect(Collectors.toList());
System.out.println(sorted);
[1, 3, 3, 5, 8, 9]

distinct() — remove duplicates

What: keeps only one copy of each value. Why: to drop repeats (notice the two 3s become one).

List<Integer> unique = numbers.stream()
        .distinct()
        .collect(Collectors.toList());
System.out.println(unique);
[5, 3, 8, 1, 9]

limit() & skip() — take some, jump over some

What: limit(n) keeps the first n; skip(n) ignores the first n. Why: for "top 3", "page 2", etc.

System.out.println( numbers.stream().limit(3).collect(Collectors.toList()) );
System.out.println( numbers.stream().skip(2).collect(Collectors.toList()) );
[5, 3, 8] <-- limit(3): first three [8, 1, 3, 9] <-- skip(2): jumped first two

count() — how many?

What: counts items. Why: to get a number, not a list. Here we count items greater than 3.

long howMany = numbers.stream()
        .filter(n -> n > 3)
        .count();
System.out.println(howMany);
4

reduce() — squeeze everything into one value

What: combines all items into a single result (sum, product, max...). Why: for a grand total. 0 is the starting value, then add each number.

int sum = numbers.stream()
        .reduce(0, (a, b) -> a + b);   // 0+5+3+8+1+3+9
System.out.println(sum);
29

anyMatch() / allMatch() — quick yes/no checks

What: return true/false. anyMatch = "is there at least one?"; allMatch = "are they all?". Why: for quick validations.

System.out.println( numbers.stream().anyMatch(n -> n > 8) ); // any over 8? (9 yes)
System.out.println( numbers.stream().allMatch(n -> n > 0) ); // all positive?
true true

forEach() — do something with each item

What: runs an action for every item (this uses a Consumer from topic 2). Why: usually to print.

numbers.stream()
        .distinct()
        .forEach(n -> System.out.println("Number: " + n));
Number: 5 Number: 3 Number: 8 Number: 1 Number: 9

collect to other shapes — joining text & grouping

collect can build more than a list. Two handy ones:

List<String> names = List.of("Ravi", "Anu", "Kiran");

// 1) Join all names into one String
String joined = names.stream()
        .collect(Collectors.joining(", "));
System.out.println(joined);

// 2) Group names by their length
Map<Integer, List<String>> byLength = names.stream()
        .collect(Collectors.groupingBy(name -> name.length()));
System.out.println(byLength);
Ravi, Anu, Kiran {3=[Anu], 4=[Ravi], 5=[Kiran]}

9. Method Reference 🔗

What is it?

A method reference (written with ::) is an even shorter lambda when the lambda only calls one existing method.

Why do we need it?

Cleaner, shorter code. If your lambda is "just call this method", you can point to that method directly.
Story: Instead of saying "take the message and give it to the printer" every time, you just point at the printer and say "you handle it". System.out::println is that pointing. 
List<String> names = List.of("ravi", "anu", "kiran");

// Lambda version:
names.stream().forEach(name -> System.out.println(name));

// Method reference version — same thing, shorter:
names.stream().forEach(System.out::println);

// Another one: make each name UPPERCASE
names.stream()
     .map(String::toUpperCase)   // same as: s -> s.toUpperCase()
     .forEach(System.out::println);
ravi anu kiran RAVI ANU KIRAN
Rule of thumb: If your lambda is just x -> something.method(x), you can usually replace it with something::method.

10. Optional 🎁

What is it?

Optional is a box that may or may not contain a value. It clearly says "there might be nothing here", instead of giving you a dangerous null.

Why do we need it?

To avoid the famous NullPointerException. Optional forces you to handle the "empty" case safely.
Story: A delivery box arrives. It might have a gift inside, or be empty. Instead of opening it blindly (and maybe finding nothing = crash), Optional lets you ask first: "is anything inside?" and give a backup plan if it's empty.

Where you meet it: findFirst()

Stream methods like findFirst() return an Optional, because maybe nothing matched your filter.

List<String> names = List.of("Ravi", "Anu", "Kiran");

// Find the first name that starts with "A"
Optional<String> found = names.stream()
        .filter(n -> n.startsWith("A"))
        .findFirst();

System.out.println(found);                        // the box itself
System.out.println(found.isPresent());            // is something inside?
System.out.println(found.get());                  // take it out (only if present!)
Optional[Anu] true Anu

The safe way: orElse() gives a backup

Don't call get() blindly. Use orElse() to provide a default when the box is empty.

String result = names.stream()
        .filter(n -> n.startsWith("Z"))   // nothing starts with Z
        .findFirst()
        .orElse("No name found");          // 👈 backup plan

System.out.println(result);
No name found

Useful Optional methods (the simple ones)

MethodWhat it doesExample result
isPresent()true if a value is insidetrue

Optional<String> name = Optional.of("Anu");

// Run code only when there is a value (no null check needed):
name.ifPresent(n -> System.out.println("Hello " + n));

// Transform inside the box, then provide a backup:
String big = name.map(String::toUpperCase).orElse("EMPTY");
System.out.println(big);
Hello Anu ANU
Golden rule: When you see Optional, don't rush to get(). Prefer orElse(...) or ifPresent(...) — that's the whole point: safe handling of "maybe nothing".

11. All together — one full example 🎯

Let's use everything in one real-life style example. Data: a list of people with their hobbies.

// Each person has a name and a list of hobbies
record Person(String name, List<String> hobbies) {}

List<Person> people = List.of(
    new Person("Ravi",  List.of("Cricket", "Reading")),
    new Person("Anu",   List.of("Painting")),
    new Person("Kiran", List.of("Cricket", "Music"))
);

Goal: Get a single list of all hobbies, in UPPERCASE, with no duplicates.

List<String> allHobbies = people.stream()          // 1. start the belt
        .flatMap(p -> p.hobbies().stream())            // 2. open each person's hobby box
        .map(h -> h.toUpperCase())                       // 3. change each hobby to UPPERCASE
        .distinct()                                       // 4. remove duplicates
        .collect(Collectors.toList());                    // 5. put back into a list

System.out.println(allHobbies);
[CRICKET, READING, PAINTING, MUSIC]
