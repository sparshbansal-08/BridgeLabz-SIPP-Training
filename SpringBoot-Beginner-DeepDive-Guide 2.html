1. Maven and pom.xml Explained

Maven is the tool that builds your project and downloads the libraries (JAR files) your code needs. Without it, you would download every library by hand and manage versions yourself.

1.1 What is Maven and why we need it

What is Maven?
Maven is a build and dependency management tool for Java projects. It compiles your code, runs tests, packages the app into a JAR or WAR, and downloads the libraries your project depends on.
Why do we need Maven?
  • Dependency management: you list a library once, and Maven downloads it and all the libraries it needs automatically.
  • Standard build: every Maven project builds the same way (mvn clean package), so any developer can build it.
  • Standard folder layout: code in src/main/java, tests in src/test/java.
  • Repeatable: the same build works on your machine, a teammate's machine, and the build server.
What problem did Maven solve?
Before Maven, developers manually downloaded JAR files, copied them into the project, and fixed version conflicts by hand. Maven automates all of this.

1.2 What POM stands for and why we need it

What does POM stand for?
POM stands for Project Object Model. It is the model (description) of your project written in a file named pom.xml.
What is pom.xml?
It is the central configuration file of a Maven project. It tells Maven the project's name, version, Java version, dependencies (libraries), and build plugins.
Why do we need pom.xml?
Because it is the single place where Maven reads everything it needs to build the project: what libraries to download, which Java version to use, and how to package the app.

1.3 A simple Spring Boot pom.xml

pom.xml<project xmlns="http://maven.apache.org/POM/4.0.0" ...> <modelVersion>4.0.0</modelVersion> <!-- Parent: gives us tested versions for all Spring libraries --> <parent> <groupId>org.springframework.boot</groupId> <artifactId>spring-boot-starter-parent</artifactId> <version>3.3.4</version> </parent> <!-- Identity of THIS project --> <groupId>com.example</groupId> <artifactId>demo</artifactId> <version>0.0.1-SNAPSHOT</version> <properties> <java.version>17</java.version> </properties> <dependencies> <!-- Web: controllers, REST, embedded Tomcat --> <dependency> <groupId>org.springframework.boot</groupId> <artifactId>spring-boot-starter-web</artifactId> </dependency> </dependencies> <build> <plugins> <plugin> <groupId>org.springframework.boot</groupId> <artifactId>spring-boot-maven-plugin</artifactId> </plugin> </plugins> </build> </project>

1.4 Why do we need the Spring Boot parent?

What is spring-boot-starter-parent?
It is a special "parent" POM that your project inherits from. It provides tested, compatible versions of hundreds of libraries, plus sensible default settings.
Why is the parent important?
  • Version management: you do not write versions for Spring dependencies. The parent already knows the correct, compatible version. This avoids version conflicts.
  • Default configuration: it sets the Java compiler, UTF-8 encoding, and plugin defaults for you.
  • Less work: your pom.xml stays short and clean.
This is why in the dependencies above, spring-boot-starter-web has no <version> tag. The parent decides the version, so all Spring libraries stay compatible with each other.

1.5 groupId, artifactId, and version

TagMeaningExample
groupIdThe organization or group that owns the project. Usually a reversed domain name.com.example
artifactIdThe name of this specific project or module.demo
versionThe version of this project. SNAPSHOT means "still in development".0.0.1-SNAPSHOT
Together these three are called the project's coordinates (GAV: GroupId, ArtifactId, Version). They uniquely identify any library in the Maven world, like a postal address.
What happens if I do NOT give a version to my own project?
For your own project, if you remove the <version> tag, Maven gives a build error: "'version' is missing". A project must have a version so it can be identified and packaged.
However, for a dependency that is managed by the parent (like the starters), you intentionally leave the version out, and the parent supplies it. That is correct and not an error.
So when is a missing version an error and when is it fine?
  • Your project's own version missing: error, build fails.
  • Dependency version missing AND a parent/BOM manages it: fine, version is inherited.
  • Dependency version missing AND nothing manages it: error, "'dependencies.dependency.version' is missing".

1.6 Other important parts of pom.xml

ElementWhat it does

What is a "starter" dependency?
A starter is a bundle of related libraries. For example, spring-boot-starter-web brings in Spring MVC, Jackson (JSON), and an embedded Tomcat server, all in one line.
What is the Spring Boot Maven plugin for?
It packages the app into a single executable "fat JAR" that contains your code, all libraries, and an embedded server, so you can run it with java -jar app.jar.

2. Maven Lifecycle and Scopes

2.1 Maven build lifecycle (phases)

When you run a Maven command, it runs that phase and all phases before it, in order.

PhaseWhat it does
validateChecks the project is correct and all needed information is available.
compileCompiles the source code into .class files.
testRuns unit tests using a framework like JUnit.
packageBundles the compiled code into a JAR or WAR file.
verifyRuns checks on the results of integration tests.
installCopies the packaged JAR into your local Maven repository (.m2) so other local projects can use it.
deployUploads the final package to a remote repository for other teams to use.
There is also clean, which is a separate lifecycle. mvn clean deletes the target folder (old build output). We often combine them: mvn clean package.
Common Maven commands$ mvn validate # check the project is set up correctly $ mvn compile # compile the source code $ mvn test # compile + run unit tests $ mvn package # compile + test + build the JAR $ mvn install # package + copy JAR to local .m2 repo $ mvn clean package # delete old build, then build fresh
What is the difference between package and install?
  • package creates the JAR inside the project's target folder.
  • install does everything package does, then also copies the JAR into your local repository (~/.m2) so other projects on your machine can depend on it.
What does mvn clean do?
It deletes the target folder, removing all previously compiled and packaged files so the next build starts fresh.

2.2 Dependency scopes

A scope tells Maven when a dependency is needed (compiling, testing, or running).

ScopeAvailable duringExample use
compile (default)Everywhere: compile, test, run.Spring Web, most libraries.
providedCompile and test, but NOT packaged (the server provides it).Servlet API on an external server.
runtimeTest and run, but not needed to compile.Database driver like MySQL.
testOnly when compiling and running tests.JUnit, Mockito.
Examples of scope in pom.xml<!-- runtime: needed to run, not to compile our code --> <dependency> <groupId>com.mysql</groupId> <artifactId>mysql-connector-j</artifactId> <scope>runtime</scope> </dependency> <!-- test: only used by unit tests --> <dependency> <groupId>org.springframework.boot</groupId> <artifactId>spring-boot-starter-test</artifactId> <scope>test</scope> </dependency>
Why use scopes at all?
To keep the final package small and correct. For example, test libraries should not be shipped inside your production JAR, so they use test scope.

3. @SpringBootApplication and Key Annotations

3.1 What @SpringBootApplication does

DemoApplication.java@SpringBootApplication public class DemoApplication { public static void main(String[] args) { SpringApplication.run(DemoApplication.class, args); } }
What is @SpringBootApplication?
It is the main annotation placed on the class that starts a Spring Boot application. It is a shortcut that combines three other annotations into one.
Which three annotations does it combine?
  • @Configuration: lets the class define beans (objects managed by Spring).
  • @EnableAutoConfiguration: tells Spring Boot to auto-configure beans based on the libraries on the classpath (for example, set up Tomcat if web is present).
  • @ComponentScan: scans the current package and sub-packages to find your controllers, services, and repositories.
Why do we need it / what if we do not use it?
If you remove it, Spring Boot will not auto-configure anything and will not scan your components. Your controllers and services would not be detected, the embedded server may not start, and the app would not work as expected. You would have to add the three annotations yourself.
Why must it be in a top-level package?
Because @ComponentScan scans the package of this class and everything below it. If your other classes are in a parent or unrelated package, they will not be found.

What is the difference between @Controller and @RestController?
@Controller returns a view name and is used with HTML templates. @RestController equals @Controller + @ResponseBody, so every method returns data (JSON or text) directly.
What is the difference between @RequestParam and @PathVariable?
@PathVariable reads part of the URL path (/users/5). @RequestParam reads a query string value (/users?id=5).

4. Spring vs Spring Boot

What is Spring?
Spring is a large Java framework that provides features like dependency injection and web support. With plain Spring, you must configure many things yourself (XML or Java config, server setup, library versions).
What is Spring Boot?
Spring Boot is built on top of Spring. It removes most of the manual configuration by using auto-configuration, starters, and an embedded server. It helps you build a running app very quickly.
PointSpringSpring Boot
ConfigurationMostly manual (XML or Java).Auto-configuration; very little setup.
ServerDeploy a WAR to an external Tomcat.Embedded Tomcat inside a runnable JAR.
DependenciesAdd and match versions by hand.Starters bundle compatible versions.
BoilerplateMore code to wire things up.Much less; sensible defaults.
RunBuild a WAR, deploy to server.mvn spring-boot:run or java -jar.
Best forFull control, custom setups.Fast development, microservices.
Simple way to remember: Spring Boot is Spring plus auto-configuration plus an embedded server. Spring Boot does not replace Spring; it makes Spring easier to use.

5. IoC and Dependency Injection

5.1 Inversion of Control (IoC)

What is IoC (Inversion of Control)?
IoC means the framework, not your code, is in control of creating and connecting objects. Instead of your class creating the objects it needs, Spring creates them and hands them over.
What is the IoC container?
It is the part of Spring that creates, configures, and manages all the objects (called beans). The two main types are BeanFactory (basic) and ApplicationContext (full-featured, used in real apps).
What are the types of IoC container?
  • BeanFactory: the basic container, creates beans only when asked (lazy).
  • ApplicationContext: the advanced container, creates beans at startup (eager) and adds extra features like events and message handling. This is what Spring Boot uses.

5.2 Dependency Injection (DI)

What is Dependency Injection?
DI is the way IoC is achieved. Spring "injects" (supplies) the objects a class needs instead of the class building them itself. A "dependency" is simply another object your class needs to do its work.
What are the types of Dependency Injection?
  • Constructor injection: dependencies are passed through the constructor. Recommended, because the object is always fully built.
  • Setter injection: dependencies are set through setter methods.
  • Field injection: dependencies are placed directly on a field with @Autowired. Easy but harder to test.
Constructor injection (recommended)@Service public class OrderService { private final PaymentService paymentService; // Spring sees this constructor and injects PaymentService automatically public OrderService(PaymentService paymentService) { this.paymentService = paymentService; } }
Why is constructor injection preferred?
  • The object is fully created with all its dependencies set.
  • You can mark fields final, making them safe and read-only.
  • It is easy to test because you just pass mock objects to the constructor.
What is @Autowired?
It tells Spring to inject a matching bean automatically. On a constructor it is optional if there is only one constructor; on a field or setter it marks where the dependency goes.
Why is DI useful (its importance)?
  • Loose coupling: classes do not create their own dependencies, so they are easy to change.
  • Easy testing: you can inject fake (mock) objects in tests.
  • Reusable and clean: Spring manages object creation in one place.

6. Stereotype Annotations (Can We Interchange?)

These annotations all create Spring beans, but each one shows the role of the class.

AnnotationLayer / RoleExtra behavior
@ComponentGeneric bean (any role).None special.
@ServiceBusiness logic layer.None special; shows intent.
@RepositoryData access layer.Translates database exceptions into Spring exceptions.
@ControllerWeb layer (returns views).Works with view resolvers.
@RestControllerWeb layer (returns data).@Controller + @ResponseBody.
Can we interchange @Component, @Service, and @Repository?
Technically yes, the app will often still run, because all three create beans. But you should not, because:
  • @Repository adds useful database exception translation that you lose if you use @Component.
  • The annotations document the class's purpose. Using the right one makes the code readable and correct.
Can we interchange @Controller and @RestController?
No, not safely. @Controller returns a view name (an HTML page). @RestController returns data (JSON/text). If you swap them, a web page controller would return the text "home" instead of rendering home.html, and a REST API would try to find a non-existent view.
What about @Entity?
@Entity is different. It is a JPA annotation that maps a class to a database table. It does not create a Spring bean and cannot be swapped with the others.
Rule of thumb: use @RestController for APIs, @Controller for HTML pages, @Service for logic, @Repository for database access, and @Component only for general helpers.

7. JDBC vs Hibernate vs Spring Data JPA

What is JDBC?
JDBC (Java Database Connectivity) is the lowest-level way to talk to a database in Java. You write SQL yourself and handle connections, statements, and results manually.
What is Hibernate?
Hibernate is an ORM (Object-Relational Mapping) tool. It maps Java objects to database tables, so you work with objects and Hibernate generates the SQL for you.
What is Spring Data JPA?
Spring Data JPA is a layer on top of JPA/Hibernate. You define a repository interface, and Spring generates the implementation, including ready-made methods like save and findAll.
PointJDBCHibernateSpring Data JPA
LevelLowest (manual).ORM framework.Highest (least code).
SQLYou write all SQL.Mostly generated; HQL available.Generated from method names.
BoilerplateA lot.Less.Very little.
MappingManual (rows to objects).Automatic via annotations.Automatic via annotations.
Best forFull control, simple needs.Complex object mapping.Fast development, CRUD apps.
Spring Data JPA: a full repository in a few lines@Repository public interface StudentRepository extends JpaRepository<Student, Integer> { // save(), findAll(), findById(), deleteById() are already provided // This one is auto-implemented just from its name: Student findByName(String name); }
Relationship: Spring Data JPA uses JPA (a standard/specification), and the most common implementation of JPA is Hibernate, which finally uses JDBC to talk to the database. So they build on each other rather than competing.

8. Reading application.properties

8.1 What it is and why we need it

What is application.properties?
It is the main configuration file of a Spring Boot app. It holds settings like the server port, database URL, and your own custom values, written as key=value pairs.
Why do we need it?
So that settings are kept outside the Java code. You can change the database password or port without recompiling the app. It keeps configuration in one easy place.
Why is it read automatically, and only this file?
Spring Boot follows "convention over configuration". By default it looks for a file named exactly application.properties (or application.yml) on the classpath, usually in src/main/resources. This default name is built into Spring Boot, which is why other names are not read unless you tell Spring about them.

8.2 How to read a value, for example name=admin

src/main/resources/application.propertiesapp.name=admin server.port=8080

Way 1: @Value (simple, single values)

Reading app.name with @Value@RestController public class DemoController { // Spring reads app.name from properties and puts "admin" here @Value("${app.name}") private String appName; @GetMapping("/name") public String getName() { return "The name is: " + appName; // -> The name is: admin } }

Way 2: @ConfigurationProperties (groups of values)

Grouping related properties@Component @ConfigurationProperties(prefix = "app") public class AppConfig { private String name; // binds app.name automatically // getters and setters }
What if the property is missing?
With @Value("${app.name}") and no value, the app fails to start. You can give a default: @Value("${app.name:guest}") uses guest if app.name is not set.

8.3 What if I use a different file name instead of application.properties?

If I create myconfig.properties instead, will Spring read it?
No, not automatically. Spring Boot only reads application.properties (or application.yml) by default. A file with any other name is ignored unless you point Spring to it.
How do I read a custom-named properties file?
Use @PropertySource on a configuration class:
Loading a custom file@Configuration @PropertySource("classpath:myconfig.properties") public class CustomConfig { @Value("${app.name}") private String name; // now read from myconfig.properties }
Can I choose a different file when running the app?
Yes. You can pass --spring.config.name=myconfig or --spring.config.location=... on the command line, and Spring Boot will load that file instead of the default.
Summary: the name application.properties is special only because it is Spring Boot's default. For any other name, use @PropertySource or the spring.config options.

9. Exception Handling in Spring Boot

Why handle exceptions?
So the app does not crash or show ugly stack traces to users. Instead it returns a clear message and a correct HTTP status code.

9.1 Local handling with @ExceptionHandler

Handle an exception inside one controller@RestController public class StudentController { @GetMapping("/students/{id}") public Student get(@PathVariable int id) { // if not found, throw an exception throw new StudentNotFoundException("No student with id " + id); } // This method runs when that exception is thrown @ExceptionHandler(StudentNotFoundException.class) @ResponseStatus(HttpStatus.NOT_FOUND) // returns HTTP 404 public String handleNotFound(StudentNotFoundException ex) { return ex.getMessage(); } }

9.2 Global handling with @RestControllerAdvice

This handles exceptions for the whole application in one place.

One global handler for all controllers@RestControllerAdvice public class GlobalExceptionHandler { @ExceptionHandler(StudentNotFoundException.class) public ResponseEntity<String> handleNotFound(StudentNotFoundException ex) { // body + status code together return ResponseEntity.status(HttpStatus.NOT_FOUND).body(ex.getMessage()); } @ExceptionHandler(Exception.class) // catch-all for anything else public ResponseEntity<String> handleOther(Exception ex) { return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR) .body("Something went wrong"); } }
What is the difference between @ExceptionHandler and @RestControllerAdvice?
  • @ExceptionHandler alone handles exceptions only inside the controller where it is written.
  • @RestControllerAdvice handles exceptions across all controllers, keeping error handling in one shared place.
How do I set the error status code in a RestController?
Two common ways:
  • Add @ResponseStatus(HttpStatus.NOT_FOUND) on the handler method.
  • Return a ResponseEntity and set the status with ResponseEntity.status(...), which also lets you set the body.

10. Logging and SLF4J

10.1 Why logging, not System.out.println

Why use a logger instead of System.out.println?
  • Levels: you can label messages as INFO, DEBUG, ERROR, and switch them on or off without changing code.
  • Destinations: logs can go to the console, a file, or a server. println only goes to the console.
  • Format: loggers add time, class name, and thread automatically.
  • Performance and control: you can reduce logging in production and increase it while debugging.

10.2 How to enable logging in Spring Boot

Do I need to add anything to use logging?
No. Spring Boot already includes SLF4J and Logback (a logging implementation) through spring-boot-starter. You can start logging immediately.
Using a logger in any classimport org.slf4j.Logger; import org.slf4j.LoggerFactory; @Service public class StudentService { // Create one logger per class private static final Logger log = LoggerFactory.getLogger(StudentService.class); public void save() { log.info("Saving student..."); // normal information log.debug("Debug details here"); // only when debugging log.error("Something failed"); // errors } }
Control logging levels in application.properties# show DEBUG logs for your own package logging.level.com.example=DEBUG # write logs to a file as well logging.file.name=app.log

10.3 SLF4J, Log4j2, and how they fit together

What is SLF4J?
SLF4J (Simple Logging Facade for Java) is not a logging tool itself. It is a common front (a facade) that your code writes against. Behind it, a real logging library does the actual work.
What is Log4j2 / Logback?
These are real logging implementations that actually write the log messages. Logback is the default in Spring Boot; Log4j2 is a popular alternative.
If I want to enable SLF4J alone, can I? If not, why?
No, SLF4J by itself cannot produce logs, because it is only a facade (an interface). It always needs a real implementation behind it to actually write the logs. So you use SLF4J in your code, but a backend like Logback or Log4j2 must be present to do the work.
So what is needed behind SLF4J?
  • By default: SLF4J + Logback (already included in Spring Boot).
  • To use Log4j2 instead: exclude the default Logback starter and add spring-boot-starter-log4j2. SLF4J then routes your log calls to Log4j2.
Picture it as: Your code → SLF4J (the common interface) → Logback or Log4j2 (the real worker). You always code to SLF4J; you swap the worker behind it without changing your code.

11. DTO - Why We Need It

What is a DTO?
A DTO (Data Transfer Object) is a simple object used to carry data between layers, especially between the backend and the client. It contains only the fields the client should see.
Why do we need a DTO? What if we do not use one?
If you return your @Entity directly:
  • You may expose sensitive fields (like a password hash) to the client.
  • The API breaks if you change the database structure, because the entity is tied to the table.
  • You cannot easily reshape or combine data for the client.
A DTO solves all of these by giving the client a clean, safe, stable shape.
What are the advantages of using DTOs?
  • Security: hide internal fields you do not want to expose.
  • Stability: the API stays the same even if the database changes.
  • Flexibility: combine fields from several entities into one response.
  • Clarity: the client receives exactly what it needs, nothing more.
Entity (database) vs DTO (sent to client)// ENTITY - mapped to the table, has sensitive fields @Entity public class User { @Id private int id; private String username; private String passwordHash; // must NOT be exposed } // DTO - only safe fields go to the client public class UserDTO { private int id; private String username; // no password here }

Simple DTO use-case examples

Use caseWhy a DTO helps
Login responseReturn username and token, never the password.
User profileShow name and email, hide internal id flags and audit fields.
Order summaryCombine customer name + product names into one object.
Public product listShow price and title, hide supplier cost.

12. Calling UI: Controller vs RestController

12.1 Returning a UI page with @Controller

Steps to show an HTML page from the backend:

StepWhat happens
1Browser requests a URL like /home.
2A @Controller method handles it and adds data to the Model.
3The method returns a view name, for example "home".
4The view resolver finds templates/home.html.
5Thymeleaf fills the page with model data and returns finished HTML.
@Controller returns an HTML page@Controller public class PageController { @GetMapping("/home") public String home(Model model) { model.addAttribute("message", "Welcome!"); // data for the page return "home"; // -> renders templates/home.html } }
templates/home.html (Thymeleaf)<h1 th:text="${message}">placeholder</h1>

12.2 Returning data with @RestController

Now the next step: returning raw data (JSON) instead of a page.

StepWhat happens
1Client (browser JS, mobile app, Postman) requests /api/message.
2A @RestController method handles it.
3The method returns an object or String directly.
4Spring converts it to JSON automatically and sends it back.
5The client reads the JSON; no HTML page is involved.
@RestController returns JSON data@RestController public class ApiController { @GetMapping("/api/message") public Map<String, String> message() { // returned object becomes JSON: {"message":"Welcome!"} return Map.of("message", "Welcome!"); } }
In short, how do the two differ when calling the UI?
  • @Controller + Thymeleaf: the server builds the HTML page and sends it. Good for traditional websites.
  • @RestController: the server sends JSON data, and the UI (JavaScript or a mobile app) builds the page. Good for APIs and modern front-ends.

13. Deploying a Spring Boot App

How do I deploy a Spring Boot app to a server?
The most common way is to build a single runnable JAR and run it on the server with java -jar. Because Spring Boot includes an embedded Tomcat, you do not need to install a separate server.

Step-by-step

Build and run the JAR$ mvn clean package # builds target/demo-0.0.1-SNAPSHOT.jar $ java -jar target/demo-0.0.1-SNAPSHOT.jar # runs the app # the app starts on http://localhost:8080
StepAction
1Run mvn clean package to create the JAR in the target folder.
2Copy the JAR to the server (using SCP, FTP, or a pipeline).
3On the server, run java -jar yourapp.jar.
4Set production settings using a profile or environment variables.
5Keep it running with a service manager (systemd) or inside a Docker container.
How do I use production settings?
Create application-prod.properties and run with --spring.profiles.active=prod, or pass values as command-line arguments or environment variables.
Dockerfile (optional, for container deployment)FROM eclipse-temurin:17-jre COPY target/demo-0.0.1-SNAPSHOT.jar app.jar ENTRYPOINT ["java", "-jar", "/app.jar"]
Can I deploy as a WAR instead?
Yes, if you must use an external server. You change packaging to war and extend SpringBootServletInitializer. But the modern, simpler way is the executable JAR.
Never run a production app with debug=true or with test data. Use a real database, a production profile, and proper logging levels.

14. Scenario-Based Questions

14.1 pom.xml scenarios

Your build fails saying a dependency version is missing. What is wrong?
The dependency is not managed by the parent or a BOM, so you must add a <version> tag to it, or add a parent that manages its version.
You added MySQL but the JAR is large and includes test libraries. How do you fix scopes?
Give the MySQL driver runtime scope and test libraries test scope, so only what is needed ships in the package.
Two libraries pull in different versions of the same dependency. What helps?
The Spring Boot parent or a BOM manages versions centrally so they stay compatible. You can also set the version once in <properties>.

14.2 Spring basics scenarios

Your service is not being injected and is null. What is the likely cause?
The class is probably not a Spring bean (missing @Service/@Component), or it is in a package outside the component scan, or you created it with new instead of letting Spring inject it.
Your controller is not found at its URL. What do you check?
Check that the class has @Controller or @RestController, the mapping annotation is correct, and the class is in a package scanned by @SpringBootApplication.

14.3 Entity, Repository, Service, Controller scenarios

You need to save a Student to the database. Which classes do you create?
  • Entity Student with @Entity and @Id.
  • Repository StudentRepository extends JpaRepository<Student, Integer>.
  • Service StudentService with the business logic, calling the repository.
  • Controller to receive the web request and call the service.
You want to find a student by email. How do you add it without writing SQL?
Add a method Student findByEmail(String email); in the repository. Spring Data JPA implements it automatically from the method name.
You want a REST API to return Students as JSON. What do you use?
A @RestController with a @GetMapping that returns the list. Spring converts it to JSON automatically. Prefer returning DTOs instead of entities.

14.4 @SpringBootApplication and application.properties scenarios

After moving the main class into a sub-package, components stopped loading. Why?
Component scanning starts from the main class's package. If your components are now in a parent or sibling package, they are no longer scanned. Move the main class back to the top package.
You set a custom value but it is not read. What do you verify?
Confirm the file is named application.properties and is in src/main/resources, the key spelling matches the @Value("${...}"), and the property is not overridden elsewhere.
You want different settings for local and production. How?
Use profile files like application-dev.properties and application-prod.properties, and activate one with spring.profiles.active.
