Module 1: Introduction to HTML5

The skeleton of every web page — tags, structure, doctypes, and the browser's mental model.

CONCEPT What is HTML?

HTML (HyperText Markup Language) is the standard markup language for creating web pages. It uses tags to describe the structure and content of a page — headings, paragraphs, images, links, forms, etc.

HTML5 is the latest major version — it added native support for video, audio, canvas, semantic tags (<header>, <article>), forms 2.0, web storage, geolocation, and more.

BENEFITS Why HTML?

  • Universal: Every browser understands HTML — no installation needed
  • Lightweight: Plain text — small file sizes, fast to load
  • SEO friendly: Search engines parse HTML structure
  • Accessibility: Screen readers rely on HTML semantics
  • Foundation: CSS and JavaScript both build on top of HTML

SETUP Minimal HTML5 Document

index.html
<!DOCTYPE html> <html lang="en"> <head> <meta charset="UTF-8"> <meta name="viewport" content="width=device-width, initial-scale=1.0"> <title>My Page</title> <link rel="stylesheet" href="styles.css"> </head> <body> <!-- This is a comment --> <h1>Hello, World!</h1> <script src="app.js"></script> </body> </html>

DOCTYPE What is <!DOCTYPE html>?

The FIRST line of every HTML document. Tells the browser "this page uses HTML5", putting it into standards mode.

Without it, browsers fall back to quirks mode — they emulate old buggy IE behavior, breaking modern CSS.

Fun fact: The HTML5 doctype is intentionally short. The HTML4 version was: <!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01//EN"...>

CHARSET Character Encoding

<meta charset="UTF-8"> tells the browser what character set the page uses. UTF-8 is the universal standard — supports every language and emoji.

Place it as the FIRST tag inside <head>, or you risk garbled characters (mojibake).

CRITICAL BOM vs DOM

  • BOM (Browser Object Model): Represents the BROWSER WINDOW. Includes window, navigator, screen, history, location. Not standardized — varies between browsers.
  • DOM (Document Object Model): Represents the PAGE CONTENT as a tree of nodes. Lets JavaScript read/modify HTML. Standardized by W3C.
Mnemonic: BOM = Browser stuff outside the page. DOM = Document content inside the page. document.title is DOM; window.location is BOM.

TAGS <script> and <link>

External resources
<!-- External CSS (in head) --> <link rel="stylesheet" href="styles.css"> <!-- External JS (at end of body, or with defer) --> <script src="app.js"></script> <!-- defer: load in parallel, run AFTER HTML parsed --> <script src="app.js" defer></script> <!-- async: load in parallel, run as soon as ready --> <script src="app.js" async></script>

SYNTAX Comments

HTML comments are not displayed but visible in "View Source":

Comments
<!-- Single-line comment --> <!-- Multi-line comment -->
⚠️ Comments are visible to anyone who clicks "View Page Source". Never put passwords, API keys, or secrets in HTML comments!

Practice Q&A — Introduction

Q1What does HTML stand for, and what is its purpose?
Answer: HTML = HyperText Markup Language. Its purpose is to define the structure and content of web pages using tags — headings, paragraphs, images, links, forms. HTML doesn't handle styling (CSS) or behavior (JavaScript) — it just describes WHAT is on the page.
Q2What does <!DOCTYPE html> do, and why is it important?
Answer: Tells the browser the page uses HTML5. MUST be the first line of every HTML document.

Why important: Without it, browsers enter quirks mode and emulate old buggy Internet Explorer behavior — breaking modern CSS layouts, box-sizing, etc.
Q3Explain the difference between BOM and DOM with examples.
Answer:
  • DOM — page CONTENT as a tree. Examples: document.getElementById(), document.querySelector(), document.title.
  • BOM — BROWSER WINDOW features. Examples: window.alert(), window.location.href, navigator.userAgent, screen.width, history.back().
Quick test: document.* = DOM. window.*, navigator.*, history.* = BOM.
Q4Why use <meta charset="UTF-8"> and where should it go?
Answer: Declares UTF-8 encoding which supports every language plus emojis. Without it, special characters (é, ñ, 漢字, 🎉) may display as garbled symbols ("mojibake").

Placement: The FIRST tag inside <head>, before <title>, so the browser knows the encoding before parsing any text.
Q5Write the syntax for an HTML comment. Are comments visible to users?
Answer: <!-- This is a comment -->

Comments are NOT rendered on the page, but they ARE visible to anyone who clicks "View Page Source" (Ctrl+U). Never put passwords, API keys, or secrets in HTML comments.
Q6What's the difference between defer and async on a script tag?
Answer: Both load the script in parallel with HTML parsing, but execute differently:
  • async — runs as soon as downloaded, possibly interrupting parsing. Order unpredictable. Use for independent scripts (analytics).
  • defer — runs after HTML parsing complete, in document order. Use for scripts that depend on the DOM.
Without either: browser blocks parsing until script downloads and runs.
Q7List 3 benefits HTML5 brought over HTML4.
Answer:
  1. Native multimedia: <audio> & <video> — no Flash plugin needed.
  2. Semantic tags: <header>, <nav>, <article>, <footer> — better SEO.
  3. New form inputs: email, date, number, range, plus required, placeholder, autofocus.
Bonus: Web Storage, Geolocation, Canvas, simpler doctype.
Q8Write a minimal valid HTML5 document.
Answer: 
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>My Page</title>
</head>
<body>
  <h1>Hello</h1>
</body>
</html>
Required: doctype, <html> with lang, <head> with charset and <title>, and <body>.

Practice Q&A — Elements

Q1What's the difference between <b> and <strong>?
Answer: Both display bold by default, but the difference is semantic:
  • <b> — purely visual, no semantic meaning. "Make this bold."
  • <strong> — indicates IMPORTANCE. Screen readers may emphasize audibly. SEO weights it.
Same applies to <i> (visual italic) vs <em> (emphasis). Always prefer the semantic version.
Q2What's the most fundamental rule about the id attribute?
Answer: An id must be unique within the page. No two elements can share the same id. Violating this breaks document.getElementById(), CSS targeting, and URL fragments. For repeating styles, use class instead.
Q3Can an element have multiple classes? Multiple ids?
Answer:
  • Multiple classes: ✅ Yes. Separate with spaces: class="btn primary large"
  • Multiple ids: ❌ No. Only ONE id attribute, and that id can only be used once per page.
Q4List 5 block-level and 5 inline elements.
Answer:
  • Block: <div>, <p>, <h1>-<h6>, <section>, <article>, <ul>, <ol>, <form>, <table>
  • Inline: <span>, <a>, <strong>, <em>, <img>, <input>, <label>, <br>
Block = full width + new line. Inline = flows with text + content width only.
Q5What is placeholder, and where is it used?
Answer: placeholder shows hint text inside an input that disappears when user starts typing. It's a hint, NOT a default value. 
<input type="email" placeholder="you@example.com">
Used on <input> and <textarea>. ⚠️ Don't use as label replacement — disappears when typing, screen readers may not announce it.
Q6Write HTML for a table with 2 columns ("Name", "Age") and 2 data rows.
Answer: 
<table>
  <thead>
    <tr>
      <th>Name</th>
      <th>Age</th>
    </tr>
  </thead>
  <tbody>
    <tr><td>Alice</td><td>30</td></tr>
    <tr><td>Bob</td><td>25</td></tr>
  </tbody>
</table>
Q7Why is the alt attribute important on <img>?
Answer: Three reasons:
  1. Accessibility: Screen readers read it aloud for blind users.
  2. Fallback: If image fails to load, alt text is shown.
  3. SEO: Search engines can't see images — alt tells them what's there.
For decorative images, use alt="" so screen readers skip them.
Q8Difference between <ol> and <ul>?
Answer:
  • <ol> — ordered list: numbered (1, 2, 3...). Order matters (recipe steps).
  • <ul> — unordered list: bullets. Order doesn't matter (shopping items).
Both contain <li> elements.
Q9What does colspan="2" do in a table cell?
Answer: Makes that cell span 2 columns horizontally. Similarly, rowspan="3" spans 3 rows vertically. Useful for headers grouping multiple columns. 
<tr><th colspan="2">Personal Info</th></tr>
<tr><td>Name</td><td>Age</td></tr>
Q10What is the difference between block and inline elements? Give 2 examples each.
Answer:
  • Block elements — take full width, force a new line before/after. You can set width/height. Examples: <div>, <p>, <h1>, <section>.
  • Inline elements — only as wide as content, flow with text. Width/height ignored. Examples: <span>, <a>, <strong>, <img>.
To get inline behavior with size control, use display: inline-block.

Module 4: Navigation

Hyperlinks, anchor tags, navigation structures, and section linking.

LINKS The Anchor Tag

Hyperlinks
<!-- Link to external site --> <a href="https://google.com">Google</a> <!-- Open in new tab (with security) --> <a href="https://x.com" target="_blank" rel="noopener noreferrer">X</a> <!-- Internal page (relative path) --> <a href="about.html">About</a> <!-- Email link --> <a href="mailto:hi@x.com">Email us</a> <!-- Phone link (mobile) --> <a href="tel:+1234567890">Call us</a> <!-- Download a file --> <a href="resume.pdf" download>Download CV</a>
⚠️ Security: Always add rel="noopener noreferrer" to target="_blank". Without it, the new page can manipulate your original page via window.opener (phishing risk).

JUMP Linking to Page Sections

In-page navigation
<!-- Step 1: Mark target with id --> <h2 id="contact">Contact Us</h2> <!-- Step 2: Link to it with #id --> <a href="#contact">Jump to Contact</a> <!-- Link to a section on ANOTHER page --> <a href="products.html#laptops">See laptops</a> <!-- Link to top of page --> <a href="#top">Back to top</a>

SEMANTIC <nav> Element

Wraps your main navigation links. Screen readers can skip directly to it.

Standard nav
<nav> <ul> <li><a href="/">Home</a></li> <li><a href="/about">About</a></li> <li><a href="/contact">Contact</a></li> </ul> </nav>

PATHS Relative vs Absolute URLs

  • Absolute URL: Full URL — https://example.com/page.html. Works regardless of where you link from.
  • Relative URL: Path relative to current page:
    • page.html — same folder
    • ./page.html — explicit "current folder"
    • ../page.html — parent folder
    • /page.html — root of site
    • folder/page.html — subfolder

Practice Q&A — Navigation

Q1How do you make a link open in a new tab safely?
Answer: 
<a href="https://example.com" target="_blank" rel="noopener noreferrer">
  Open in new tab
</a>
Always add rel="noopener noreferrer". Without noopener, the new page can use window.opener to redirect or phish your original page.
Q2How do you create a link that jumps to a section on the same page?
Answer: Two steps:
  1. Give target a unique id: <h2 id="features">Features</h2>
  2. Link with href="#" + the id: <a href="#features">See features</a>
Clicking scrolls to that element and updates URL to page.html#features.
Q3What's the difference between an absolute URL and a relative URL?
Answer:
  • Absolute: Full URL — https://example.com/about.html. Use for external links.
  • Relative: Path relative to current page — about.html, ../images/logo.png. Use for internal links — easier when site moves domains.
Q4How do you create a "mailto" link with subject pre-filled?
Answer: 
<a href="mailto:hello@example.com?subject=Inquiry&body=Hi%20there">
  Email Us
</a>
Spaces in subject/body must be URL-encoded as %20. Multiple parameters separated by &. Similarly tel: works for phone numbers.
Q5What does the download attribute do?
Answer: Tells the browser to download the linked file instead of navigating to it. 
<a href="report.pdf" download>Download Report</a>
<a href="report.pdf" download="quarterly-report.pdf">Download</a>
Optional value sets the suggested filename. Only works for same-origin URLs (security).
Q6What does ../page.html mean as a path?
Answer: Go UP one folder, then look for page.html. Each ../ moves up one directory level. So ../../images/logo.png goes up 2 folders, then into the images folder.

Practice Q&A — Events

Q1Difference between onchange and oninput?
Answer:
  • onchange — fires when value changes AND element loses focus (text inputs). For <select> and checkboxes, fires immediately on selection.
  • oninput — fires IMMEDIATELY on every keystroke. Doesn't wait for blur.
Use case: Live search → oninput. Validation after typing → onchange.
Q2When does onblur fire? Give a use case.
Answer: Fires when an element loses focus — user clicks elsewhere or tabs to another field.

Use case: Validate an email field as soon as user moves on: 
emailInput.addEventListener('blur', () => {
  if (!emailInput.value.includes('@')) {
    showError('Invalid email');
  }
});
Q3What does onbeforeunload do?
Answer: Triggers right before user leaves the page (closes tab, navigates away, refreshes). Common use: warn about unsaved changes. 
window.addEventListener('beforeunload', (e) => {
  if (hasUnsavedChanges) {
    e.preventDefault();
    e.returnValue = '';
  }
});
⚠️ Modern browsers ignore custom messages and show a generic prompt — to prevent abuse.
Q4What is oncanplay used for?
Answer: A media event for <audio> and <video>. Fires when browser has buffered enough to start playing without immediately stopping for more buffering. Use it to enable a "Play" button only when media is ready, or hide a loading spinner.
Q5Which is the BEST way to attach an event handler? Why?
Answer: addEventListener is best: 
btn.addEventListener('click', handler);
Reasons:
  1. Multiple handlers: Attach many to same event. Inline onclick= only allows ONE.
  2. Separation: Keeps JS out of HTML.
  3. Removable: removeEventListener can detach later.
  4. Capture phase support.
Q6Difference between load and DOMContentLoaded?
Answer:
  • DOMContentLoaded — fires when HTML parsed and DOM ready. Doesn't wait for images, stylesheets.
  • load — fires when EVERYTHING loaded — images, fonts, iframes, all resources.
Use DOMContentLoaded for most JS init (faster). Use load only when you need image dimensions.
Q7What's the difference between onclick and ondblclick?
Answer:
  • onclick — fires on a single click.
  • ondblclick — fires on a double-click. Note: onclick ALSO fires twice before ondblclick fires, so don't combine them on the same element without care.

Practice Q&A — Forms 2.0

Q1What does required do, and where can it be used?
Answer: Boolean attribute that prevents form submission if the field is empty. Browser shows built-in error message and highlights the field.

Used on: <input>, <textarea>, <select>. 
<input type="text" name="username" required>
Q2Difference between placeholder and a default value?
Answer:
  • placeholder — hint text that DISAPPEARS when typing. Field starts empty.
  • value — actual content. User must DELETE it to enter their own.
<input placeholder="Enter name">  <!-- Empty, hint shown -->
<input value="John">             <!-- "John" is in the field -->
Q3What does autofocus do?
Answer: When page loads, the browser automatically places cursor in this field — no clicking. Only ONE element per page should have autofocus.

Common use: search box on homepage, username field on login.
Q4Difference between readonly and disabled?
Answer:
readonlydisabled
User can edit?❌ No❌ No
Submitted with form?✅ Yes❌ No
Receives focus?✅ Yes❌ No
Visual styleNormalGreyed out
Use: readonly when value matters (auto-generated ID). disabled when option isn't currently available.
Q5Write an input that accepts only 6-digit pincodes.
Answer: 
<input type="text"
       pattern="[0-9]{6}"
       title="Enter a 6-digit pincode"
       required>
pattern uses regex. [0-9]{6} means exactly 6 digits. title shows as tooltip and validation message.
Q6List 5 new input types added in HTML5.
Answer: email, url, tel, number, range, date, time, color, search, file. Each provides type-specific validation and (on mobile) optimized keyboards.
Q7What is <output> and what's it used for?
Answer: An HTML5 element that displays the result of a calculation. Commonly used with form inputs and the oninput event for live results — like showing the sum of two numbers, or current value of a slider.

Module 7: Web Storage

Storing data in the browser — localStorage and sessionStorage.

CONCEPT Why Web Storage?

Before HTML5, browsers stored data in cookies — small (4KB), sent with every HTTP request. Web Storage is bigger (~5-10MB), stays in the browser only, and is much easier to use.

localStoragesessionStorageCookies
Persists?Forever (until cleared)Until tab closedConfigurable expiry
Size~5-10 MB~5-10 MB~4 KB
Sent to server?❌ No❌ No✅ With every request
Across tabs?✅ Shared❌ Per-tab✅ Shared

API Web Storage Methods

Both have the SAME API — only difference is persistence:

API
// Save data localStorage.setItem('username', 'alice'); // Retrieve data const name = localStorage.getItem('username'); // → "alice" // Remove a single key localStorage.removeItem('username'); // Clear EVERYTHING localStorage.clear(); // How many items localStorage.length; // Same API, but for sessionStorage: sessionStorage.setItem('tempData', 'X');

PATTERN Storing Objects (JSON Trick)

Web Storage only stores STRINGS. To store objects, convert with JSON:

Objects
// Store an object const user = { name: 'Alice', age: 30 }; localStorage.setItem('user', JSON.stringify(user)); // Retrieve and parse back const stored = JSON.parse(localStorage.getItem('user')); console.log(stored.name); // "Alice"

Practice Q&A — Web Storage

Q1Main difference between localStorage and sessionStorage?
Answer:
  • localStorage — persists FOREVER, until manually cleared. Survives browser restarts.
  • sessionStorage — cleared when TAB is closed. Different tabs have separate sessionStorage.
Both scoped to origin (protocol + domain + port).
Q2How do you save and retrieve data using localStorage?
Answer: 
// Save
localStorage.setItem('theme', 'dark');

// Retrieve
const theme = localStorage.getItem('theme');
// → "dark"
Q3How do you store an object in localStorage?
Answer: Convert to JSON string before saving: 
const user = { name: 'Alice', age: 30 };

// Store
localStorage.setItem('user', JSON.stringify(user));

// Retrieve
const data = JSON.parse(localStorage.getItem('user'));
Without JSON.stringify, your object becomes "[object Object]".
Q4How do you delete one key vs all keys?
Answer: 
localStorage.removeItem('username');  // one key
localStorage.clear();                  // EVERYTHING
Q5Why shouldn't you store sensitive data in localStorage?
Answer: localStorage is accessible to ANY JavaScript on the same origin. If your site has an XSS vulnerability, attackers can read all localStorage data — including auth tokens.

For sensitive auth data, prefer httpOnly cookies (which JavaScript cannot access).
Q6Compare Web Storage vs Cookies in 3 ways.
Answer:
  1. Size: Web Storage ~5-10 MB; Cookies only ~4 KB.
  2. Network: Cookies sent with EVERY HTTP request. Web Storage stays in browser only.
  3. API: Web Storage has clean methods. Cookies require manual string parsing.
Use cookies for server-side auth; Web Storage for client-only data.

Module 8: Web SQL Database

A deprecated client-side SQL database API. Still in syllabi for historical context.

⚠️ DEPRECATED Important Context

Web SQL was an HTML5 API for storing data in a relational database in the browser, queried with SQL. It is officially deprecated — Chrome removed it in 2023; Firefox and Safari never fully implemented it.

Modern replacement: Use IndexedDB (key-value with indexes, asynchronous, supported everywhere).

API openDatabase()

Opens (or creates) a database in the browser:

Open database
const db = openDatabase( 'mydb', // 1. Database name '1.0', // 2. Version 'My Database', // 3. Display name 2 * 1024 * 1024 // 4. Estimated size in bytes (2MB) );

API transaction()

All database operations happen inside a transaction — a unit of work that either fully completes or fully fails (rollback).

Create & query
db.transaction(function(tx) { // Create table tx.executeSql('CREATE TABLE IF NOT EXISTS users (id INTEGER PRIMARY KEY, name TEXT)'); // Insert data (parameterized) tx.executeSql( 'INSERT INTO users (name) VALUES (?)', ['Alice'] ); // Query data tx.executeSql('SELECT * FROM users', [], function(tx, results) { for (let i = 0; i < results.rows.length; i++) { console.log(results.rows.item(i).name); } } ); });

Practice Q&A — Web SQL

Q1What is Web SQL Database, and what's its current status?
Answer: Web SQL was an HTML5 API for client-side relational database storage, accessed via SQL queries. It's been deprecated — only WebKit-based browsers supported it, and Chrome removed it in 2023. Modern replacement is IndexedDB.
Q2What 4 arguments does openDatabase() take?
Answer:
  1. Database name — string identifier
  2. Version — string like "1.0"
  3. Display name — human-readable description
  4. Estimated size — bytes (e.g., 2 * 1024 * 1024 for 2MB)
Optional 5th argument: callback fired on creation.
Q3Why does Web SQL wrap operations in a transaction?
Answer: Transactions ensure ATOMICITY — all SQL statements either succeed together or fail together (rollback). This prevents the database from being left in an inconsistent state if one operation fails midway.
Q4Why use parameterized queries (?) instead of string concatenation?
Answer: To prevent SQL injection: 
// ⚠️ DANGEROUS - vulnerable
tx.executeSql("INSERT INTO users (name) VALUES ('" + userInput + "')");

// ✅ SAFE - parameters escaped
tx.executeSql('INSERT INTO users (name) VALUES (?)', [userInput]);
If userInput = "'); DROP TABLE users;--", the first version executes malicious SQL. Parameterized queries treat input as data, not code.
Q5How do you read query results in Web SQL?
Answer: The success callback receives a results object with a rows collection: 
tx.executeSql('SELECT * FROM users', [], (tx, results) => {
  for (let i = 0; i < results.rows.length; i++) {
    const row = results.rows.item(i);
    console.log(row.name);
  }
});

Module 9: Geolocation API

Get the user's location (with permission) — for maps, weather, store finders.

CONCEPT The Geolocation API

The browser exposes navigator.geolocation. The user MUST grant permission via a browser prompt before location is available.

⚠️ HTTPS required: Geolocation only works on HTTPS pages (or localhost for dev). On HTTP, the API is silently disabled.

METHOD getCurrentPosition()

Get a one-time location reading:

Get position
navigator.geolocation.getCurrentPosition( // Success callback (position) => { const lat = position.coords.latitude; const lng = position.coords.longitude; console.log(`Lat: ${lat}, Lng: ${lng}`); }, // Error callback (error) => console.error(error.message), // Options { enableHighAccuracy: true, timeout: 5000, maximumAge: 0 } );

METHOD watchPosition() / clearWatch()

For continuous tracking (e.g., turn-by-turn navigation):

Watch position
const watchId = navigator.geolocation.watchPosition( (pos) => updateMap(pos), (err) => console.error(err) ); // Stop watching when done navigator.geolocation.clearWatch(watchId);

PROPS Position Properties

PropertyDescription
latitudeDecimal degrees (-90 to 90)
longitudeDecimal degrees (-180 to 180)
accuracyAccuracy of lat/lng in meters
altitudeMeters above sea level (may be null)
altitudeAccuracyAltitude accuracy in meters
headingDirection of travel in degrees (0=N)
speedSpeed in meters/second

Plus position.timestamp — when reading was taken.

ERRORS Error Codes

CodeConstantMeaning
1PERMISSION_DENIEDUser refused permission
2POSITION_UNAVAILABLECouldn't determine location
3TIMEOUTRequest took longer than timeout

OPTIONS Position Options

OptionDescription
enableHighAccuracytrue: GPS (slower, more battery, more accurate). false: WiFi/cell triangulation (faster).
timeoutMax time (ms) to wait. After this, error code 3 fires.
maximumAgeMax age (ms) of cached position. 0 = always fresh.

Practice Q&A — Geolocation

Q1How do you check if Geolocation is supported?
Answer: 
if ('geolocation' in navigator) {
  navigator.geolocation.getCurrentPosition(success, error);
} else {
  alert('Geolocation not supported');
}
Q2Difference between getCurrentPosition() and watchPosition()?
Answer:
  • getCurrentPosition() — gets location ONCE.
  • watchPosition() — keeps tracking, fires callback on every change. Returns a watchId.
Stop watching with navigator.geolocation.clearWatch(watchId) — important to save battery!
Q3List 4 properties of the position.coords object.
Answer: latitude, longitude, accuracy (meters), altitude, altitudeAccuracy, heading (direction), speed. Plus position.timestamp outside coords.
Q4What are the 3 possible error codes?
Answer:
  1. Code 1 (PERMISSION_DENIED): User refused permission or has location blocked.
  2. Code 2 (POSITION_UNAVAILABLE): Couldn't determine location — GPS unavailable, no signal.
  3. Code 3 (TIMEOUT): Took longer than timeout option specified.
Q5What does enableHighAccuracy: true do?
Answer: Tells browser to use the most accurate method available — usually GPS on mobile. Tradeoffs: slower, more battery drain. For "find my city" use cases, leave it false (default) — WiFi/cell triangulation is faster and accurate enough.
Q6Why doesn't Geolocation work on HTTP?
Answer: Modern browsers require HTTPS for privacy-sensitive APIs including Geolocation. Without HTTPS, anyone on the network could intercept location data. Use HTTPS in production or localhost in development.
