What Are These Tools and Why Do We Need Them?

Before writing a single line of test code, you must understand what problem each tool solves. Each one has a specific job, and together they form a complete quality net under your code.

🧪

JUnit 5

The testing framework. Lets you write methods that verify your code works correctly. The foundation of everything else.

🎭

Mockito

Creates fake versions of dependencies (databases, APIs). Test your class in isolation without needing real infrastructure.

📊

JaCoCo

Measures what percentage of your code is actually tested. Generates coloured HTML reports showing tested vs untested lines.

🔍

SpotBugs

Scans your compiled bytecode for real bugs — null pointers, wrong comparisons, resource leaks — before they hit production.

Real-world problem each tool solves

📌
JUnit — "Did I break something?"

A developer changes the interest calculation formula in a banking app. Without JUnit tests, the only way to verify nothing broke is to manually test dozens of scenarios. With JUnit, 50 tests run in 3 seconds and instantly show if any scenario is now wrong.

📌
Mockito — "I can't test this because it needs a database"

An OrderService calls PaymentGateway (charges real money), InventoryDatabase (needs a server), and EmailService (sends real emails). With Mockito, you create fake versions that return controlled responses. No real money charged. No server needed. Tests run in milliseconds.

📌
JaCoCo — "How much of my code is tested?"

A team has 200 test cases and feels confident. JaCoCo reveals only 38% of code paths are tested. The untested 62% contains the exact code paths that fail in production. JaCoCo shows precisely which lines need more tests.

📌
SpotBugs — "Find bugs before users do"

A developer compares two Integer objects with == instead of .equals(). Works for values 1–127 (due to Java caching) but silently fails for 128+. SpotBugs catches this in 2 seconds at build time. Without it, this bug only appears in production when order quantity exceeds 127.

How the four tools connect

Pipeline flow
  You write code
       |
       v
  SpotBugs  ──── Scans .class files for bugs BEFORE tests even run
       |
       v
  JUnit 5   ──── You write test methods that verify your logic
       |
       v
  Mockito   ──── Inside JUnit tests, mocks replace real dependencies
       |
       v
  JaCoCo   ──── Measures which lines your JUnit+Mockito tests covered
       |
       v
  Build PASSES or FAILS based on quality gates

Maven Setup — All Four Tools in One pom.xml

Everything is configured in your project's pom.xml. Add this once, and all four tools are ready. No other installation needed.

pom.xml
xml
<project>

  <groupId>com.training</groupId>
  <artifactId>testing-demo</artifactId>
  <version>1.0.0</version>

  <properties>
    <java.version>17</java.version>
    <maven.compiler.source>17</maven.compiler.source>
    <maven.compiler.target>17</maven.compiler.target>
  </properties>

  <!-- ==============================
       DEPENDENCIES
  ================================= -->
  <dependencies>

    <!-- JUnit 5 — the test framework -->
    <dependency>
      <groupId>org.junit.jupiter</groupId>
      <artifactId>junit-jupiter</artifactId>
      <version>5.10.2</version>
      <scope>test</scope>
    </dependency>

    <!-- Mockito — for mocking dependencies -->
    <dependency>
      <groupId>org.mockito</groupId>
      <artifactId>mockito-junit-jupiter</artifactId>
      <version>5.11.0</version>
      <scope>test</scope>
    </dependency>

    <!-- Lombok — reduces boilerplate -->
    <dependency>
      <groupId>org.projectlombok</groupId>
      <artifactId>lombok</artifactId>
      <version>1.18.32</version>
      <scope>provided</scope>
    </dependency>

  </dependencies>

  <!-- ==============================
       PLUGINS
  ================================= -->
  <build>
    <plugins>

      <!-- Maven Surefire — runs JUnit tests -->
      <plugin>
        <groupId>org.apache.maven.plugins</groupId>
        <artifactId>maven-surefire-plugin</artifactId>
        <version>3.2.5</version>
      </plugin>

      <!-- JaCoCo — code coverage -->
      <plugin>
        <groupId>org.jacoco</groupId>
        <artifactId>jacoco-maven-plugin</artifactId>
        <version>0.8.12</version>
        <executions>
          <!-- Attaches JaCoCo agent before tests run -->
          <execution>
            <id>prepare-agent</id>
            <goals><goal>prepare-agent</goal></goals>
          </execution>
          <!-- Generates HTML report after tests -->
          <execution>
            <id>report</id>
            <phase>test</phase>
            <goals><goal>report</goal></goals>
          </execution>
          <!-- Fails build if coverage drops below 80% -->
          <execution>
            <id>check</id>
            <goals><goal>check</goal></goals>
            <configuration>
              <rules><rule>
                <element>BUNDLE</element>
                <limits><limit>
                  <counter>LINE</counter>
                  <value>COVEREDRATIO</value>
                  <minimum>0.80</minimum>
                </limit></limits>
              </rule></rules>
            </configuration>
          </execution>
        </executions>
      </plugin>

      <!-- SpotBugs — bytecode bug analysis -->
      <plugin>
        <groupId>com.github.spotbugs</groupId>
        <artifactId>spotbugs-maven-plugin</artifactId>
        <version>4.8.4.0</version>
        <configuration>
          <effort>Max</effort>
          <threshold>Medium</threshold>
          <failOnError>true</failOnError>
        </configuration>
        <executions>
          <execution>
            <goals><goal>check</goal></goals>
          </execution>
        </executions>
      </plugin>

    </plugins>
  </build>

</project>

JUnit 5 — Writing and Running Tests

JUnit 5 is the industry-standard Java testing framework. A test is simply a method annotated with @Test that calls your code and checks the result using assertions.

Core annotations reference

AnnotationWhat it doesExample use
@TestMarks the method as a test caseEvery individual test
@BeforeEachRuns before each test — set up objectsCreate fresh object before each test
@AfterEachRuns after each test — cleanupClose files, reset state
@BeforeAllRuns once before all tests (must be static)Start database connection
@AfterAllRuns once after all tests (must be static)Close database connection
@DisplayNameHuman-readable name shown in test reportMake reports readable
@DisabledSkips the test temporarilyKnown broken test to fix later
@ParameterizedTestRun same test with multiple inputsTest multiple values at once
@ValueSourceProvide simple values for parameterized testTest with int[], String[], double[]
@CsvSourceProvide input + expected pairsgrade(90)="A", grade(80)="B"
@MethodSourceProvide data from a static methodComplex test data objects
@NestedGroup related tests inside a classOrganise by scenario

Core assertions reference

AssertionWhat it checks
assertEquals(expected, actual)Values are equal
assertNotEquals(a, b)Values are not equal
assertTrue(condition)Condition is true
assertFalse(condition)Condition is false
assertNull(obj)Object is null
assertNotNull(obj)Object is not null
assertThrows(Exception.class, () -> ...)Code throws expected exception
assertAll(executable...)Run multiple assertions, all must pass

Example 1 — BankAccount (basic assertions)

BankAccount.java (production code)
java
public class BankAccount {
    private double balance;
    private final String owner;

    public BankAccount(String owner, double initialBalance) {
        if (initialBalance < 0)
            throw new IllegalArgumentException("Balance cannot be negative");
        this.owner = owner;
        this.balance = initialBalance;
    }

    public void deposit(double amount) {
        if (amount <= 0)
            throw new IllegalArgumentException("Deposit must be positive");
        balance += amount;
    }

    public void withdraw(double amount) {
        if (amount > balance)
            throw new InsufficientFundsException(
                "Need " + amount + " but only have " + balance);
        balance -= amount;
    }

    public double getBalance() { return balance; }
    public String  getOwner()   { return owner; }

    public boolean transfer(BankAccount target, double amount) {
        try {
            withdraw(amount);
            target.deposit(amount);
            return true;
        } catch (InsufficientFundsException e) {
            return false;
        }
    }
}
BankAccountTest.java (test code)
java
import org.junit.jupiter.api.*;
import static org.junit.jupiter.api.Assertions.*;

@DisplayName("BankAccount Tests")
class BankAccountTest {

    private BankAccount account;

    // Runs BEFORE each test method — fresh account every time
    @BeforeEach
    void setUp() {
        account = new BankAccount("Alice", 1000.0);
    }

    // ─── basic state tests ───────────────────────────
    @Test
    @DisplayName("Account has correct initial balance")
    void initialBalance() {
        assertEquals(1000.0, account.getBalance());
        assertEquals("Alice", account.getOwner());
    }

    // ─── deposit tests ───────────────────────────────
    @Test
    @DisplayName("Deposit increases balance correctly")
    void depositIncreasesBalance() {
        account.deposit(500.0);
        assertEquals(1500.0, account.getBalance());
    }

    @Test
    @DisplayName("Deposit of zero throws exception")
    void depositZeroThrows() {
        var ex = assertThrows(
            IllegalArgumentException.class,
            () -> account.deposit(0)
        );
        assertEquals("Deposit must be positive", ex.getMessage());
    }

    @Test
    @DisplayName("Deposit of negative amount throws exception")
    void depositNegativeThrows() {
        assertThrows(IllegalArgumentException.class,
            () -> account.deposit(-100));
    }

    // ─── withdraw tests ──────────────────────────────
    @Test
    @DisplayName("Withdraw reduces balance correctly")
    void withdrawReducesBalance() {
        account.withdraw(300.0);
        assertEquals(700.0, account.getBalance());
    }

    @Test
    @DisplayName("Withdraw more than balance throws InsufficientFundsException")
    void withdrawExceedingBalance() {
        assertThrows(InsufficientFundsException.class,
            () -> account.withdraw(2000.0));
    }

    @Test
    @DisplayName("Withdraw exact balance leaves zero")
    void withdrawExactBalance() {
        account.withdraw(1000.0);
        assertEquals(0.0, account.getBalance());
    }

    // ─── transfer tests ──────────────────────────────
    @Test
    @DisplayName("Successful transfer updates both accounts")
    void transferSuccess() {
        BankAccount target = new BankAccount("Bob", 500.0);
        boolean result = account.transfer(target, 200.0);

        // assertAll: runs ALL assertions even if first fails
        assertAll(
            () -> assertTrue(result),
            () -> assertEquals(800.0, account.getBalance()),
            () -> assertEquals(700.0, target.getBalance())
        );
    }

    @Test
    @DisplayName("Transfer with insufficient funds returns false")
    void transferInsufficientFunds() {
        BankAccount target = new BankAccount("Bob", 0);
        boolean result = account.transfer(target, 5000.0);

        assertAll(
            () -> assertFalse(result),
            () -> assertEquals(1000.0, account.getBalance()),  // unchanged
            () -> assertEquals(0.0, target.getBalance())          // unchanged
        );
    }
}

Example 2 — Parameterized Tests (test multiple inputs at once)

💡
Why parameterized?

Instead of writing 10 separate test methods for 10 different inputs, write one test and supply the data. Same coverage, 90% less code. Perfect for boundary conditions like grade boundaries, discount tiers, or tax brackets.

GradeCalculatorTest.java
java
import org.junit.jupiter.params.ParameterizedTest;
import org.junit.jupiter.params.provider.*;
import static org.junit.jupiter.api.Assertions.*;

class GradeCalculatorTest {

    private final GradeCalculator calc = new GradeCalculator();

    // ─── @ValueSource: same test, many single values ──
    @ParameterizedTest
    @ValueSource(doubles = {90, 95, 99, 100})
    @DisplayName("Scores 90-100 should return grade A")
    void scoreAbove90IsGradeA(double score) {
        assertEquals("A", calc.getGrade(score));
    }

    // ─── @CsvSource: input → expected pairs ──────────
    @ParameterizedTest
    @CsvSource({
        "100, A",
        "90,  A",
        "89,  B",
        "80,  B",
        "79,  C",
        "70,  C",
        "69,  D",
        "60,  D",
        "59,  F",
        "0,   F"
    })
    @DisplayName("Grade boundaries")
    void gradeBoundaries(double score, String expected) {
        assertEquals(expected, calc.getGrade(score));
    }

    // ─── @MethodSource: complex objects ─────────────
    static Stream<Arguments> discountScenarios() {
        return Stream.of(
            Arguments.of("GOLD",   1000, 200),   // 20% off
            Arguments.of("SILVER", 1000, 100),   // 10% off
            Arguments.of("BRONZE", 1000, 50),    // 5% off
            Arguments.of("NONE",   1000, 0)      // no discount
        );
    }

    @ParameterizedTest
    @MethodSource("discountScenarios")
    @DisplayName("Discount by membership tier")
    void discountByTier(String tier, double price, double expectedDiscount) {
        assertEquals(expectedDiscount, calc.getDiscount(tier, price));
    }
}

Mockito — Mocking Dependencies

Mockito creates fake (mock) objects that behave exactly as you specify. You control what they return, what they throw, and then verify they were called correctly.

🎯
The core idea

A unit test should test ONE class in isolation. When your class depends on a database, an API, or another service, those dependencies make the test slow, fragile, and hard to control. Mockito replaces each dependency with a fake that you fully control.

Core Mockito methods

MethodWhat it doesExample
mock(Class)Create a fake objectmock(UserRepository.class)
@MockAnnotation shortcut to create mockCleaner than manual mock()
@InjectMocksCreates class under test, injects all mocksAuto-wires all @Mock into your class
when().thenReturn()Define what mock returns on method callwhen(repo.findById(1)).thenReturn(user)
when().thenThrow()Define what exception mock throwswhen(api.call()).thenThrow(TimeoutException::new)
doNothing().when()Silence a void methoddoNothing().when(emailSvc).send(any())
verify(mock).method()Assert method was calledverify(repo).save(user)
verify(mock, times(n))Assert method called exactly n timesverify(repo, times(1)).save(any())
verify(mock, never())Assert method was NEVER calledverify(emailSvc, never()).send(any())
ArgumentCaptorCapture what argument was passed to mockCheck the exact object saved to DB
any(), anyString()Argument matchers — match any valueUsed in when() and verify()
eq(value)Match specific valueverify(repo).findById(eq(42L))

Example 1 — OrderService (mock payment + database + email)

OrderService.java (production code)
java
@Service
@RequiredArgsConstructor
public class OrderService {

    private final OrderRepository  orderRepo;
    private final PaymentGateway   payment;
    private final EmailService      email;
    private final InventoryService  inventory;

    public OrderResult placeOrder(Order order) {

        // 1. Check stock
        if (!inventory.isAvailable(order.getProductId(), order.getQty())) {
            return OrderResult.failed("Out of stock");
        }

        // 2. Charge payment
        PaymentResult payResult = payment.charge(
            order.getCustomerId(), order.getTotal());
        if (!payResult.isSuccess()) {
            return OrderResult.failed("Payment failed");
        }

        // 3. Save order
        order.setStatus("CONFIRMED");
        order.setTransactionId(payResult.getTransactionId());
        orderRepo.save(order);

        // 4. Send confirmation
        email.sendConfirmation(order);

        return OrderResult.success(payResult.getTransactionId());
    }
}
OrderServiceTest.java (test code)
java
import org.junit.jupiter.api.*;
import org.junit.jupiter.api.extension.ExtendWith;
import org.mockito.*;
import org.mockito.junit.jupiter.MockitoExtension;
import static org.junit.jupiter.api.Assertions.*;
import static org.mockito.Mockito.*;

@ExtendWith(MockitoExtension.class)   // enables @Mock and @InjectMocks
class OrderServiceTest {

    // These are ALL fake — no real database, no real payment, no real email
    @Mock OrderRepository  orderRepo;
    @Mock PaymentGateway   payment;
    @Mock EmailService      email;
    @Mock InventoryService  inventory;

    // OrderService created with ALL mocks auto-injected
    @InjectMocks OrderService orderService;

    // ─── Test 1: Happy path ───────────────────────────
    @Test
    @DisplayName("Successful order: stock OK + payment OK → saved + email sent")
    void successfulOrder() {
        // ARRANGE — tell mocks what to return
        Order order = new Order("CUST-1", "PROD-1", 2, 500.0);

        when(inventory.isAvailable("PROD-1", 2))
            .thenReturn(true);
        when(payment.charge("CUST-1", 500.0))
            .thenReturn(new PaymentResult(true, "TXN-123"));

        // ACT — call the method under test
        OrderResult result = orderService.placeOrder(order);

        // ASSERT — verify the result is correct
        assertTrue(result.isSuccess());
        assertEquals("TXN-123", result.getTransactionId());

        // VERIFY — confirm mocks were called correctly
        verify(orderRepo, times(1)).save(order);
        verify(email, times(1)).sendConfirmation(order);
    }

    // ─── Test 2: Out of stock ─────────────────────────
    @Test
    @DisplayName("Out of stock: payment NOT charged, order NOT saved")
    void outOfStock() {
        Order order = new Order("CUST-1", "PROD-1", 999, 5000.0);

        when(inventory.isAvailable("PROD-1", 999))
            .thenReturn(false);   // out of stock

        OrderResult result = orderService.placeOrder(order);

        assertFalse(result.isSuccess());
        assertEquals("Out of stock", result.getMessage());

        // Payment and save should NEVER be called when out of stock
        verify(payment, never()).charge(anyString(), anyDouble());
        verify(orderRepo, never()).save(any());
        verify(email, never()).sendConfirmation(any());
    }

    // ─── Test 3: Payment fails ────────────────────────
    @Test
    @DisplayName("Payment declined: order NOT saved, email NOT sent")
    void paymentDeclined() {
        Order order = new Order("CUST-2", "PROD-2", 1, 200.0);

        when(inventory.isAvailable(anyString(), anyInt()))
            .thenReturn(true);
        when(payment.charge(anyString(), anyDouble()))
            .thenReturn(new PaymentResult(false, null));  // declined

        OrderResult result = orderService.placeOrder(order);

        assertFalse(result.isSuccess());
        verify(orderRepo, never()).save(any());
        verify(email, never()).sendConfirmation(any());
    }

    // ─── Test 4: ArgumentCaptor ───────────────────────
    @Test
    @DisplayName("Saved order should have CONFIRMED status and transaction ID")
    void savedOrderHasCorrectState() {
        Order order = new Order("CUST-3", "PROD-3", 1, 300.0);

        when(inventory.isAvailable(anyString(), anyInt())).thenReturn(true);
        when(payment.charge(anyString(), anyDouble()))
            .thenReturn(new PaymentResult(true, "TXN-999"));

        orderService.placeOrder(order);

        // Capture the exact Order object passed to repo.save()
        ArgumentCaptor<Order> captor = ArgumentCaptor.forClass(Order.class);
        verify(orderRepo).save(captor.capture());

        Order savedOrder = captor.getValue();
        assertEquals("CONFIRMED", savedOrder.getStatus());
        assertEquals("TXN-999",   savedOrder.getTransactionId());
    }
}

Example 2 — Testing Error Handling (thenThrow)

UserServiceTest.java
java
@ExtendWith(MockitoExtension.class)
class UserServiceTest {

    @Mock UserRepository     userRepo;
    @Mock EmailService        emailSvc;
    @Mock AuditLogger         auditLog;

    @InjectMocks UserService userService;

    // ─── Test: Database timeout ───────────────────────
    @Test
    @DisplayName("Database timeout is handled gracefully")
    void databaseTimeout() {
        when(userRepo.findByEmail("test@mail.com"))
            .thenThrow(new DatabaseException("Connection timed out"));

        ServiceResponse<User> response =
            userService.getUser("test@mail.com");

        assertFalse(response.isSuccess());
        assertEquals("Service temporarily unavailable",
                     response.getMessage());
        // Verify error was logged
        verify(auditLog, times(1)).logError(anyString(), any());
    }

    // ─── Test: Duplicate email on register ───────────
    @Test
    @DisplayName("Registering duplicate email returns error, no email sent")
    void duplicateEmailRegistration() {
        when(userRepo.existsByEmail("dup@mail.com"))
            .thenReturn(true);

        ServiceResponse<User> response =
            userService.register(new User("dup@mail.com", "pwd"));

        assertFalse(response.isSuccess());
        assertEquals("Email already registered", response.getMessage());
        verify(emailSvc, never()).sendWelcome(anyString());
        verify(userRepo, never()).save(any());
    }

    // ─── Test: Void method (doNothing) ───────────────
    @Test
    @DisplayName("Password reset sends exactly one email")
    void passwordReset() {
        var user = new User("user@mail.com", "oldPwd");
        when(userRepo.findByEmail("user@mail.com"))
            .thenReturn(user);

        // emailSvc.sendReset() is void — doNothing() is default but shown for clarity
        doNothing().when(emailSvc).sendReset(anyString(), anyString());

        userService.resetPassword("user@mail.com");

        // Verify the reset email was sent exactly once
        verify(emailSvc, times(1)).sendReset(
            eq("user@mail.com"), anyString()  // any token
        );
    }
}

Example 3 — @Spy (partial mocking — real code + override specific method)

🔬
Mock vs Spy

Mock — completely fake object. All methods return null/0/false by default unless you configure them with when().
Spy — wraps a REAL object. Real methods execute unless you specifically override them. Use spy when you want to test a real class but mock only some of its methods.

PricingServiceTest.java
java
@ExtendWith(MockitoExtension.class)
class PricingServiceTest {

    // @Spy wraps the REAL PricingService instance
    @Spy
    PricingService pricingService = new PricingService();

    @Test
    @DisplayName("Real calculateBase runs, but applyTax is overridden")
    void spyTest() {
        // Override ONLY the tax calculation (e.g. tax API is down)
        doReturn(100.0).when(pricingService).applyTax(anyDouble());

        // calculateFinalPrice calls: calculateBase() (REAL) + applyTax() (MOCKED)
        double finalPrice = pricingService.calculateFinalPrice("PROD-1");

        // Real base calculation ran + our overridden tax = verifiable result
        assertEquals(600.0, finalPrice);  // 500 base + 100 tax

        // Verify real method was called

JaCoCo — Code Coverage Reports

JaCoCo instruments your code while tests run and generates a colour-coded HTML report showing which lines were exercised and which were completely missed.

How JaCoCo works

Prepare Agent: JaCoCo attaches a Java agent that instruments every .class file before test execution begins.

Tests Run: Your JUnit tests execute. The agent records every line, branch, and method that is touched.

Report Generated: After tests finish, JaCoCo writes the collected data to target/jacoco.exec and generates an HTML report at target/site/jacoco/index.html.

Coverage Check: If you have a minimum coverage rule (e.g., 80%), the build fails automatically if coverage falls below it.

Coverage types explained

TypeWhat it measuresExample
Line coveragePercentage of code lines executed at least once85 of 100 lines executed = 85%
Branch coveragePercentage of if/else/switch branches takenif/else: test both branches = 100%, only if = 50%
Method coveragePercentage of methods called at least once10 of 12 methods called = 83%
Class coveragePercentage of classes with any method testedAll 8 classes touched = 100%

Reading the HTML report

What the colours mean in target/site/jacoco/index.html
GREEN  background  = Line was fully executed during tests — tested
RED    background  = Line was NEVER executed — completely untested
YELLOW background  = Branch partially covered
                     e.g. the "if" ran but "else" never ran

        }
    }

SpotBugs — Finding Real Bugs at Build Time

SpotBugs analyses your compiled .class files (bytecode) for real bugs — null pointers, wrong comparisons, resource leaks, security holes — and reports them before your tests even run.

Why bytecode analysis beats source analysis

PMD and Checkstyle read source code text. SpotBugs reads bytecode, which means it understands how Java actually executes at runtime. Some bugs are invisible at the source level but obvious in bytecode — like Integer comparison using == that looks correct but fails for values above 127 due to Java's Integer cache.

Bug categories SpotBugs catches

CategoryExamplesSeverity
CorrectnessNull dereference, == on objects, infinite loop, wrong String comparisonHigh
SecuritySQL injection, hardcoded passwords, exposed sensitive dataCritical
Bad practiceEmpty catch blocks, finalizer ignores exception, clone does not call superMedium
PerformanceBoxing primitive for comparison, string concatenation in loopLow
MT SafetyUnsynchronised access to shared field, lock ordering issuesHigh

BuggyOrderService.java — SpotBugs finds all of these
java
public class BuggyOrderService {

    // ─── BUG 1: Null dereference ──────────────────────
    // SpotBugs: NP_NULL_ON_SOME_PATH
    public String getCustomerName(Long orderId) {
        Order order = orderRepo.findById(orderId);
        return order.getCustomer().getName();
        // findById can return null — crash guaranteed when order not found
    }

    // ─── BUG 2: Integer comparison with == ────────────
    // SpotBugs: RC_REF_COMPARISON_BAD_PRACTICE
    public boolean isSameQuantity(Integer a, Integer b) {
        return a == b;
        // Works for -128 to 127 (cache range), FAILS for 128+
        // Example: isSameQuantity(200, 200) returns FALSE!
    }

    // ─── BUG 3: Resource leak ─────────────────────────
    // SpotBugs: OBL_UNSATISFIED_OBLIGATION
    public String readFile(String path) throws IOException {
        FileReader reader = new FileReader(path);
        return new BufferedReader(reader).readLine();
        // reader is never closed — file handle leak!
        // On Windows this prevents the file from being deleted/moved
    }

    // ─── BUG 4: SQL injection ─────────────────────────
    // SpotBugs: SQL_NONCONSTANT_STRING_PASSED_TO_EXECUTE
    public List<Order> searchOrders(String customerName) {
        String sql = "SELECT * FROM orders WHERE customer = '"
                   + customerName + "'";
        return jdbcTemplate.query(sql);
        // customerName = "'; DROP TABLE orders; --" ← SQL injection!
    }
}

Example 2 — Fixed versions of every bug above

FixedOrderService.java
java
public class FixedOrderService {

    // ─── FIX 1: Null dereference → Optional chain ─────
    public String getCustomerName(Long orderId) {
        return Optional.ofNullable(orderRepo.findById(orderId))
            .map(Order::getCustomer)
            .map(Customer::getName)
            .orElse("Unknown");
    }

    // ─── FIX 2: Use Objects.equals() ─────────────────
    public boolean isSameQuantity(Integer a, Integer b) {
        return Objects.equals(a, b);
        // Works correctly for ALL values, null-safe
    }

    // ─── FIX 3: try-with-resources (auto-closes) ──────
    public String readFile(String path) throws IOException {
        try (var reader = new BufferedReader(new FileReader(path))) {
            return reader.readLine();
        }
        // Reader closed automatically — even if exception thrown
    }

    // ─── FIX 4: Parameterized query ───────────────────
    public List<Order> searchOrders(String customerName) {
        String sql = "SELECT * FROM orders WHERE customer = ?";
        return jdbcTemplate.query(sql, customerName);
        // ? is a bind parameter — injection impossible
    }
}

public class Report {

    private List<String> items;

    // Return copy — caller cannot change internal state
    public Date getCreatedAt() {
        return new Date(createdAt.getTime());
    }
    public List<String> getItems() {
        return Collections.unmodifiableList(items);
    }
    // Better yet: use LocalDate (immutable) instead of Date
}

The production class

LoanEligibilityService.java
java
@Service
@RequiredArgsConstructor
public class LoanEligibilityService {

    private final CustomerRepository  customerRepo;
    private final CreditScoreService   creditService;
    private final LoanPolicyService     policyService;
    private final AuditLogger           auditLogger;

    public EligibilityResult checkEligibility(String customerId,
                                               double loanAmount) {
        // 1. Load customer (SpotBugs-safe: Optional.ofNullable)
        Customer customer = Optional
            .ofNullable(customerRepo.findById(customerId))
            .orElseThrow(() -> new CustomerNotFoundException(customerId));

        // 2. Get credit score
        int creditScore = creditService.getScore(customerId);

        // 3. Check policy limits
        double maxLoan = policyService.getMaxLoanAmount(creditScore);

        // 4. Apply eligibility rules
        if (creditScore < 600) {
            auditLogger.log(customerId, "REJECTED: Low credit score");
            return EligibilityResult.rejected("Credit score below minimum");
        }

        if (loanAmount > maxLoan) {
            auditLogger.log(customerId, "REJECTED: Exceeds max loan");
            return EligibilityResult.rejected(
                "Loan amount exceeds maximum of " + maxLoan);
        }

        if (loanAmount > customer.getAnnualIncome() * 10) {
            auditLogger.log(customerId, "REJECTED: Income ratio exceeded");
            return EligibilityResult.rejected("Loan exceeds 10x annual income");
        }

        auditLogger.log(customerId, "APPROVED: loan=" + loanAmount);
        return EligibilityResult.approved(loanAmount, creditScore);
    }
}

        assertFalse(result.isApproved());

        verify(policyService, never()).getMaxLoanAmount(anyInt());

        assertFalse(result.isApproved());
