What is OOP and Why Does It Exist?

The philosophy behind the code — and why it matters in real projects

Before OOP, all software was written as a long sequence of commands — procedural code. It worked for small programs. When IBM built banking software in the 1970s, they had a single file with thousands of lines and no organisation. Changing one interest calculation formula broke five other things. Teams couldn't work in parallel. Bugs were nearly impossible to trace.

OOP solves this by modelling software the way the real world works. Your banking system has accounts, customers, and transactions. Your telecom system has customers, plans, and recharges. OOP lets you build these as self-contained, reusable units of code called objects.

🔒 Encapsulation

Hide account balance from direct modification. Only allow changes through deposit() and withdraw(). Like a bank vault with controlled access.

🧬 Inheritance

SavingsAccount and CurrentAccount both extend BankAccount. They share common logic (owner, balance) without rewriting it.

🎭 Polymorphism

One processPayment() method works for UPI, credit card, and net banking. The caller doesn't care which — it just calls the method.

🎨 Abstraction

A teller uses a screen to transfer money. They don't know the SQL queries behind it. You define what can be done, not how.

❌ Without OOP — Procedural style

  • Account balance stored as a loose variable
  • Any code can set balance = -99999
  • Duplicate logic across functions
  • Adding a new account type means modifying existing functions
  • Impossible to have SBI and ICICI accounts with different rules

✅ With OOP — Java style

  • Balance is private inside BankAccount
  • Only deposit() and withdraw() can change it
  • Shared logic lives in the parent class once
  • New account types just extend the parent
  • Each bank can have its own rules in its own class

Data Types

Primitive vs Reference — what every variable holds

Every variable in Java has a type that tells the JVM how much memory to allocate and what operations are valid. Java has two categories:

⚡

Primitive Types

Store actual values directly in memory. Fixed size. 8 types total.

📦

Reference Types

Store a reference (address) to an object in heap memory. Classes, arrays, interfaces.

⚠️
What goes wrong with wrong types?
  • Using int for balance → Rs 2,147,483,647 max. Large corporate accounts overflow silently.
  • Using float for money → floating-point errors: Rs 10.1 + Rs 0.2 = Rs 10.299999 (use BigDecimal for real financial apps)
  • Calling a method on a null reference → NullPointerException at runtime

Variables — 3 Types Explained

Instance, Local, and Static — when each lives and why it matters

Not all variables work the same way. Where you declare a variable determines its scope (where it can be used), its lifetime (how long it exists), and what it belongs to.

🏠

Instance Variable

Belongs to an object. Each object has its own copy. Lives as long as the object lives.

⚡

Local Variable

Declared inside a method. Only exists while that method is running. Must be initialised before use.

🌐

Static Variable

Belongs to the class, not any object. Shared by all objects. Exists from class load to program end.

🏦 Banking Domain
BankAccount.java — All 3 variable types 
public class BankAccount {

    // ══ STATIC variable — shared by ALL accounts ══
    // Counts total accounts opened across the whole bank
    private static int totalAccountsOpened = 0;
    public  static final double INTEREST_RATE = 3.5;  // constant

    // ══ INSTANCE variables — each account has its OWN copy ══
    private int    accountNumber;
    private String accountHolder;
    private double balance;
    private booleanisActive;

    public BankAccount(int accNo, String holder, double openingBalance) {
        this.accountNumber = accNo;
        this.accountHolder = holder;
        this.balance        = openingBalance;
        this.isActive       = true;
        totalAccountsOpened++;         // every new account increments the counter
    }

    public void deposit(double amount) {
        // ══ LOCAL variable — exists only inside this method ══
        double previousBalance = this.balance;  // local — for the receipt
        this.balance += amount;
        System.out.println("Deposited ₹" + amount +
            ". Balance: ₹" + this.balance);
        // previousBalance vanishes after method ends — we don't need it anymore
    }

    // static method — called on the class, not an object
    public static int getTotalAccounts() {
        return totalAccountsOpened;
    }
}

Classic Mistakes
  • Using a static variable for balance → all accounts share the same balance. Depositing into one changes all of them!
  • Trying to use a local variable outside its method → compile error: "variable not found"
  • Forgetting to initialise a local variable before reading it → compile error (unlike instance vars which have defaults)

Classes & Objects

Blueprint vs the real thing — the core of OOP

📘
Class = Blueprint. Object = Instance of that blueprint.

A Customer class defines what a customer is — name, phone, email. An object customer1 is one actual customer with specific values. You can create millions of customer objects from one class definition.

Real-World Analogy — HDFC Bank When HDFC Bank opens a new branch, they don't invent a new "customer" from scratch. They have a standardised KYC form — that's the class. Each filled-in form (Rahul's form, Priya's form) is an object. Same structure, different data.
📱 Telecom Domain — Airtel
Customer.java + Main.java 
// ══════ CLASS — the blueprint ══════
public class Customer {

    // Fields (instance variables)
    private int    customerId;
    private String name;
    private String mobileNumber;
    private String activePlan;
    private double walletBalance;

    // Constructor
    public Customer(int id, String name, String mobile) {
        this.customerId    = id;
        this.name          = name;
        this.mobileNumber  = mobile;
        this.walletBalance  = 0.0;
        this.activePlan     = "No Plan";
    }

    // Methods (behaviours)
    public void recharge(double amount, String plan) {
        this.walletBalance += amount;
        this.activePlan     = plan;
        System.out.println(name + " recharged ₹" + amount +
            ". Plan activated: " + plan);
    }

    public void displayProfile() {
        System.out.println("--- Customer Profile ---");
        System.out.println("ID     : " + customerId);
        System.out.println("Name   : " + name);
        System.out.println("Mobile : " + mobileNumber);
        System.out.println("Plan   : " + activePlan);
        System.out.println("Wallet : ₹" + walletBalance);
    }
}

// ══════ Creating OBJECTS in Main ══════
public class Main {
    public static void main(String[] args) {

        // new keyword creates an object on the HEAP
        Customer c1 = new Customer(1001, "Rahul Sharma", "9876543210");
        Customer c2 = new Customer(1002, "Priya Nair",   "9123456789");

        c1.recharge(299, "Airtel 299 - 2GB/day, Unlimited calls");
        c2.recharge(149, "Airtel 149 - 1GB/day");

        c1.displayProfile();
        c2.displayProfile();

        // c1 and c2 are completely independent — changing one doesn't affect the other
    }
}

Syntax Rules for Classes
  • Class name must match the filename: class Customer → file Customer.java
  • Only one public class per file
  • Class name starts with Capital letter (PascalCase)
  • Fields should be private, methods usually public
  • new ClassName(args) creates the object and calls the constructor

public class Employee {

    private String name;
    private String department;

        this.employeeId  = id;
        this.name        = name;
        this.department  = dept;

Constructors

Initialising objects at birth — the setup phase

📘
What is a Constructor?

A constructor is a special method that runs automatically when you create an object using new. It sets up the object's initial state. It has the same name as the class and no return type.

⚠️
What if you don't use a proper constructor?

Fields get default values (0, null, false). A bank account with null accountHolder and Rs 0 balance, with no validation — you'd allow creating invalid accounts that crash later when you call methods on null fields.

Three kinds of constructors

🛒 E-Commerce Domain — Flipkart
Product.java — Constructor overloading 
public class Product {
    private int    productId;
    private String name;
    private double price;
    private int    stock;
    private String category;

    // ── 1. Default constructor — Java provides one if you write none
    //       But here we override it to set sensible defaults:
    public Product() {
        this.productId = 0;
        this.name     = "Unnamed";
        this.price    = 0.0;
        this.stock    = 0;
        this.category = "Uncategorised";
    }

    // ── 2. Parameterised constructor — set everything at creation
    public Product(int id, String name, double price, int stock) {
        this.productId = id;
        this.name      = name;
        this.price     = (price > 0) ? price : 0;   // validation at birth
        this.stock     = (stock >= 0) ? stock : 0;
        this.category  = "General";
    }

    // ── 3. Full parameterised constructor
    public Product(int id, String name, double price,
                   int stock, String category) {
        this(id, name, price, stock);      // calls constructor above (code reuse)
        this.category = category;
    }

    public void displayProduct() {
        System.out.println("[" + productId + "] " + name +
            " | ₹" + price + " | Stock: " + stock +
            " | Category: " + category);
    }
}

// Usage — Java picks the right constructor by matching parameters:
Product p1 = new Product();
Product p2 = new Product(301, "Samsung Galaxy S24", 79999, 50);
Product p3 = new Product(302, "Nike Air Max", 8999, 200, "Footwear");

p1.displayProduct();  // [0] Unnamed | ₹0.0 | Stock: 0 | Category: Uncategorised
p2.displayProduct();  // [301] Samsung Galaxy S24 | ₹79999.0 | Stock: 50 | Category: General
p3.displayProduct();  // [302] Nike Air Max | ₹8999.0 | Stock: 200 | Category: Footwear

Methods — void, Return Types, Overloading & Overriding

Defining what objects can do — and how methods communicate results

📘
What is a Method?

A method is a named block of code inside a class that defines what an object can do. Methods can receive data (parameters), perform logic, and optionally return a result.

🔇

void method

Does something but returns nothing. Like printReceipt() — it just prints, doesn't give you back a value.

📤

Return-type method

Computes and gives back a value to the caller. Like calculateInterest() — returns a double the caller can use.

🏦 Banking Domain — SBI
SBIAccount.java — Methods in depth 
public class SBIAccount {
    private double balance;
    private String accountHolder;

    public SBIAccount(String holder, double balance) {
        this.accountHolder = holder;
        this.balance       = balance;
    }

    // ── void method: performs action, returns nothing
    public void printStatement() {
        System.out.println("Account: " + accountHolder +
            " | Balance: ₹" + balance);
    }

    // ── return double: caller needs the computed value
    public double calculateYearlyInterest() {
        return balance * 0.035;   // SBI savings: 3.5% p.a.
    }

    // ── return boolean: validation check
    public boolean withdraw(double amount) {
        if (amount > 0 && amount <= balance) {
            balance -= amount;
            return true;   // success
        }
        return false;      // failed
    }

    // ── return String: formatted data for display
    public String getMiniStatement() {
        return "Holder: " + accountHolder +
               " | Balance: ₹" + balance +
               " | Interest/year: ₹" + calculateYearlyInterest();
    }

    // ══ METHOD OVERLOADING — same name, different parameters ══
    // transfer to another account by ID
    public boolean transfer(int toAccountId, double amount) {
        System.out.println("Transferred ₹"+amount+" to account #"+toAccountId);
        return withdraw(amount);
    }

    // transfer to another account OBJECT
    public boolean transfer(SBIAccount toAccount, double amount) {
        if (withdraw(amount)) {
            toAccount.balance += amount;
            System.out.println("₹"+amount+" transferred to "+toAccount.accountHolder);
            return true;
        }
        System.out.println("Transfer failed: insufficient balance");
        return false;
    }
}

// Usage:
SBIAccount myAcc   = new SBIAccount("Ravi Kumar", 50000);
SBIAccount friendAcc = new SBIAccount("Sita Devi", 10000);

double interest = myAcc.calculateYearlyInterest();  // 1750.0
boolean ok = myAcc.transfer(friendAcc, 5000);         // overloaded: object version
System.out.println(myAcc.getMiniStatement());

The this and super Keywords

Referring to the current object and the parent class

👆

this

Refers to the current object. Used to disambiguate field names from parameters, call another constructor, or pass self as argument.

⬆️

super

Refers to the parent class. Used to call the parent's constructor (super()) or a parent method that's been overridden.

🏦 Banking Domain — ICICI Bank
this and super in Banking 
// ── this: resolves name clash between field and parameter ──
public class ICICIAccount {
    private String accountHolder;
    private double balance;
    private String ifscCode;

    // parameter 'accountHolder' shadows the field 'accountHolder'
    // 'this.accountHolder' means the FIELD; 'accountHolder' means the PARAMETER
    public ICICIAccount(String accountHolder, double balance) {
        this.accountHolder = accountHolder;
        this.balance       = balance;
        this.ifscCode      = "ICIC0001104";
    }

    // this() — calls another constructor to avoid repeating code
    public ICICIAccount(String accountHolder) {
        this(accountHolder, 0.0);   // reuses the 2-param constructor above
    }
}

// ── super: child uses parent's constructor and methods ──
public class BankAccount {
    protected String accountHolder;
    protected double balance;

    public BankAccount(String holder, double balance) {
        this.accountHolder = holder;
        this.balance = balance;
    }

    public void displayInfo() {
        System.out.println("Holder: " + accountHolder + " | Balance: ₹" + balance);
    }
}

public class SavingsAccount extends BankAccount {
    private double interestRate;
    private int    minimumBalance;

    public SavingsAccount(String holder, double balance) {
        super(holder, balance);  // MUST be first line — calls BankAccount constructor
        this.interestRate   = 3.5;
        this.minimumBalance = 1000;
    }

    @Override
    public void displayInfo() {
        super.displayInfo();             // prints holder & balance from parent
        System.out.println(              // then adds savings-specific info
            "Interest Rate: " + interestRate +
            "% | Min Balance: ₹" + minimumBalance);
    }
}

SavingsAccount sa = new SavingsAccount("Meera Kapoor", 25000);
sa.displayInfo();
// Holder: Meera Kapoor | Balance: ₹25000.0
// Interest Rate: 3.5% | Min Balance: ₹1000

Access Specifiers

Controlling who can see and modify what

📘
What are Access Specifiers?

Keywords that control which other classes can access your fields and methods. This is the primary tool for enforcing encapsulation and data security in real systems.

🏦 Banking Domain
Access specifiers — real usage 
public class BankAccount {

    // private — ONLY this class can access. Not even subclasses.
    // No one can directly set balance = -1000 from outside.
    private double  balance;
    private String  pin;

    // protected — this class AND subclasses can access.
    // SavingsAccount (child) can use accountHolder directly.
    protected String accountHolder;
    protected int    accountNumber;

    // public — anyone can call these
    public BankAccount(String holder, int accNo, double initial) {
        this.accountHolder = holder;
        this.accountNumber  = accNo;
        this.balance        = initial;
        this.pin            = "0000";  // default PIN
    }

    // Public method — the ONLY way to change balance from outside
    public boolean deposit(double amount) {
        if (amount <= 0) return false;
        balance += amount;
        return true;
    }

    // Public getter — read-only access to balance
    public double getBalance() { return balance; }

    // Private helper — called internally only; not exposed outside
    private void logTransaction(String type, double amount) {
        System.out.println("[LOG] " + type + ": ₹" + amount);
    }
}

// In another class:

acc.deposit(1000);                  // ✅ public — allowed
System.out.println(acc.getBalance()); // ✅ public getter — allowed
// acc.balance = -99999;    ← ❌ COMPILE ERROR: balance is private
// acc.logTransaction(...); ← ❌ COMPILE ERROR: logTransaction is private

Encapsulation

The bank vault principle — protect data, expose controlled access

📘
What is Encapsulation?

Bundling data (fields) and methods that operate on that data into a class, while hiding the internal state behind a controlled interface (getters/setters). The data can only change through the methods you allow — with validation and logic built in.

🎓 Education Domain — University
Student.java — Full encapsulation 
public class Student {
    private int    studentId;
    private String name;
    private double cgpa;            // 0.0 to 10.0
    private int    attendancePercent; // 0 to 100
    private String course;

    public Student(int id, String name, String course) {
        this.studentId  = id;
        this.name       = name;
        this.course     = course;
        this.cgpa       = 0.0;
        this.attendancePercent = 0;
    }

    // ── Getters (read access) ──
    public int    getStudentId()   { return studentId; }
    public String getName()         { return name; }
    public double getCgpa()         { return cgpa; }
    public int    getAttendance()   { return attendancePercent; }

    // ── Setters (write access with VALIDATION) ──
    public void setCgpa(double cgpa) {
        if (cgpa >= 0.0 && cgpa <= 10.0) {
            this.cgpa = cgpa;
        } else {
            System.out.println("Invalid CGPA. Must be 0.0 to 10.0");
        }
    }

    public void setAttendance(int percent) {
        if (percent >= 0 && percent <= 100) {
            this.attendancePercent = percent;
        } else {
            System.out.println("Attendance must be 0-100");
        }
    }

    // Business logic method
    public boolean isEligibleForExam() {
        return attendancePercent >= 75;
    }

    public String getGrade() {
        if      (cgpa >= 9.0) return "O (Outstanding)";
        else if (cgpa >= 8.0) return "A+ (Excellent)";
        else if (cgpa >= 7.0) return "A  (Very Good)";
        else if (cgpa >= 6.0) return "B  (Good)";
        else                   return "F  (Fail)";
    }
}

// Usage:
Student s = new Student(2024001, "Divya Menon", "B.Tech CSE");
s.setCgpa(8.7);
s.setCgpa(15);    // → "Invalid CGPA. Must be 0.0 to 10.0" (protected!)
s.setAttendance(82);
System.out.println(s.getGrade());           // A+ (Excellent)
System.out.println(s.isEligibleForExam()); // true
Intermediate Exercise 2 — BankAccount with full encapsulation

Build an ICICIBankAccount class with private fields: accountNumber (int), holderName (String), balance (double), isActive (boolean). Write a constructor. Add deposit(double) that rejects negative amounts. Add withdraw(double) that rejects if amount exceeds balance or is negative, and prints appropriate messages. Add a getBalance() getter and a printStatement() method. Test with a few transactions.

Solution — ICICIBankAccount.java 
public class ICICIBankAccount {
    private int     accountNumber;
    private String  holderName;
    private double  balance;
    private boolean isActive;

    public ICICIBankAccount(int accNo, String name, double initialDeposit) {
        this.accountNumber = accNo;
        this.holderName    = name;
        this.balance       = initialDeposit;
        this.isActive      = true;
    }

    public void deposit(double amount) {
        if (amount <= 0) {
            System.out.println("❌ Invalid deposit amount.");
            return;
        }
        balance += amount;
        System.out.println("✅ Deposited ₹" + amount +
            ". New balance: ₹" + balance);
    }

    public void withdraw(double amount) {
        if (amount <= 0) {
            System.out.println("❌ Invalid withdrawal amount.");
        } else if (amount > balance) {
            System.out.println("❌ Insufficient balance. Available: ₹" + balance);
        } else {
            balance -= amount;
            System.out.println("✅ Withdrawn ₹" + amount +
                ". Remaining: ₹" + balance);
        }
    }

    public double getBalance() { return balance; }

    public void printStatement() {
        System.out.println("\n=== ICICI Bank Statement ===");
        System.out.println("Account: " + accountNumber);
        System.out.println("Holder : " + holderName);
        System.out.println("Balance: ₹" + balance);
        System.out.println("Status : " + (isActive ? "Active" : "Inactive"));
    }
}

Inheritance

Code reuse through parent-child class hierarchy

📘
What is Inheritance?

A child class (subclass) automatically gets all non-private fields and methods of a parent class (superclass). It can add new features and override existing ones. Uses the extends keyword.

💡
Why Inheritance? — Banking Example

SBI offers Savings Accounts, Current Accounts, Salary Accounts, and NRI Accounts. All of them share: account number, holder name, balance, deposit(), withdraw(). Without inheritance, you repeat all that code 4 times. With inheritance, write it once in BankAccount, and each subclass just adds what's unique to it.

🏦 Banking Domain — Account Hierarchy
BankAccount.java + SavingsAccount.java + CurrentAccount.java 
// ══ PARENT CLASS — common to ALL account types ══
public class BankAccount {
    protected int    accountNumber;
    protected String accountHolder;
    protected double balance;

    public BankAccount(int accNo, String holder, double balance) {
        this.accountNumber = accNo;
        this.accountHolder = holder;
        this.balance       = balance;
    }

    public void deposit(double amount) {
        if (amount > 0) balance += amount;
    }

    public String getAccountInfo() {

        this.overdraftLimit = overdraft;

    @Override
    public void deposit(double amount) {

        System.out.println("[Current A/C] Cheque clearing initiated for ₹"+amount);

        return false;

               " | Overdraft: ₹" + overdraftLimit;
    }

Polymorphism

One interface, many implementations — the power of runtime dispatch

📘
What is Polymorphism?

"Many forms." The same method call produces different behaviour depending on the actual object type. Java decides which version to call at runtime — this is called dynamic dispatch.

💡
Why it matters in real projects

An E-commerce payment system must handle UPI, Credit Card, Net Banking, and Wallets. Without polymorphism, you'd write separate if-else blocks for every payment type. With polymorphism, call processPayment() on any payment object and the right implementation runs automatically. Adding a new payment method (say, BNPL) doesn't change existing code — just add a new class.

🛒 E-Commerce — Payment Gateway
Polymorphism — Payment Gateway 
// Parent class
public class Payment {

    protected String orderId;

    public Payment(double amount, String orderId) {
        this.amount  = amount;

    public void processPayment() {

Abstract Classes

Defining the skeleton — enforcing what must be implemented

📘
What is an Abstract Class?

A class declared abstract. It may have both complete methods (shared code) and abstract methods (no body — subclasses MUST implement them). You cannot instantiate it directly.

Real-World Analogy — Telecom Plan Airtel says: every telecom plan MUST have a getDataLimit() and a getValidity(). But each plan calculates these differently. So TelecomPlan is abstract — it mandates that subclasses provide these, but each plan implements them in its own way.
📱 Telecom Domain — Airtel / Jio
TelecomPlan.java (abstract) + concrete plans 
// Abstract class — cannot do: new TelecomPlan()
public abstract class TelecomPlan {
    protected String planName;
    protected double price;

    public TelecomPlan(String planName, double price) {
        this.planName = planName;
        this.price    = price;
    }

    // ABSTRACT — subclasses MUST implement these
    public abstract int    getDataLimitGB();
    public abstract int    getValidityDays();
    public abstract boolean hasUnlimitedCalls();

    // CONCRETE — shared by ALL plans
    public void displayPlan() {
        System.out.println(
            "Plan: " + planName +
            " | ₹" + price +
            " | Data: " + getDataLimitGB() + "GB" +
            " | Validity: " + getValidityDays() + "d" +
            " | Calls: " + (hasUnlimitedCalls() ? "Unlimited" : "Limited"));
    }

    // Template method — uses abstract methods internally
    public double getPricePerDay() {
        return price / getValidityDays();
    }
}

public class AirtelPrepaid299 extends TelecomPlan {
    public AirtelPrepaid299() { super("Airtel 299", 299); }

}

Interfaces

Pure contracts — define what must be done, not how

📘
What is an Interface?

An interface is a 100% abstract contract. It declares method signatures that any implementing class must provide. A class can implement multiple interfaces (unlike inheritance where you can only extend one class).

📅
Abstract Class vs Interface — which to use?
  • Use abstract class when subclasses share common code/fields AND an "is-a" relationship exists (SavingsAccount IS-A BankAccount)
  • Use interface when you define a capability/behaviour that many unrelated classes might support (a Transaction, an Order, and a Refund can all be Auditable)
  • Use interfaces when a class needs to play multiple roles — Java doesn't allow multiple inheritance, but allows multiple interface implementation
🛒 E-Commerce / Banking Domain
Interfaces — Auditable, Refundable, Notifiable 
// Interface 1: anything that can be audited
public interface Auditable {
    String getAuditLog();      // automatically public abstract
    boolean isAuditComplete();
}

// Interface 2: anything that supports refund
public interface Refundable {
    boolean initiateRefund(double amount);
    String  getRefundStatus();
}

// Interface 3: anything that can send notifications
public interface Notifiable {
    void sendSMS(String message);
    void sendEmail(String subject, String body);
}

// An Order implements ALL THREE — it can be audited, refunded, and sends notifications
public class FlipkartOrder implements Auditable, Refundable, Notifiable {
    private String orderId;
    private double orderAmount;
    private String customerMobile;
    private String refundStatus;

    public FlipkartOrder(String id, double amount, String mobile) {
        this.orderId        = id;
        this.orderAmount    = amount;
        this.customerMobile = mobile;
        this.refundStatus   = "NONE";
    }

    // Auditable implementation
    @Override
    public String getAuditLog() {
        return "[AUDIT] Order "+orderId+" | ₹"+orderAmount+" | Status: PLACED";
    }
    @Override
    public boolean isAuditComplete() { return true; }

    // Refundable implementation
    @Override
    public boolean initiateRefund(double amount) {
        if (amount <= orderAmount) {
            refundStatus = "INITIATED";
            sendSMS("Refund of ₹"+amount+" initiated for order "+orderId);
            return true;
        }
        return false;
    }
    @Override
    public String getRefundStatus() { return refundStatus; }

    // Notifiable implementation
    @Override
    public void sendSMS(String message) {
        System.out.println("SMS → "+customerMobile+": "+message);
    }
    @Override
    public void sendEmail(String subject, String body) {
        System.out.println("Email → Subj: "+subject);
    }
}

The static Keyword

Class-level members — shared state and utility methods

📘
What does static mean?

A static field or method belongs to the class itself, not to any object. All objects share the same static field. You call static methods on the class name, not on an object.

📊

Static Variable

Shared counter, constant rate, global configuration. E.g. total transactions processed, bank name, tax rate.

🔧

Static Method

Utility methods that don't need object state. E.g. InterestCalculator.calculate(), DateUtil.formatDate().

🏦 Banking Domain
Static — Transaction counter + Utility class 
public class Transaction {
    // Shared by ALL Transaction objects — counts every transaction ever made
    private static int  transactionCount = 0;
    private static final String BANK_NAME = "SBI Bank";

    // Instance variables — each Transaction has its own
    private int    txnId;
    private String type;
    private double amount;

    public Transaction(String type, double amount) {
        transactionCount++;                // increments class-level counter
        this.txnId  = transactionCount;
        this.type   = type;
        this.amount = amount;
    }

    // Static method — no object needed
    public static int getTransactionCount() {
        return transactionCount;
    }

    public static String getBankName() { return BANK_NAME; }

    public void printReceipt() {
        System.out.println(BANK_NAME + " | TXN#"+txnId+" | "+type+": ₹"+amount);
    }
}

// Static utility class — no need to create objects
public class EMICalculator {
    // Standard EMI formula: P × r × (1+r)^n / ((1+r)^n - 1)
    public static double calculateEMI(double principal,
                                        double annualRate, int months) {
        double r = annualRate / (12 * 100);
        double numerator   = principal * r * Math.pow(1 + r, months);
        double denominator = Math.pow(1 + r, months) - 1;
        return Math.round(numerator / denominator);
    }
}

Exception Handling

Graceful failure — protecting your system when things go wrong

📘
What is Exception Handling?

An exception is an event that disrupts normal program flow — network failure, invalid input, null reference, insufficient balance. Without handling, the JVM prints a stack trace and crashes. With try-catch, you catch errors and respond gracefully.

⚠️
What happens without exception handling in banking?
  • A failed database connection during a fund transfer crashes the app — the money is deducted but never received
  • Invalid account number input causes a NumberFormatException that exposes stack traces to the user
  • A null customer reference in a loan approval loop crashes the entire batch job
🏦 Banking Domain — Fund Transfer
Exception Handling — Banking Transactions 
// ══ Custom Exception — domain-specific error ══
public class InsufficientFundsException extends Exception {
    private double shortfall;

    public InsufficientFundsException(double shortfall) {
        super("Insufficient funds. Shortfall: ₹" + shortfall);
        this.shortfall = shortfall;
    }

    public double getShortfall() { return shortfall; }
}

public class BankTransferService {

    // 'throws' declares that this method can throw the exception
    public void transfer(SBIAccount from, SBIAccount to, double amount)
            throws InsufficientFundsException {

        if (amount <= 0) {
            throw new IllegalArgumentException("Amount must be positive");
        }
        if (from.getBalance() < amount) {
            double shortfall = amount - from.getBalance();
            throw new InsufficientFundsException(shortfall);  // throw our custom exception
        }
        // If we reach here, transfer is safe
        from.withdraw(amount);
        to.deposit(amount);
        System.out.println("✅ Transfer of ₹"+amount+" successful.");
    }
}

// Using try-catch-finally
BankTransferService service = new BankTransferService();
SBIAccount a1 = new SBIAccount("Raj", 5000);
SBIAccount a2 = new SBIAccount("Priya", 1000);

try {
    service.transfer(a1, a2, 3000);   // ✅ succeeds
    service.transfer(a1, a2, 9000);   // ❌ throws InsufficientFundsException
} catch (InsufficientFundsException e) {
    System.out.println("❌ Transfer failed: " + e.getMessage());
    System.out.println("   Need ₹" + e.getShortfall() + " more to complete transfer");
} catch (IllegalArgumentException e) {
    System.out.println("❌ Invalid input: " + e.getMessage());
} finally {
    // ALWAYS runs — use for cleanup: close DB connections, log the attempt
    System.out.println("[LOG] Transfer attempt completed.");
}

// ── 1. Custom Exception ──
class InsufficientFundsException extends Exception {
    private double available;
    public InsufficientFundsException(double avail) {
        super("Insufficient funds. Available: ₹" + avail);
        this.available = avail;
    }
    public double getAvailable() { return available; }
}

// ── 2. Interface ──
interface Transactable {
    void   credit(double amount);
    void   debit(double amount) throws InsufficientFundsException;
    double getBalance();
}

// ── 3. Abstract Class ──
abstract class BankAccount implements Transactable {
    private static int    totalAccounts = 0;
    protected int         accountNumber;
    protected String      accountHolder;
    protected double      balance;

    public BankAccount(int accNo, String holder, double opening) {
        this.accountNumber = accNo;
        this.accountHolder = holder;
        this.balance       = opening;
        totalAccounts++;
    }

    public abstract String getAccountType();

    @Override
    public void credit(double amount) {
        if (amount > 0) { balance += amount; 
        System.out.println("✅ Credited ₹"+amount+" to "+accountHolder); }
    }

    @Override
    public void debit(double amount) throws InsufficientFundsException {
        if (amount > balance) throw new InsufficientFundsException(balance);
        balance -= amount;
        System.out.println("✅ Debited ₹"+amount+" from "+accountHolder);
    }

    @Override public double getBalance() { return balance; }

    public void printStatement() {
        System.out.println("\n━━━ Statement ━━━");
        System.out.println("Type   : "+getAccountType());
        System.out.println("Acc#   : "+accountNumber);
        System.out.println("Holder : "+accountHolder);
        System.out.println("Balance: ₹"+balance);
    }

    public static int getTotalAccounts() { return totalAccounts; }
}

class SavingsAccount extends BankAccount {
    private double interestRate = 3.5;
    public SavingsAccount(int no, String h, double b) { super(no,h,b); }

            cur.debit(140000);   // uses overdraft
            sav.debit(999999);  // ← throws exception
        } catch (InsufficientFundsException e) {
            System.out.println("❌ " + e.getMessage());
        } finally {
            sav.printStatement();
            cur.printStatement();
            System.out.println("Total accounts: "+BankAccount.getTotalAccounts());
        }
    }
}
