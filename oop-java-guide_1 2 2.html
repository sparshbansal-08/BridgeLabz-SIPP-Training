What is Object-Oriented Programming?

The big picture before we dive in

Before OOP, programs were just long lists of instructions — one thing after another. This was hard to organise, hard to reuse, and nearly impossible to maintain in large projects.

OOP is a way of writing code that models the real world. Instead of thinking in procedures, you think in things — objects that have data (properties) and can do stuff (methods).

Real-World Analogy Think about a car. A car has data — colour, brand, speed, fuel. A car can do things — accelerate, brake, honk. In OOP, we model this exactly: the data becomes fields, and the actions become methods. The blueprint for "what a car is" is the class. Your actual red Honda in the driveway is the object.

🔒 Encapsulation

Hiding internal data. Only expose what's needed. Like a capsule pill — the medicine is inside, protected.

🧬 Inheritance

A child class gets the properties and methods of a parent class automatically. Like a child inheriting traits from parents.

🎭 Polymorphism

One name, many forms. A method can behave differently depending on the object. Like a "speak" command that works for Dog, Cat, and Bird.

🎨 Abstraction

Hiding complexity. You use a TV remote without knowing the circuit board. You call a method without knowing how it works internally.

Classes

The blueprint — defining what something is

📘
What is a Class?

A class is a template or blueprint. It defines what data an object will hold and what actions it can perform. No memory is used until you create an actual object from it.

💡
Why use Classes?

Instead of writing separate variables for every student in a school system, you define a Student class once — and create as many student objects as you need. Reusable, organised, maintainable.

📅
When to create a Class?

Whenever you have a concept that has both data (name, age, price) and behaviour (calculate, display, save). Real-world nouns are great candidates: Car, BankAccount, Student.

Syntax & Rules

Class syntax 
// Syntax:
accessModifier class ClassName {
    // fields (data / attributes)
    dataType fieldName;

    // constructor
    ClassName(parameters) { ... }

    // methods (behaviours)
    returnType methodName(parameters) { ... }
}
  • ✅ Class name starts with a capital letter: Student, BankAccount
  • ✅ One public class per file, and the filename must match the class name exactly
  • ✅ Fields (variables inside the class) usually have access modifier private
  • ⚠️ A class is just a blueprint — it stores no data by itself

Full Example — Defining a Class

Dog.java 
public class Dog {

    // Fields — the data a Dog holds
    String name;
    String breed;
    int    age;

    // Method — something a Dog can do
    void bark() {
        System.out.println(name + " says: Woof!");
    }

    void displayInfo() {
        System.out.println("Name: " + name + ", Breed: " + breed + ", Age: " + age);
    }
}

// At this point, no Dog exists yet. This is just the blueprint.

Objects

The real thing — creating instances from blueprints

📘
What is an Object?

An object is a specific instance of a class. When you create an object, Java allocates memory for it and it gets its own copy of the class's fields. Multiple objects from the same class are all independent.

Analogy The class Dog is the concept "dog". The objects myDog and yourDog are two actual dogs — they share the same structure (name, breed, age) but have completely different values.

Creating Objects — step by step

Declare a variable of the class type

Dog myDog; — this reserves space for a reference, but the object doesn't exist yet.

Use the new keyword to create the object

myDog = new Dog(); — Java allocates memory and calls the constructor.

Combine into one line (most common)

Dog myDog = new Dog(); — declare and create together.

Access fields and methods with the dot operator

myDog.name = "Rex"; or myDog.bark();

Main.java — creating and using objects 
public class Main {
    public static void main(String[] args) {

        // Create first Dog object
        Dog myDog = new Dog();
        myDog.name  = "Rex";
        myDog.breed = "Labrador";
        myDog.age   = 3;

        // Create second Dog object — completely independent!
        Dog yourDog = new Dog();
        yourDog.name  = "Bella";
        yourDog.breed = "Poodle";
        yourDog.age   = 5;

        // Call methods on each object
        myDog.bark();          // Rex says: Woof!
        yourDog.bark();        // Bella says: Woof!
        myDog.displayInfo();   // Name: Rex, Breed: Labrador, Age: 3
    }
}

Constructors

Initialising objects at birth

📘
What is a Constructor?

A constructor is a special method that runs automatically when you create an object with new. Its job is to set the object's initial values. It has the same name as the class and no return type.

💡
Why use Constructors?

Without a constructor, you have to set every field manually after creation — messy and error-prone. With a constructor, you set everything in one clean step when creating the object.

Types of Constructors

🏗️

Default Constructor

No parameters. Java creates one automatically if you write none. Fields get default values (0, null, false).

🔧

Parameterised Constructor

Accepts arguments. You pass values when creating the object, so it starts fully initialised.

📋

Constructor Overloading

Multiple constructors with different parameters. Java picks the right one based on what you pass.

Student.java — constructors demonstrated 
public class Student {

    String name;
    int    age;
    double gpa;

    // ── 1. Default constructor (no parameters)
    Student() {
        name = "Unknown";
        age  = 0;
        gpa  = 0.0;
    }

    // ── 2. Parameterised constructor
    Student(String name, int age, double gpa) {
        this.name = name;    // 'this' explained in next section
        this.age  = age;
        this.gpa  = gpa;
    }

    void display() {
        System.out.println(name + " | Age: " + age + " | GPA: " + gpa);
    }
}

// In Main:
Student s1 = new Student();                  // uses default constructor
Student s2 = new Student("Alice", 20, 3.9);  // uses parameterised constructor

s1.display();  // Unknown | Age: 0 | GPA: 0.0
s2.display();  // Alice   | Age: 20 | GPA: 3.9
  • ✅ Constructor name must exactly match the class name (including case)
  • ✅ No return type — not even void
  • ✅ Called automatically when you write new ClassName()
  • ⚠️ If you write any constructor, Java no longer provides a default — add one yourself if needed

The this Keyword

Referring to the current object

📘
What is this?

this is a reference to the current object — the one the method or constructor is running on right now. It tells Java "I mean this object's field, not the local variable."

When do you need this?

The most common situation: your constructor parameter has the same name as the field. Without this, Java gets confused and uses the parameter for both.

Why this is needed — the confusion problem 
public class Person {
    String name;   // ← field
    int    age;    // ← field

    // ❌ WITHOUT this — broken!
    Person(String name, int age) {
        name = name;  // Just assigns the parameter to itself! Field stays null.
        age  = age;   // Same problem — field stays 0.
    }

    // ✅ WITH this — correct!
    Person(String name, int age) {
        this.name = name;  // this.name = the field | name = the parameter
        this.age  = age;   // clear, unambiguous
    }
}

Other uses of this

this() — calling one constructor from another 
public class Rectangle {
    int width;
    int height;

    // Full constructor
    Rectangle(int width, int height) {
        this.width  = width;
        this.height = height;
    }

    // Square shortcut — calls the constructor above with this()
    Rectangle(int side) {
        this(side, side);  // reuses the code above — no duplication!
    }

    int area() {
        return this.width * this.height;
    }
}

// Usage:
Rectangle r1 = new Rectangle(4, 6);   // area = 24
Rectangle r2 = new Rectangle(5);      // area = 25 (5x5 square)

Encapsulation

Protecting data with private fields and getters/setters

📘
What is Encapsulation?

Encapsulation means wrapping data (fields) and the methods that work on it inside a class, then hiding the fields from outside code. You only allow access through controlled methods called getters and setters.

💡
Why use Encapsulation?
  • Prevents invalid data (e.g. someone setting age to -500)
  • You can change the internal implementation without breaking external code
  • Clear boundary between what is public and what is internal
Analogy Think of a bank account. You can't directly put your hand into the database and change the balance. You go through official methods: deposit() and withdraw(). Those methods contain rules (can't withdraw more than balance). That's encapsulation.

Access Modifiers

ModifierSame ClassSame PackageSubclassEverywhere
private✅❌❌❌
default (no modifier)✅✅❌❌
protected✅✅✅❌
public✅✅✅✅
👆
Golden Rule

Make fields private. Provide public getters and setters. This is the standard Java convention you'll see in every professional codebase.

BankAccount.java — full encapsulation example 
public class BankAccount {

    // Private fields — hidden from outside code
    private String owner;
    private double balance;

    // Constructor
    public BankAccount(String owner, double initialBalance) {
        this.owner   = owner;
        this.balance = (initialBalance > 0) ? initialBalance : 0;
    }

    // ── Getter — read-only access
    public double getBalance() {
        return balance;
    }
    public String getOwner() {
        return owner;
    }

    // ── Business methods — controlled write access
    public void deposit(double amount) {
        if (amount > 0) {
            balance += amount;
            System.out.println("Deposited: " + amount);
        } else {
            System.out.println("Invalid amount.");
        }
    }

    public void withdraw(double amount) {
        if (amount > 0 && amount <= balance) {
            balance -= amount;
            System.out.println("Withdrawn: " + amount);
        } else {
            System.out.println("Insufficient funds.");
        }
    }
}

// Usage:
BankAccount acc = new BankAccount("Alice", 1000);
acc.deposit(500);               // Deposited: 500.0
acc.withdraw(200);              // Withdrawn: 200.0
acc.withdraw(9999);             // Insufficient funds.
System.out.println(acc.getBalance());  // 1300.0

// This would NOT compile — balance is private:
// acc.balance = -99999;  ← ERROR!
Exercise 2 Encapsulation — Temperature Class

Create a class Temperature with a private field celsius (double). Write a setter that rejects values below −273.15 (absolute zero). Write a getter for celsius and a method toFahrenheit() that returns the converted value.

Solution 
public class Temperature {
    private double celsius;

    public void setCelsius(double celsius) {
        if (celsius < -273.15) {
            System.out.println("Below absolute zero! Not allowed.");
        } else {
            this.celsius = celsius;
        }
    }

    public double getCelsius() {
        return celsius;
    }

    public double toFahrenheit() {
        return (celsius * 9.0 / 5.0) + 32;
    }
}

Inheritance

Building new classes on top of existing ones

📘
What is Inheritance?

Inheritance lets a class (child/subclass) automatically receive all the non-private fields and methods of another class (parent/superclass). The child can then add its own fields/methods or override existing ones.

💡
Why use Inheritance?

Code reuse. Instead of rewriting name, age, and displayInfo() in every class, put them in a parent class once. All children get them for free. Changes in the parent apply to all children automatically.

Analogy Animal is the parent. Dog and Cat are children. All animals breathe and eat — so those methods live in Animal. Dogs bark, cats meow — those are specific methods in each child class.
Animal.java + Dog.java + Cat.java — inheritance 
// ── Parent class
public class Animal {
    protected String name;
    protected int    age;

    public Animal(String name, int age) {
        this.name = name;
        this.age  = age;
    }

    public void eat() {
        System.out.println(name + " is eating.");
    }

    public void sleep() {
        System.out.println(name + " is sleeping.");
    }
}

// ── Child class: inherits Animal with 'extends'
public class Dog extends Animal {
    private String breed;

    public Dog(String name, int age, String breed) {
        super(name, age);   // calls Animal's constructor
        this.breed = breed;
    }

    // Dog's own method
    public void bark() {
        System.out.println(name + " says: Woof!");
    }
}

public class Cat extends Animal {
    public Cat(String name, int age) {
        super(name, age);
    }

    public void meow() {
        System.out.println(name + " says: Meow!");
    }
}

// In Main:
Dog d = new Dog("Rex", 3, "Labrador");
d.eat();   // inherited from Animal → Rex is eating.
d.bark();  // Dog's own method → Rex says: Woof!

Cat c = new Cat("Luna", 2);
c.sleep();  // inherited → Luna is sleeping.
c.meow();  // Cat's own method → Luna says: Meow!
  • ✅ Use extends keyword: class Dog extends Animal
  • ✅ Java supports single inheritance only — one direct parent per class
  • ✅ Use protected in the parent so children can access fields directly
  • ⚠️ private fields in the parent are NOT inherited (invisible to child)
  • ⚠️ Every class in Java implicitly extends Object — the root of all classes

The super Keyword

Accessing the parent class from a child class

📘
What is super?

super refers to the parent class. It lets you call the parent's constructor (super()) or the parent's methods (super.methodName()) from inside a child class.

super() and super.method() — two uses 
public class Vehicle {
    protected String brand;
    protected int    speed;

    public Vehicle(String brand, int speed) {
        this.brand = brand;
        this.speed = speed;
    }

    public void describe() {
        System.out.println("Brand: " + brand + ", Max speed: " + speed + " km/h");
    }
}

public class ElectricCar extends Vehicle {
    private int batteryRange;

    public ElectricCar(String brand, int speed, int batteryRange) {
        super(brand, speed);   // ← calls Vehicle's constructor
        this.batteryRange = batteryRange;
    }

    // Override describe() but also call the parent's version
    @Override
    public void describe() {
        super.describe();       // ← calls Vehicle.describe() first
        System.out.println("Battery range: " + batteryRange + " km");
    }
}

// Output:
ElectricCar ev = new ElectricCar("Tesla", 250, 500);
ev.describe();
// Brand: Tesla, Max speed: 250 km/h
// Battery range: 500 km
  • ✅ super(args) must be the first line in a constructor
  • ✅ super.method() can be called anywhere in the child's methods
  • ⚠️ You cannot use super in a static method

Polymorphism

One interface, many behaviours

📘
What is Polymorphism?

"Poly" = many, "morph" = form. Polymorphism means the same method name can behave differently depending on the object it's called on. There are two types: method overriding (runtime) and method overloading (compile-time).

🔄

Method Overriding (Runtime)

A child class rewrites a parent method with the same name and signature. Decided at runtime.

📦

Method Overloading (Compile-time)

Same method name but different parameters in the same class. Decided at compile time.

Method Overriding

Overriding — same method, different behaviour 
public class Shape {
    public void draw() {
        System.out.println("Drawing a shape...");
    }
}

public class Circle extends Shape {
    @Override
    public void draw() {
        System.out.println("Drawing a circle ⬤");
    }
}

public class Triangle extends Shape {
    @Override
    public void draw() {
        System.out.println("Drawing a triangle △");
    }
}

// ── The power of polymorphism: use parent type to hold child objects
Shape[] shapes = {new Circle(), new Triangle(), new Shape()};

for (Shape s : shapes) {
    s.draw();  // Each calls ITS OWN draw() — decided at runtime!
}
// Output:
// Drawing a circle ⬤
// Drawing a triangle △
// Drawing a shape...

Method Overloading

Overloading — same name, different parameters 
public class Calculator {

    // add two ints
    public int add(int a, int b) {
        return a + b;
    }

    // add three ints
    public int add(int a, int b, int c) {
        return a + b + c;
    }

    // add two doubles
    public double add(double a, double b) {
        return a + b;
    }
}

Calculator calc = new Calculator();
calc.add(2, 3);           // → 5
calc.add(2, 3, 4);        // → 9
calc.add(1.5, 2.5);       // → 4.0

Abstraction

Hiding complexity, showing only what matters

📘
What is Abstraction?

Abstraction means hiding the complex details and showing only the relevant interface. In Java this is achieved through abstract classes and interfaces. You define what must be done without specifying how.

Analogy You use a TV remote. You press "Volume Up" — you don't know how the infrared signal encodes the command, how the TV's chip decodes it, how the amplifier adjusts. The remote gives you an abstract interface. The complexity is hidden.
🎨

Abstract Class

A class declared with abstract. Can have both regular and abstract methods. Cannot be instantiated directly.

🔌

Interface

A pure contract — all methods are abstract by default. A class can implement multiple interfaces (unlike inheritance).

Abstract Class

Abstract class — Payment system 
// Abstract class — cannot create: new Payment()
public abstract class Payment {
    protected double amount;

    public Payment(double amount) {
        this.amount = amount;
    }

    // Abstract method — no body! Subclasses MUST implement it.
    public abstract void pay();

    // Normal method — inherited by all subclasses
    public void printReceipt() {
        System.out.println("Payment receipt: $" + amount);
    }
}

// Concrete subclass — must implement pay()
public class CreditCardPayment extends Payment {
    private String cardNumber;

    public CreditCardPayment(double amount, String cardNumber) {
        super(amount);
        this.cardNumber = cardNumber;
    }

    @Override
    public void pay() {
        System.out.println("Paid $" + amount + " via Credit Card **** " + cardNumber.substring(cardNumber.length() - 4));
    }
}

public class CashPayment extends Payment {
    public CashPayment(double amount) { super(amount); }

    @Override
    public void pay() {
        System.out.println("Paid $" + amount + " in cash.");
    }
}

// Usage:
Payment p1 = new CreditCardPayment(150.00, "1234567890123456");
Payment p2 = new CashPayment(30.00);

p1.pay();            // Paid $150.0 via Credit Card **** 3456
p1.printReceipt();   // Payment receipt: $150.0
p2.pay();            // Paid $30.0 in cash.

Interface

Interface — defining a contract 
// Interface: a pure contract
public interface Printable {
    void print();       // automatically public and abstract
}

public interface Saveable {
    void save();
}

// A class can IMPLEMENT multiple interfaces
public class Report implements Printable, Saveable {
    private String title;

    public Report(String title) { this.title = title; }

    @Override
    public void print() {
        System.out.println("Printing: " + title);
    }

    @Override
    public void save() {
        System.out.println("Saving: " + title);
    }
}
⚡
Abstract Class vs Interface — when to use which?
  • Use abstract class when subclasses share common code (fields, implemented methods)
  • Use interface when you just want to enforce a contract with no shared implementation
  • Use interface when a class needs to fulfil multiple roles (Java allows multiple interface implementation but only single inheritance)
Exercise 4 Abstraction — Shape Area Calculator

Create an abstract class Shape with an abstract method getArea() (returns double). Create subclasses Circle (with field radius) and Rectangle (with fields width and height). Each must implement getArea() with the correct formula. In Main, create one of each and print their areas.

Solution 
public abstract class Shape {
    public abstract double getArea();
}

public class Circle extends Shape {
    private double radius;
    public Circle(double radius) { this.radius = radius; }

    @Override
    public double getArea() {
        return Math.PI * radius * radius;
    }
}

public class Rectangle extends Shape {
    private double width, height;
    public Rectangle(double w, double h) { width = w; height = h; }

    @Override
    public double getArea() { return width * height; }
}

// In Main:
Shape c = new Circle(5);
Shape r = new Rectangle(4, 6);
System.out.println("Circle area: "    + c.getArea());  // ~78.54
System.out.println("Rectangle area: " + r.getArea());  // 24.0

📝
Key Rules Summary
  • One public class per .java file, filename = class name
  • Fields: private. Methods: public. Constructor: public.
  • Always use @Override annotation when overriding parent methods
  • Abstract class with at least one abstract method cannot be instantiated
  • Interface methods are implicitly public abstract
  • super() must be the first line of a child constructor
  • Java is single-inheritance for classes, but multi-implementation for interfaces
Final Challenge Build a Complete OOP System — Library

Combine everything you've learned:

1. Create an abstract class LibraryItem with private fields title and author, a constructor, getters, and an abstract method getDetails().

2. Create subclass Book that adds pageCount and implements getDetails().

3. Create subclass Magazine that adds issueNumber and implements getDetails().

4. In Main, create an array of LibraryItem containing both Books and Magazines. Loop through and call getDetails() on each.

Full Solution 
public abstract class LibraryItem {
    private String title;
    private String author;

    public LibraryItem(String title, String author) {
        this.title  = title;
        this.author = author;
    }

    public String getTitle()  { return title; }
    public String getAuthor() { return author; }

    public abstract void getDetails();
}

public class Book extends LibraryItem {
    private int pageCount;

    public Book(String title, String author, int pageCount) {
        super(title, author);
        this.pageCount = pageCount;
    }

    @Override
    public void getDetails() {
        System.out.println("[Book] " + getTitle() + " by " + getAuthor() + " | Pages: " + pageCount);
    }
}

public class Magazine extends LibraryItem {
    private int issueNumber;

    public Magazine(String title, String author, int issueNumber) {
        super(title, author);
        this.issueNumber = issueNumber;
    }

    @Override
    public void getDetails() {
        System.out.println("[Magazine] " + getTitle() + " | Issue #" + issueNumber);
    }
}

// Main:
LibraryItem[] items = {
    new Book("Clean Code", "Robert Martin", 464),
    new Magazine("National Geographic", "NG Society", 523),
    new Book("Effective Java", "Joshua Bloch", 412)
};

for (LibraryItem item : items) {
    item.getDetails();
}
// [Book] Clean Code by Robert Martin | Pages: 464
// [Magazine] National Geographic | Issue #523
// [Book] Effective Java by Joshua Bloch | Pages: 412
