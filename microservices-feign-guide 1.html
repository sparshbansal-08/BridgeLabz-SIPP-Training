What this guide covers

This is a focused companion to the full microservices guide. It zooms in on the single most common beginner question: how does one service call another? We use the same example throughout — a Product Service that owns products, and an Order Service that needs product details to build an order. The Order Service is the caller; the Product Service is just a normal REST service being called.

Every main concept uses the same nine headings: what it is (with an analogy), why we need it, mandatory or optional, what happens without it, what we gain, how to implement it, the annotations involved, how to test it, and what is next. Tech: Java 17, Spring Boot 3.x, Spring Cloud, Maven, Postman.

The myth to drop right now

There is no "Feign server". Feign lives only on the caller. The Product Service is the ordinary REST service you already know; it does not change at all because someone calls it with Feign.

1Service Discovery with Eureka (the foundation Feign uses)

1 · What it is

A live directory of services. Each service registers its name and address when it starts; callers look services up by name instead of memorising addresses. We cover it first because the clean version of Feign calls services by name, and that name resolves through Eureka.

Analogy

A phone directory. You search a name and get the current number; if the number changes, the directory updates and you still just search the name.

2 · Why we need it (the port-number problem)

Without a directory, the Order Service must hardcode http://localhost:8081 to reach the Product Service. The moment the Product Service moves port or machine, or runs as several copies, that hardcoded address breaks and must be edited everywhere. Eureka removes memorised addresses entirely.

3 · Mandatory or optional

Recommended You can use Feign with a fixed url and no Eureka, but then you are back to hardcoding addresses. With Eureka, Feign calls by name. This guide assumes Eureka is on.

4 · What happens without it

Hardcoded addresses scattered across callers; every move or scale-up means hunting and editing addresses and redeploying. A wrong port fails only at runtime, with no compile-time warning.

5 · What we gain

Callers use the name product-service; services can move or scale and the directory stays current automatically.

6 · How to implement it step by step

The Eureka Server (a separate project named eureka-server, dependency "Eureka Server"):

eureka-server/.../EurekaServerApplication.java
@SpringBootApplication
@EnableEurekaServer
public class EurekaServerApplication {
    public static void main(String[] args) { SpringApplication.run(EurekaServerApplication.class, args); }
}
eureka-server/src/main/resources/application.properties
spring.application.name=eureka-server
server.port=8761
eureka.client.register-with-eureka=false
eureka.client.fetch-registry=false

Each business service adds the Eureka client dependency and points at the directory:

product-service & order-service: pom.xml (add this)
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-netflix-eureka-client</artifactId>
</dependency>
product-service/application.properties
# This name is what the Order Service's Feign client will use. Keep it exact.
spring.application.name=product-service
server.port=8081
eureka.client.service-url.defaultZone=http://localhost:8761/eureka/

The Order Service uses the same lines with spring.application.name=order-service and server.port=8082.

Start Eureka, then Product Service. Open http://localhost:8761 — you should see PRODUCT-SERVICE listed under registered instances. That line proves the name is now resolvable, which is exactly what Feign will rely on.

Services register by name. Now the Order Service can call the Product Service by that name — the job of Feign, next.

2Feign Client (the heart of this guide)

1 · What it is

Feign lets the Order Service call the Product Service by writing a simple Java interface that describes the call. You declare the method; Feign builds the real HTTP request, sends it, reads the reply, and converts the JSON into an object for you.

Analogy

Speed-dial. Instead of dialing a full number each time, you press one labelled button. You label the call once ("get product by id"); Feign does the dialing every time you press it.

2 · Why we need it

The Order Service needs product details. Doing that by hand means building the URL, sending a request, reading the response, converting JSON, and handling errors — repeated at every call site. Feign collapses all of that into one interface method.

3 · Mandatory or optional

Core idea, chosen tool Service-to-service communication is core to microservices. The specific tool is a choice (Feign, RestTemplate, or WebClient); Feign is the simplest to read and write, so it is the default for beginners.

4 · What happens without Feign (the hard way) 
// Manual call, repeated at every call site, address hardcoded:
RestTemplate rest = new RestTemplate();
String url = "http://localhost:8081/products/" + id;
ProductResponse p = rest.getForObject(url, ProductResponse.class);

Verbose, repetitive, and the hardcoded address brings back the port problem from concept 1.

5 · What we gain with Feign

One interface, reused everywhere. Calls go by service name (no address), JSON-to-object conversion is automatic, and each call site is a single readable line.

6 · How to implement it step by step (all in the Order Service)

Step 1 — add the Feign dependency.

order-service/pom.xml (add this)
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-openfeign</artifactId>
</dependency>

Step 2 — switch Feign on once on the Order Service main class.

order-service/.../OrderServiceApplication.java
@SpringBootApplication
@EnableFeignClients          // makes Spring find and build your @FeignClient interfaces
public class OrderServiceApplication {
    public static void main(String[] args) { SpringApplication.run(OrderServiceApplication.class, args); }
}

Step 3 — define a local DTO for the product fields the Order Service needs (it must not import the Product entity from the other service — see the DTO section below).

order-service/dto/ProductResponse.java
package com.example.orderservice.dto;
import java.math.BigDecimal;

public class ProductResponse {
    private Long id;
    private String name;
    private BigDecimal price;
    public Long getId() { return id; }            public void setId(Long id) { this.id = id; }
    public String getName() { return name; }       public void setName(String name) { this.name = name; }
    public BigDecimal getPrice() { return price; } public void setPrice(BigDecimal price) { this.price = price; }
}

Step 4 — declare the Feign client interface. You only describe the call.

order-service/client/ProductClient.java
package com.example.orderservice.client;

import com.example.orderservice.dto.ProductResponse;
import org.springframework.cloud.openfeign.FeignClient;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;

// "product-service" MUST match the provider's spring.application.name.
// With Eureka running, Feign turns that name into a real address automatically.
@FeignClient(name = "product-service")
public interface ProductClient {

    @GetMapping("/products/{id}")          // must match the Product controller's URL exactly
    ProductResponse getProductById(@PathVariable("id") Long id);
}

Step 5 — use it like a normal object in the Order controller.

order-service/controller/OrderController.java
@RestController
@RequestMapping("/orders")
public class OrderController {

    private final ProductClient productClient;
    public OrderController(ProductClient productClient) { this.productClient = productClient; }

    @GetMapping("/check/{productId}")
    public String check(@PathVariable Long productId) {
        ProductResponse p = productClient.getProductById(productId);   // one clean call
        return "Order can include: " + p.getName() + " at price " + p.getPrice();
    }
}

8 · How to test it

Start Eureka (8761), Product Service (8081), Order Service (8082). Create a product first (POST http://localhost:8081/products with a JSON body). Then call the consumer:

GET http://localhost:8082/orders/check/1

Expected: Order can include: Wireless Mouse at price 799.00. Your single Feign line triggered a name lookup in Eureka, a real HTTP call to Product Service, and JSON-to-object conversion.

9 · Where we are and what is next

The Order Service calls the Product Service cleanly, by name. The remaining sections answer the questions beginners ask next: which @FeignClient settings are required, how Feign compares to the alternatives, and how to handle the response type.

3The @FeignClient Attributes (is the name mandatory?)

Beginners get confused by the few settings inside @FeignClient(...). Here is exactly what each does and whether you need it.

AttributeWhat it doesStatus
name (same as value)The target service name. With Eureka on, this is resolved to a live address. This is the normal way.MANDATORY (you must name a target somehow)
urlA fixed address like http://localhost:8081. Use only when there is no Eureka. It brings back hardcoded addresses, so avoid it in a discovery-based system.OPTIONAL
pathA common URL prefix added to every method, e.g. path="/products" so methods only write /{id}. Convenience only.OPTIONAL
Is the name mandatory?

You must give Feign a target. The usual and recommended form is name = "product-service" (resolved by Eureka). The only alternative is a fixed url, which abandons discovery. So in a Eureka-based project, treat name as required.

Valid forms at a glance

@FeignClient(name = "product-service")                       // by name, via Eureka (recommended)
@FeignClient(name = "product-service", path = "/products")   // name + shared prefix
@FeignClient(name = "product-service", url = "http://localhost:8081")  // fixed url (no Eureka)

4Three Ways to Call Another Service — Compared

Feign is not the only option. Seeing the alternatives makes clear why Feign is the beginner default.

ToolHow it feelsBest forBeginner verdict
RestTemplateYou build the URL and make the call by hand. Blocking (waits for each call).Old code that already uses it.Avoid for new code; it is in maintenance mode.
WebClientFluent calls; can fire several requests at once and wait only for the slowest.Many calls in parallel.Use when you need parallel calls.
@FeignClientYou declare an interface; no calling code at all.Most everyday service-to-service calls.Default choice for beginners.

The same call, all three ways:

// RestTemplate: you build the URL and call
ProductResponse p = restTemplate.getForObject(url + "/products/" + id, ProductResponse.class);

// WebClient: fluent, you still do each step
ProductResponse p = productWebClient.get().uri("/products/{id}", id)
        .retrieve().bodyToMono(ProductResponse.class).block();

// Feign: declare once in the interface, then just call the method
ProductResponse p = productClient.getProductById(id);
Recommendation

Use Feign by default. Reach for WebClient only when you must call several services in parallel. Avoid RestTemplate for new code.

5The DTO Question: what type comes back?

A very common beginner question: the Product entity lives in the Product Service — how does the Order Service receive it? The answer is the single most important rule of clean service calls.

Do not do this

Do not import or share the Product Service's entity class. Sharing the entity glues the two services together: a change to the Product entity would force a change in the Order Service, defeating their independence.

Do this instead

The Order Service defines its own small DTO (ProductResponse above) containing only the fields it actually uses (id, name, price). Feign matches the JSON fields to this DTO by name. Extra fields in the JSON that your DTO leaves out are simply ignored.

Can the Order Service store product data?

Yes, but only a snapshot of what an order genuinely needs — for example the product name and the price at the time of the order — saved in the order's own record. It must never try to keep a full copy of the product catalogue in sync; that would make it a second owner of product data and break database-per-service.

6Running and Testing the Whole Flow

Start in order, each in its own terminal with mvn spring-boot:run:

OrderServicePortWhy here
1Eureka Server8761The directory must be up so services can register and be found.
2Product Service8081The provider registers itself by name.
3Order Service8082The consumer registers, then can find the provider by name.

Verify step by step

  1. Eureka dashboard http://localhost:8761 lists PRODUCT-SERVICE and ORDER-SERVICE.
  2. Create a product: POST http://localhost:8081/products with body { "name": "Wireless Mouse", "price": 799.00, "quantity": 50 }.
  3. Direct read works: GET http://localhost:8081/products/1.
  4. The Feign call works: GET http://localhost:8082/orders/check/1 returns the product name and price — proof the consumer reached the provider by name.

7Troubleshooting

SymptomLikely cause and fix
"No instances available for product-service"The provider is not registered, or you started the consumer before Eureka/the provider were ready. Check the Eureka dashboard shows PRODUCT-SERVICE, then retry.
Feign call returns 404The interface's @GetMapping path does not exactly match the provider's controller URL. Compare /products/{id} on both sides.
The interface is never called / injection fails@EnableFeignClients is missing from the Order Service main class, or the Feign dependency is not in the pom.
Name does not resolveThe @FeignClient(name=...) does not match the provider's spring.application.name. They must be identical.
Response fields are all nullYour DTO field names do not match the JSON keys returned by the provider. Match id, name, price exactly.

Summary

  • Eureka is the directory; it lets you call services by name instead of by memorised address.
  • Feign is a client-only tool: you declare an interface and Spring builds the real call. There is no "Feign server".
  • @EnableFeignClients (on the caller's main class) and @FeignClient(name=...) (on the interface) are the two mandatory annotations; the name must match the provider's spring.application.name.
  • Receive responses into your own local DTO, never the other service's entity.
  • Prefer Feign by default; use WebClient for parallel calls; avoid RestTemplate for new code.
The one line to remember

Feign turns "make an HTTP call to another service" into "call a method on an interface" — and Eureka makes that work by name, not by address.
