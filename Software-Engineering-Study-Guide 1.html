1. Agile & Software Maintenance

Agile is an iterative approach to delivering software in small, working increments. Scrum is the most widely used Agile framework. It organizes work into fixed-length iterations called sprints, supported by defined roles, events (ceremonies), and artifacts.

1.1 Core Agile Values and Scrum Pillars

The Agile Manifesto defines four values. Scrum adds three empirical pillars.

1.5 Q&A

Q1. What is the difference between Agile and Scrum?
Agile is a philosophy defined by the Agile Manifesto (values and principles). Scrum is one concrete framework that implements Agile using sprints, roles, and ceremonies. All Scrum is Agile, but not all Agile is Scrum (Kanban and XP are other Agile approaches).
Q2. Can the Sprint Backlog change during a sprint?
The sprint goal stays fixed, but the detailed work can be renegotiated between the team and Product Owner as more is learned. New scope that threatens the goal should wait for the next sprint.
Q3. Who runs the Daily Standup?
The Development Team owns it. The Scrum Master ensures it happens and stays within the timebox but does not run it as a status meeting.
Q4. What is the difference between a Sprint Review and a Retrospective?
The Review inspects the product (demo to stakeholders, feedback on what was built). The Retrospective inspects the process (how the team worked and how to improve).

Q5. What is the difference between response time and resolution time in an SLA?
Response time is how quickly the team acknowledges and begins work on a ticket. Resolution time is how quickly the issue is actually fixed. A P1 may require a 15-minute response but allow a few hours for full resolution.
Q6. When should L2 escalate to L3?
When the issue requires source-code changes, a database fix, or root-cause analysis that goes beyond configuration and known workarounds. L3 owns permanent code-level fixes.

2.2 File Permissions: chmod and chown

Each file has three permission groups: owner (user), group, and others. Each group can have read (r=4), write (w=2), and execute (x=1) permissions. 

 -rwxr-xr--   1  alice  devs   ...   script.sh
 |  |  |  |
 |  |  |  +--- others: r--  (4)  read only
 |  |  +------ group:  r-x  (5)  read + execute
 |  +--------- owner:  rwx  (7)  read + write + execute
 +------------ file type ( - file, d directory, l link )
OctalSymbolicMeaning
7rwxread + write + execute
6rw-read + write
5r-xread + execute
4r--read only
0---no access
# Give owner all, group read+execute, others read (754)
chmod 754 script.sh

# Symbolic form: add execute for the owner
chmod u+x script.sh

# Recursively set permissions on a directory tree
chmod -R 755 /opt/app

# Change the owner to 'alice' and group to 'devs'
chown alice:devs script.sh

# Change owner recursively
chown -R alice:devs /opt/app

2.3 Stream Processing: grep, awk, sed

ToolBest atOne-line description
grepSearchingFind lines that match a pattern
awkColumns / fieldsProcess structured text by field, compute, format
sedEditingStream editor for find-and-replace and transforms
# grep: show ERROR lines, case-insensitive, with line numbers
grep -in "error" app.log

# grep: recursive search in a project for a TODO
grep -rn "TODO" ./src

# awk: print the 1st and 3rd whitespace-separated columns
awk '{ print $1, $3 }' access.log

# awk: sum the 5th column (e.g., bytes transferred)
awk '{ total += $5 } END { print total }' access.log

# awk: use a custom field separator (CSV) and filter
awk -F',' '$3 > 100 { print $1 }' data.csv

# sed: replace the first 'foo' with 'bar' on each line
sed 's/foo/bar/' file.txt

# sed: replace ALL occurrences (global) and edit the file in place
sed -i 's/foo/bar/g' file.txt

# sed: delete blank lines
sed '/^$/d' file.txt

2.4 Pipes and Redirection

A pipe | sends the output of one command as the input of the next, allowing small tools to be chained.

# Count how many ERROR lines are in the log
grep "ERROR" app.log | wc -l

# Top 5 most frequent IP addresses in an access log
awk '{ print $1 }' access.log | sort | uniq -c | sort -nr | head -5

# Redirection operators
command >  out.txt   # overwrite stdout to a file
command >> out.txt   # append stdout to a file
command 2> err.txt   # redirect stderr
command <  in.txt    # take stdin from a file

2.6 Q&A

Q1. When would you use awk instead of grep?
Use grep to find lines matching a pattern. Use awk when you need to work with specific columns or fields, do arithmetic, or format output. grep filters; awk processes.
Q2. What is the difference between > and >>?
> overwrites the target file with new output. >> appends to the end of the file, preserving existing content.
Q3. What does chmod 755 mean?
Owner gets read+write+execute (7), group gets read+execute (5), others get read+execute (5). It is common for executable scripts and directories.
Q4. Why is the shebang line important?
The shebang (#!/bin/bash) tells the operating system which interpreter to use to run the script, so it executes consistently regardless of the user's current shell.

3.5 Resolving a Merge Conflict (Manually)

A conflict happens when two branches change the same lines. Git marks the conflict and pauses.

<<<<<<< HEAD
int timeout = 30;        // your current branch's version
=======
int timeout = 60;        // the incoming branch's version
>>>>>>> feature/login

Steps to resolve:

# 1. See which files conflict
git status

# 2. Open each file, pick the correct code, and remove the
#    <<<<, ====, and >>>> markers entirely.

# 3. Stage the resolved files
git add Config.java

# 4a. If merging:
git commit

# 4b. If rebasing:
git rebase --continue

# To abandon and start over:
git merge --abort      # or: git rebase --abort

3.6 Q&A

Q1. What is the difference between git fetch and git pull?
git fetch downloads new commits from the remote but does not change your working branch. git pull is fetch followed by merge, so it also updates your current branch.
Q2. What is the difference between staging and committing?
Staging (git add) selects which changes go into the next snapshot. Committing (git commit) permanently records that snapshot in the local repository with a message.
Q3. When should you use rebase over merge?
Use rebase to keep a clean, linear history on your own local feature branch before sharing it. Use merge to integrate shared branches. Never rebase commits that have already been pushed and pulled by others.
Q4. What causes a merge conflict?
Two branches modify the same lines of the same file, or one edits a file the other deletes. Git cannot decide automatically, so it marks the region and asks a human to choose.

4.4 TypeScript Foundations

TypeScript is a superset of JavaScript that adds optional static typing. Browsers cannot run it directly; it is transpiled (compiled) into plain JavaScript. 

TypeScript (.ts)  --[ tsc compiler ]-->  JavaScript (.js)  -->  runs in browser/Node

Static Typing

let count: number = 5;
let title: string = "Report";
let active: boolean = true;

// Function with typed parameters and return type
function add(a: number, b: number): number {
    return a + b;
}

// Error caught at compile time, not at runtime:
// add("2", 3);  // string is not assignable to number

Interface vs. Type

// interface: best for object shapes, can be extended and merged
interface User {
    id: number;
    name: string;
    email?: string;      // optional property
}

// type alias: can also model unions and primitives
type Status = "active" | "inactive";   // union type
type ID = number | string;

4.5 Q&A

Q1. Why must columns add up to 12 in Bootstrap?
The grid divides each row into 12 equal units. Using 12 total ensures columns fit on one line; exceeding 12 makes the extra columns wrap to a new line.
Q2. What does col-12 col-md-6 mean?
The element spans all 12 units (full width) on extra-small and small screens, and 6 units (half width) from the medium breakpoint upward. This is mobile-first responsive design.
Q3. What is transpilation?
Transpilation converts source code from one language to another at a similar level of abstraction. TypeScript is transpiled by the tsc compiler into JavaScript that browsers can run.
Q4. When should you choose a type over an interface?
Use type when you need union types, tuples, or to compose complex types. Use interface for object contracts you expect to extend or that form a public API.

5. Logging Frameworks (Log4j & SLF4J)

Logging records what an application does at runtime. A logging framework provides control over what is recorded, at what severity, in what format, and where it is sent.

5.1 SLF4J vs. Log4j: Facade vs. Implementation

AspectSLF4JLog4j 2 / Logback
What it isAn abstraction (facade) APIA concrete logging implementation
RoleYou code against itIt does the actual logging work
BenefitSwap the backend without changing codePerformance, appenders, configuration
AnalogyThe power socket standardThe power station behind it
Best practice: write code against the SLF4J API and plug in Log4j 2 or Logback as the backend. This decouples your application from any single logging library. 
// Code is written against SLF4J, not the implementation
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

public class OrderService {
    private static final Logger log = LoggerFactory.getLogger(OrderService.class);

    public void place(String id) {
        // Parameterized logging avoids building the string unless needed
        log.info("Placing order {}", id);
        try {
            // ... business logic ...
        } catch (Exception e) {
            log.error("Failed to place order {}", id, e);
        }
    }
}

5.5 Q&A

Q1. What is the difference between SLF4J and Log4j?
SLF4J is a facade (an API you program against). Log4j is an implementation that performs the logging. SLF4J lets you change the underlying logging library without changing application code.
Q2. If the level is set to WARN, will INFO messages appear?
No. Only WARN, ERROR, and FATAL appear. The threshold shows the chosen level and everything more severe; less severe levels are suppressed.
Q3. Why prefer parameterized logging like log.info("id {}", id)?
The message string is only assembled if that level is enabled, avoiding unnecessary string concatenation and improving performance, especially for DEBUG and TRACE.
Q4. Why is System.out.println discouraged in real applications?
It has no levels, cannot be reconfigured without recompiling, writes only to the console, lacks context like timestamps and thread names, and performs poorly under load. A logging framework solves all of these.

Creational: Factory Method

interface Shape { void draw(); }
class Circle implements Shape { public void draw() { } }
class Square implements Shape { public void draw() { } }

class ShapeFactory {
    Shape create(String type) {
        return switch (type) {
            case "circle" -> new Circle();
            case "square" -> new Square();
            default -> throw new IllegalArgumentException(type);
        };
    }
}

Behavioral: Strategy

interface SortStrategy { void sort(int[] data); }
class QuickSort  implements SortStrategy { public void sort(int[] d) { } }
class MergeSort  implements SortStrategy { public void sort(int[] d) { } }

class Sorter {
    private SortStrategy strategy;                 // swappable at runtime
    Sorter(SortStrategy s) { this.strategy = s; }
    void run(int[] data) { strategy.sort(data); }
}

Structural: Adapter

// Makes an incompatible class usable through an expected interface
interface MediaPlayer { void play(String file); }

class LegacyAudio { void playMp3(String f) { } }   // incompatible API

class AudioAdapter implements MediaPlayer {
    private final LegacyAudio legacy = new LegacyAudio();
    public void play(String file) { legacy.playMp3(file); }  // translate the call
}

6.5 Q&A

Q1. What does the Open/Closed Principle mean in practice?
You should be able to add new behavior by adding new code (new classes or strategies), not by modifying existing, tested classes. Interfaces and polymorphism make this possible.
Q2. What is the difference between aggregation and composition?
Both are whole-part relationships. In aggregation the parts can exist independently of the whole (a team and its players). In composition the parts cannot exist without the whole (a house and its rooms).
Q3. How do Factory and Strategy patterns differ?
Factory is creational: it decides which object to create. Strategy is behavioral: it swaps an algorithm at runtime. Factory answers "which object," Strategy answers "which behavior."
Q4. Why is Dependency Inversion important for testing?
When a class depends on an interface, you can inject a mock implementation during tests, isolating the class from databases or external services.

7.1 Test-Driven Development (TDD)

        | write a   |        | write the |        | clean up    |
        | failing   |        | minimum   |        | code, tests |
        | test      |        | code to   |        | still pass  |
        |           |        | pass      |        |             |
        +-----------+        +-----------+        +-------------+
              ^                                          |
              +------------------------------------------+

import org.junit.jupiter.api.*;
import static org.junit.jupiter.api.Assertions.*;

class CalculatorTest {

    private Calculator calc;

    @BeforeAll
    static void initAll() { /* runs once, e.g. load config */ }

    @BeforeEach
    void setUp() { calc = new Calculator(); }   // fresh per test

    @Test
    void addsTwoNumbers() {
        assertEquals(5, calc.add(2, 3));            // arrange-act-assert
    }

    @Test
    void throwsOnDivideByZero() {
        assertThrows(ArithmeticException.class, () -> calc.divide(1, 0));
    }

    @AfterEach
    void tearDown() { calc = null; }

    @AfterAll
    static void tearDownAll() { /* runs once at the end */ }
}

7.3 Mockito

Mockito creates fake collaborators so a class can be tested in isolation.

Annotation / TermMeaning
@MockCreate a fake (mock) of a dependency
@InjectMocksCreate the object under test and inject the mocks into it
StubbingDefine what a mock returns: when(...).thenReturn(...)
VerifyingCheck a method was called: verify(...)
SpyWrap a real object; real methods run unless stubbed
AspectMockSpy

@ExtendWith(MockitoExtension.class)
class OrderServiceTest {

    @Mock
    private PaymentGateway gateway;        // fake dependency

    @InjectMocks
    private OrderService service;          // real object, mock injected

    @Test
    void chargesCustomer() {
        // stubbing: define the mock's behavior
        when(gateway.charge(100.0)).thenReturn(true);

        boolean ok = service.checkout(100.0);

        assertTrue(ok);
        // verifying: confirm the interaction happened once
        verify(gateway, times(1)).charge(100.0);
    }
}

7.5 Q&A

Q1. What is the difference between @BeforeEach and @BeforeAll?
@BeforeEach runs before every individual test for fresh setup. @BeforeAll runs once before all tests and must be static, used for expensive shared setup.
Q2. What is the difference between a mock and a spy?
A mock is a fully fake object that returns default values unless stubbed. A spy wraps a real object and runs real methods unless specific ones are stubbed. Use a spy when you need most of the real behavior.
Q3. What is the difference between stubbing and verifying?
Stubbing sets up what a mock should return (when().thenReturn()). Verifying asserts that a method was actually called with expected arguments (verify()).
Q4. What does the Red-Green-Refactor cycle achieve?
It ensures every piece of code is driven by a test (Red), implemented minimally (Green), and then improved safely (Refactor), producing well-tested, well-designed code incrementally.
Q5. Does 100 percent code coverage mean the code is bug-free?
No. Coverage shows which code ran during tests, not whether the assertions are meaningful. High coverage with weak assertions can still miss bugs. It is a useful signal, not a guarantee.
Q6. How does SonarQube use quality profiles and quality gates?
A quality profile is the set of rules applied during analysis. A quality gate is the threshold that decides pass or fail (for example, no new critical issues and coverage above a target). The CI pipeline can block a merge if the gate fails.
