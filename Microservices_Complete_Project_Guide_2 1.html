First — What Is a Microservice? (Simple Concept)

Monolith (what you know)
One single Spring Boot project containing everything — products, orders, users — all in one application, talking to one database. You package it as one JAR and run it as one program.
Microservice (what is new)
The same application split into several small, independent Spring Boot projects. Each one owns a single area (one for products, one for orders, one for login) and has its own database. They run as separate programs and talk to each other over HTTP.
Real-life analogy
A monolith is one large department store where everything is under one roof. Microservices are like a shopping mall — separate specialist shops (each independent), with shared services like security and a directory desk that helps you find each shop.
Why split at all?
If one part fails or needs an update, you fix only that small service — not the whole system. Teams can work on different services independently. Each service can scale on its own.
Beginner: You are NOT learning new Java. You already know how to build one Spring Boot service. Microservices is about running SEVERAL of them and connecting them. The Java code inside each service is the same as you already write.

MySQL Setup — You Never Need to Create Databases Manually

Key: Add ?createDatabaseIfNotExist=true to every datasource URL. Spring Boot creates the database automatically when the service first starts. You only need MySQL running — no manual database creation needed.
All service datasource URLs use this formatPROPERTIES
spring.datasource.url=jdbc:mysql://localhost:3306/product_db?createDatabaseIfNotExist=true
spring.datasource.url=jdbc:mysql://localhost:3306/order_db?createDatabaseIfNotExist=true
spring.datasource.url=jdbc:mysql://localhost:3306/auth_db?createDatabaseIfNotExist=true

POINT 1

Eureka Server — Services Find Each Other by Name

Problem
All services use hardcoded URLs like http://localhost:8081. If product-service moves port or scales to 3 instances — all callers break.
Solution
Every service registers with Eureka by name at startup. Callers ask for the name. Eureka returns the current address. Scale or move with no config change.
Heartbeat
Every 30 seconds each service sends a heartbeat. If heartbeats stop, Eureka removes it after 90 seconds. Dead services never returned.

Code — Just One Annotation

EurekaServerApplication.java — complete codeJAVA
@SpringBootApplication
@EnableEurekaServer  // this one annotation is all that is needed
public class EurekaServerApplication {
    public static void main(String[] args) {
        SpringApplication.run(EurekaServerApplication.class, args);
    }
}

POINT 2

API Gateway — One Entry Point for All Services

Problem
Clients must know every port: 8081, 8082, 8085. Add a new service and every client app needs updating.
Solution
One address: port 8080. Gateway reads URL path, finds the service via Eureka, forwards. Clients never know internal ports.
JWT bonus
When JWT is added (Point 4), Gateway checks token on every request. One filter protects all services.

Routing Logic — How Gateway Decides

Route Matching Order — First Match Wins
✓Request: GET /api/products/1checking routes...
✓routes[0]: Path=/api/products/**MATCH — forward to product-service and stop
✓routes[1]: not checked (already matched)skipped
✓routes[2]: not checked (already matched)skipped
Rule: Gateway checks routes in index order. First match wins. If NO route matches: 404 Not Found.

POINT 4

Spring Security + JWT — Protect Every API

Problem
All APIs open — anyone can DELETE /api/products/1 with no login.
Solution
auth-service issues JWT tokens on login. Gateway checks every request. Services trust all forwarded requests.
What a JWT is
Three dot-separated parts: header (algorithm), payload (email+expiry), signature (tamper-proof). Verified instantly with the shared secret — no database call needed.
JWT token structureSTRUCTURE
eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiJ1c2VyQHRlc3QuY29tIiwiZXhwIjoxNzA0MDY3MjAwfQ.SIG

Part 1: eyJhbGciOiJIUzI1NiJ9
  decoded: { "alg": "HS256" }  — signing algorithm

Part 2: eyJzdWIiOiJ1c2VyQHRlc3QuY29tIiwiZXhwIjoxNzA0MDY3MjAwfQ
  decoded: { "sub": "user@test.com", "exp": 1704067200 }  — who, when expires

Part 3: SIG
  signature — proves parts 1 and 2 were not tampered with

JWT Filter — 5-Step Validation Detail

StepFilter ChecksPASSFAIL — returns
1Is path in PUBLIC_ROUTES? (/auth/login, /auth/register)Skip all checks — forward(continue to step 2)
2Is Authorization header present?(continue)401 — missing header
3Does value start with "Bearer "?Extract token string401 — wrong format
4Can token be parsed with jwt.secret?(continue)401 — invalid/tampered
5Is token NOT expired?Forward to service401 — token expired

#   api-gateway application.properties
Config Server: Cannot find config-repo / 404 for all config requests
Cause: spring.cloud.config.server.native.search-locations points to wrong folder, or config-repo does not exist at that path.
Fix: Create config-repo folder at the ROOT of config-server project (same level as src/, NOT inside src/). Verify the path in application.properties matches.
FixBASH
# config-server application.properties
spring.profiles.active=native
spring.cloud.config.server.native.search-locations=file:./config-repo
# config-repo MUST be here:
# config-server/
#   config-repo/   <-- at this level
#     application.properties
spring.config.import property is required / No spring.config.import property
Cause: In Spring Boot 3, if spring-cloud-starter-config is on the classpath and spring.config.import is not set, the app fails to start.
Fix: Add spring.config.import=optional:configserver:http://localhost:8888 to every service's application.properties. The 'optional:' prefix lets the service start even if Config Server is down.
FixBASH
# Add to every service application.properties:
spring.config.import=optional:configserver:http://localhost:8888
Failed to configure a DataSource: url attribute is not specified
Cause: Spring Boot auto-configures JPA but the datasource URL is not set. Happens on eureka-server or api-gateway if spring-boot-starter-data-jpa was accidentally added.
Fix: Check the pom.xml of eureka-server and api-gateway — they should NOT have spring-boot-starter-data-jpa or mysql-connector-j. Remove them and reload Maven.
FixBASH
Route id is required / Route must have a non-null id
Cause: A route in api-gateway application.properties is missing the .id= line, or the route index numbers have a gap or duplicate.
Fix: Check every route has all 3 required lines: .id=, .uri=, .predicates[0]=. Verify indices are sequential: routes[0], routes[1], routes[2] with no gaps.
FixBASH
# Every route needs exactly these 3 lines:
spring.cloud.gateway.routes[0].id=product-service-route
spring.cloud.gateway.routes[0].uri=lb://product-service
spring.cloud.gateway.routes[0].predicates[0]=Path=/api/products/**
Hibernate failed to create SessionFactory / Table does not exist
Cause: spring.jpa.hibernate.ddl-auto is not set or is set to validate/none. Hibernate does not create tables from Entity classes.
Fix: Set spring.jpa.hibernate.ddl-auto=update in application.properties for all services that have a database. This creates tables from Entity classes automatically.
FixBASH
# Add to any service with a database:
spring.jpa.hibernate.ddl-auto=update
# update = create if missing, alter if changed
# create-drop = recreate every restart (dev only, loses data)
CORS error: Access-Control-Allow-Origin header missing
Cause: A browser-based frontend is calling the Gateway API and the Gateway does not send CORS headers in the response.
Fix: Add global CORS configuration to api-gateway application.properties. This allows all origins in development.
FixBASH
# api-gateway application.properties:
spring.cloud.gateway.globalcors.corsConfigurations.[/**].allowedOrigins=*
spring.cloud.gateway.globalcors.corsConfigurations.[/**].allowedMethods=GET,POST,PUT,DELETE,OPTIONS
spring.cloud.gateway.globalcors.corsConfigurations.[/**].allowedHeaders=*
WhiteLabel Error — 404 when calling through Gateway
Cause: Route predicate does not match the URL. Either the URL path is wrong or the predicate pattern has a typo.
Fix: Check your URL starts with exactly the predicate path. /products/1 does NOT match Path=/api/products/**. Must be /api/products/1.
FixBASH
# Wrong:
GET http://localhost:8080/products/1

# Correct (matches Path=/api/products/**):
GET http://localhost:8080/api/products/1
java.net.ConnectException: Connection refused: localhost:3306
Cause: MySQL is not running, or datasource URL / username / password is wrong.
Fix: 1. Start MySQL service. 2. Open MySQL Workbench and confirm connection works. 3. Check datasource.url, username, password in application.properties match your MySQL install.
FixBASH
# Check these match your MySQL:
spring.datasource.url=jdbc:mysql://localhost:3306/product_db?createDatabaseIfNotExist=true
spring.datasource.username=root
spring.datasource.password=YOUR_PASSWORD_HERE
BeanCreationException: Error creating bean jwtUtil / No qualifying bean of type JwtUtil
Cause: JwtUtil class is missing @Component annotation. Spring cannot find it as a bean to inject.
Fix: Add @Component to JwtUtil.java in auth-service. Rebuild and restart.
FixBASH
@Component  // ADD THIS
public class JwtUtil {
    @Value("${jwt.secret}")
    private String secret;
    ...
}
Order total is wrong — always same fixed value, not real price
Cause: Feign is not calling product-service. OrderService uses a hardcoded placeholder. Causes: @EnableFeignClients missing, openfeign dependency missing, or @FeignClient name typo.
Fix: 1. Check @EnableFeignClients on OrderServiceApplication. 2. Check spring-cloud-starter-openfeign in pom.xml. 3. Check @FeignClient(name='product-service') matches spring.application.name in product-service exactly.
FixBASH
@FeignClient(name = "product-service")  // must match EXACTLY
public interface ProductClient {
    @GetMapping("/api/products/{id}")
    ProductResponseDTO getProductById(@PathVariable Long id);
}
Feign returns null fields — ProductResponseDTO fields are all null
Cause: Field names in ProductResponseDTO in order-service do not match the JSON field names that product-service returns. Jackson cannot deserialize mismatched field names.
Fix: Check that ProductResponseDTO in order-service has EXACTLY the same field names as the JSON product-service sends. Names are case-sensitive.
FixBASH
// If product-service sends: { "id": 1, "name": "Laptop", "price": 75000 }
// Then order-service ProductResponseDTO MUST have:
private Long id;      // matches "id"
private String name;  // matches "name"
private double price; // matches "price"
// NOT productPrice or Price -- these would be null
Service registers in Eureka but Gateway returns 503 Service Unavailable
Cause: Service registered but Gateway cache has not refreshed yet. Or the service registered but immediately went DOWN (startup failure after registration).
Fix: Wait 30-60 seconds for the Gateway's Eureka cache to refresh. Check the Eureka dashboard — service must show Status=UP (not DOWN or OUT_OF_SERVICE). If DOWN: check the service console for post-startup errors.
FixBASH
# Check Eureka dashboard at http://localhost:8761
# Service must show: Status = UP
# If DOWN: check IntelliJ console of that service
# If still UP but 503: wait 60 seconds and retry
@Value annotation not injecting jwt.secret — field is null
Cause: jwt.secret is defined in Config Server but the service is not fetching from Config Server. spring.config.import is missing, OR Config Server started after the service.
Fix: 1. Start Config Server FIRST. 2. Add spring.config.import=optional:configserver:http://localhost:8888 to service application.properties. 3. Test: GET http://localhost:8888/product-service/default should return jwt.secret in the response.
FixBASH
# product-service application.properties:
spring.application.name=product-service
spring.config.import=optional:configserver:http://localhost:8888

# config-repo/application.properties:
jwt.secret=mySecretKey404E635266556A586E3272357538782F413F4428

GLOSSARY

Glossary — Every Term You Will Hear

Keep this handy. These are the words used throughout microservices work.

TermPlain Meaning
MonolithOne single application containing all features in one project
MicroserviceOne small independent service owning a single area, with its own database
Service RegistryA directory where services register so others can find them — this is Eureka
EurekaNetflix's service registry — the phone book for all services
Service DiscoveryThe process of finding a service's current address by its name, not a fixed URL
API GatewayThe single entry point that routes every client request to the right service
RouteA rule in the Gateway: if URL matches this pattern, send it to that service
PredicateThe condition that triggers a route — usually a URL path pattern
lb://Load-balanced URI — tells the Gateway to find the service via Eureka
Feign ClientAn interface that calls another service; Spring generates the HTTP code
Inter-service callOne service calling another service over HTTP
JWTJSON Web Token — a signed token proving who the user is
Bearer tokenA token sent in the Authorization header as 'Bearer <token>'
BCryptA one-way hashing algorithm for safely storing passwords
Config ServerA service that holds all configuration centrally
Config ClientA service that fetches its config from the Config Server at startup
BOMBill of Materials — a pom.xml block that locks compatible library versions
HeartbeatA periodic 'I am alive' signal a service sends to Eureka every 30 seconds
WebFluxThe reactive web framework the Gateway uses (instead of Spring MVC)
NettyThe non-blocking web server the Gateway runs on (instead of Tomcat)
GlobalFilterA Gateway filter that runs on every request — used for the JWT check
ddl-autoJPA setting that auto-creates or updates database tables from entities
RITMA request item ID in IT service systems (unrelated to code — used in provisioning)
Tip: If you ever forget what lb:// or BOM means while reading the guide, come back to this glossary. Every term used in the document is listed here.
DOCKER (OPTIONAL)

Docker — Package and Deploy Everything (Do This Later)

Remember: Complete all 5 points with a fully working and tested system before starting Docker. Adding Docker to a broken system makes every error harder to debug.

Docker packages each service into a container — isolated, consistent on any machine. One docker-compose up command starts all 6 services.

Key: Most important Docker concept: inside a container, localhost means the container itself — NOT another container. All localhost references in application.properties must change to Docker service names. http://localhost:8761 becomes http://eureka-server:8761.
What to LearnWhat It DoesWhen to Learn
Dockerfile per serviceRecipe to build a container image from your JARAfter all 6 services work locally
docker-compose.ymlStarts all containers with one commandAfter Dockerfiles written
localhost → service-nameThe critical networking change inside DockerLearn this FIRST — biggest gotcha
spring-boot-maven-pluginNeeded to build a Docker imageWhen writing Dockerfiles
Key: Docker is a completely separate topic. Do not mix it with building the microservices system. Treat it as a new guide when all 5 points are working and tested.
