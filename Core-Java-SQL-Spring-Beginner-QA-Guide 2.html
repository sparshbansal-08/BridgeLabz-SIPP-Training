1. Java Fundamentals

Q1. What is Java and what are its main features?
Java is a popular, object-oriented programming language that runs on any device with a JVM ("write once, run anywhere"). Key features: platform-independent, object-oriented, automatic memory management (garbage collection), secure, multithreaded, and robust.
Q2. What is the difference between JDK, JRE, and JVM?
  • JVM (Java Virtual Machine): runs the bytecode.
  • JRE (Java Runtime Environment): JVM + libraries needed to run programs.
  • JDK (Java Development Kit): JRE + development tools like the compiler (javac).
Simple way to remember: JDK is to develop, JRE is to run, JVM actually executes.
Q3. Which file is generated after compiling a Java source file?
A .class file containing bytecode. For example, compiling Hello.java produces Hello.class.
Q4. How do you compile and run a Java file written in Notepad++?
Open a terminal in the folder and run:
Compile and run from the command linejavac Hello.java # creates Hello.class (bytecode) java Hello # runs the program (no .class extension)
Q5. What is a classloader, and which one loads your class?
A classloader loads .class files into the JVM. There are three main ones:
  • Bootstrap — loads core Java classes (java.lang.*).
  • Extension/Platform — loads extension libraries.
  • Application/System — loads your classes from the classpath.
Answer to "which loads my class": the Application (System) classloader.
Q6. What are stack, heap, and method area?
  • Stack: stores method calls and local variables; one per thread.
  • Heap: stores all objects; shared by all threads.
  • Method area: stores class information, static variables, and method code.
Q7. What is garbage collection?
The automatic process where the JVM frees the memory of objects that are no longer referenced, so you do not free memory manually like in C/C++.

2. OOP Concepts

Q1. What are the four pillars of OOP?
Encapsulation, Inheritance, Polymorphism, Abstraction.
Q2. What is encapsulation? (with example)
Hiding internal data by making fields private and exposing them through public getters/setters, so the object controls its own state.
Encapsulation examplepublic class Account { private double balance; // hidden public double getBalance() { // controlled read return balance; } public void deposit(double amt) { // controlled write if (amt > 0) balance += amt; } }
Real-world analogy: An ATM: you cannot touch the cash directly; you use buttons (methods) that control access.
Q3. What is abstraction? (with example)
Showing only the essential features and hiding the complex details. Achieved with abstract classes and interfaces.
Abstraction exampleabstract class Shape { abstract double area(); // what, not how } class Circle extends Shape { double r; double area() { return 3.14 * r * r; } // the how }
Real-world analogy: Driving a car: you use the steering and pedals (interface) without knowing the engine's internal workings.
Q4. Difference between abstraction and encapsulation?
  • Abstraction hides complexity (shows what an object does, hides how).
  • Encapsulation hides data (keeps fields private behind methods).
Q5. Difference between an abstract class and an interface?

FieldsAny fieldsOnly constants (public static final)
InheritanceExtend only oneImplement many

Q6. Can we create an object of an abstract class or interface?
No, not directly. But you can create an object of a subclass and refer to it using the parent/interface type.
Using a parent referenceShape s = new Circle(); // object is Circle, reference is Shape
Q7. Difference between method overloading and overriding?
  • Overloading: same method name, different parameters, in the same class (compile-time).
  • Overriding: a subclass redefines a parent method with the same signature (runtime).
Q8. Can we change the return type in method overriding?
It must be the same type or a subtype (called a covariant return type). You cannot change it to an unrelated type.
Q9. Difference between static binding and dynamic binding?
  • Static (early) binding: resolved at compile time, e.g. overloaded methods and static methods.
  • Dynamic (late) binding: resolved at runtime, e.g. overridden methods through a parent reference.
Q10. Why is multiple inheritance (with classes) not supported in Java?
To avoid the "diamond problem", where two parent classes provide the same method and the compiler cannot decide which to use. Java allows multiple inheritance only through interfaces, which avoids this confusion.

3. Strings & Immutability

Q1. Why are Strings immutable in Java?
Once created, a String cannot be changed. This gives:
  • Security: safe to use for file paths, URLs, and passwords as keys.
  • Caching: strings can be shared in the String constant pool.
  • Thread safety: immutable objects can be shared freely.
  • Reliable hashing: the hash never changes, so they work well as map keys.
Q2. Difference between StringBuilder and StringBuffer?
Both are mutable (changeable). StringBuilder is faster but not thread-safe. StringBuffer is thread-safe (synchronized) but slightly slower.
Q3. Difference between == and .equals()?
== compares references (same object in memory). .equals() compares the actual content/value.
== vs equalsString a = new String("hi"); String b = new String("hi"); System.out.println(a == b); // false (different objects) System.out.println(a.equals(b)); // true (same content)
Q4. What is the String constant pool, and how is it different from the heap?
The String constant pool is a special area inside the heap where string literals are stored and reused. String s = "hello"; goes to the pool; String s = new String("hello"); creates a new object in the normal heap.
Moving between them: the intern() method returns the pooled version of a string, e.g. s2.intern().
Q5. Difference between .equals() and .equalsIgnoreCase()?
.equals() is case-sensitive; .equalsIgnoreCase() ignores upper/lower case. So "Hello".equals("hello") is false but "Hello".equalsIgnoreCase("hello") is true.
Q6. Which class provides the .equals() method?
The Object class. String overrides it to compare characters instead of references.
Q7. Program: reverse the words of a sentence ("Hello World" → "World Hello").
Reverse word orderString input = "Hello World"; String[] words = input.split(" "); StringBuilder sb = new StringBuilder(); for (int i = words.length - 1; i >= 0; i--) { sb.append(words[i]); if (i > 0) sb.append(" "); } System.out.println(sb); // World Hello
Q8. Program: find duplicates in a String array.
Find duplicatesString[] s = {"hello", "ant", "boy", "hello", "cat"}; Set<String> seen = new HashSet<>(); for (String w : s) { if (!seen.add(w)) { // add returns false if already present System.out.println("Duplicate: " + w); // Duplicate: hello } }

4. Collections Framework

Q1. What is the Collections framework?
A set of ready-made classes and interfaces (List, Set, Map, Queue) for storing and managing groups of objects, with useful methods like add, remove, search, and sort.
Q2. Difference between List, Set, and Map?
  • List: ordered, allows duplicates (e.g. ArrayList).
  • Set: no duplicates (e.g. HashSet).
  • Map: key-value pairs with unique keys (e.g. HashMap).
Q3. Difference between ArrayList and LinkedList?
ArrayList uses a dynamic array; fast for get-by-index, slow for inserts/removes in the middle. LinkedList uses nodes; fast for inserts/removes, slow for random access.
When to use: use ArrayList for mostly reading by index; use LinkedList for frequent inserts/deletes.
Q4. Difference between ArrayList and Vector?
Both are growable arrays. Vector is synchronized (thread-safe) but slower; ArrayList is not synchronized and faster. Vector is mostly legacy.
Q5. Difference between HashSet and HashMap?
HashSet stores unique values; HashMap stores key-value pairs. Internally, HashSet is backed by a HashMap.
Q6. Difference between HashMap and Hashtable?
HashMap is not synchronized (faster) and allows one null key. Hashtable is synchronized (thread-safe) and allows no null key or value.
Q7. How does a HashMap store data internally?
It stores entries in "buckets" based on the key's hashCode(). On lookup, it finds the bucket by hash, then uses equals() to match the exact key. Collisions are handled with linked lists (and trees for large buckets).
Q8. Null keys/values: what is allowed?
CollectionNull keyNull value
HashMapOne allowedMany allowed
TreeMapNot allowed (needs sorting)Allowed
TreeSetNot allowed (needs sorting)—
Q9. Why are Maps not part of the Collection interface?
Because a Collection holds single elements, while a Map holds pairs (key and value). The structure is different, so Map is a separate hierarchy.
Q10. Difference between fail-fast and fail-safe iterators?
Fail-fast throws ConcurrentModificationException if the collection changes during iteration (e.g. ArrayList). Fail-safe works on a copy and does not throw (e.g. CopyOnWriteArrayList).
Q11. Difference between Comparable and Comparator?
Comparable defines the natural order inside the class via compareTo(). Comparator defines an external, custom order via compare(), useful for multiple sort orders.

5. Exception Handling

Q1. What is exception handling?
A way to handle runtime errors gracefully using try, catch, finally, throw, and throws, so the program does not crash.
Q2. What is the exception hierarchy?
Throwable is the root. It splits into Error (serious problems like OutOfMemoryError) and Exception. Exception splits into checked exceptions and unchecked (RuntimeException).
Q3. Difference between checked and unchecked exceptions?
  • Checked: checked at compile time, must be handled or declared (e.g. IOException).
  • Unchecked: extend RuntimeException, occur at runtime (e.g. NullPointerException).
Q4. Difference between throw and throws?
throw actually throws an exception object; throws declares in the method signature that the method may throw an exception.
Q5. Difference between final, finally, and finalize?
  • final: a keyword for constants, non-overridable methods, or non-extendable classes.
  • finally: a block that always runs after try/catch (used for cleanup).
  • finalize: an old method called before garbage collection (now deprecated).
Q6. Does the finally block always run?
Yes, whether or not an exception occurs — except in rare cases like System.exit() or JVM crash.
Q7. Can we have try-finally without catch? Multiple catch blocks? Try inside finally?
Yes to all:
  • try-finally without catch: allowed (the exception propagates, but cleanup runs).
  • Multiple catch blocks: allowed, ordered from specific to general.
  • try-catch inside catch or finally: allowed (nested try blocks are valid).
Q8. How do you create a custom exception?
Extend Exception (checked) or RuntimeException (unchecked).
Custom exceptionpublic class InvalidAgeException extends RuntimeException { public InvalidAgeException(String message) { super(message); } } // usage: if (age < 18) throw new InvalidAgeException("Age must be 18+");
Why useful: custom exceptions give clear, meaningful error names for your business rules.
Q9. What is try-with-resources?
A try block that automatically closes resources (like files or DB connections) when done, so you do not need a finally block to close them.
try-with-resourcestry (BufferedReader br = new BufferedReader(new FileReader("a.txt"))) { System.out.println(br.readLine()); } // br is closed automatically here
Q10. Program using ArithmeticException.
Handle divide-by-zerotry { int result = 10 / 0; // throws ArithmeticException } catch (ArithmeticException e) { System.out.println("Cannot divide by zero"); }

6. Threads & Multithreading

Q1. What is a thread and what is multithreading?
A thread is a lightweight unit of execution. Multithreading means running several threads at once to do more work in parallel and use the CPU efficiently.
Q2. How do you create a thread in Java?
Two ways:
  • Extend Thread and override run().
  • Implement Runnable and pass it to a Thread (preferred, because your class can still extend another class).
Runnable exampleRunnable task = () -> System.out.println("Running"); new Thread(task).start();
Q3. What is the thread lifecycle?
New → Runnable → Running → Waiting/Blocked → Terminated. A thread is created, becomes ready, runs, may wait, and finally finishes.
Q4. What is the Runnable interface?
A functional interface with a single run() method that holds the code a thread will execute.
Q5. What is synchronization?
It allows only one thread at a time to run a block or method, preventing data corruption when threads share a resource. Use the synchronized keyword.
Q6. What do wait(), notify(), and notifyAll() do?
They coordinate threads. wait() makes a thread pause and release the lock; notify() wakes one waiting thread; notifyAll() wakes all of them. They are called inside synchronized blocks.
Q7. What is the volatile keyword?
It marks a variable so every thread reads its latest value from main memory (not a cached copy). It ensures visibility of changes across threads.
Q8. Difference between transient and volatile?
transient tells serialization to skip a field; volatile ensures a variable's value is always read fresh across threads. They solve completely different problems.

7. Java 8 Features

Q1. What are the main Java 8 features?
Lambda expressions, Functional interfaces, Stream API, Optional, the new Date/Time API, and default/static methods in interfaces.
Q2. What is a lambda expression?
A short way to write a function (an implementation of a functional interface) without a full class or method.
Lambda exampleList<String> names = List.of("raj", "amit"); names.forEach(n -> System.out.println(n)); // prints each name
Q3. What is a functional interface?
An interface with exactly one abstract method, which a lambda can implement. Examples: Runnable, Comparator, Predicate, Function, Supplier, Consumer.
Q4. What is the Stream API?
A way to process collections in a clean, pipeline style (filter, map, reduce) without writing manual loops.
Stream exampleList<Integer> nums = List.of(1, 2, 3, 4); int sumEven = nums.stream() .filter(n -> n % 2 == 0) .mapToInt(Integer::intValue) .sum(); System.out.println(sumEven); // 6
Q5. What is Optional and why use it?
A container that may or may not hold a value, used to avoid NullPointerException by forcing you to handle the "no value" case clearly.
Optional exampleOptional<String> name = Optional.ofNullable(getName()); System.out.println(name.orElse("Guest")); // default if null

8. JDBC, JPA & Hibernate

Q1. What is JDBC?
JDBC (Java Database Connectivity) is the lowest-level way to talk to a database in Java. You write SQL yourself and manage connections, statements, and results.
Q2. Difference between Statement and PreparedStatement?
Statement runs plain SQL and is open to SQL injection. PreparedStatement uses parameters (?), is precompiled, faster for repeated use, and safer.
Q3. What is JPA and what is Hibernate?
JPA is a specification (standard) for mapping Java objects to database tables. Hibernate is the most popular implementation of JPA that actually does the work and generates the SQL.
Q4. What is Spring Data JPA?
A Spring layer on top of JPA/Hibernate. You define a repository interface and Spring generates the implementation, including ready methods like save and findAll.
Q5. What is an Entity and a POJO?
A POJO (Plain Old Java Object) is a simple class with fields, a constructor, and getters/setters. An Entity is a POJO marked with @Entity so JPA maps it to a database table.
Q6. Write a One-to-Many mapping.
Department has many Employees@Entity public class Department { @Id @GeneratedValue(strategy = GenerationType.IDENTITY) private int id; @OneToMany(mappedBy = "department") private List<Employee> employees; } @Entity public class Employee { @Id @GeneratedValue(strategy = GenerationType.IDENTITY) private int id; @ManyToOne @JoinColumn(name = "department_id") private Department department; }
Q7. What is the difference between transient keyword and @Transient annotation?
@Transient (JPA) means "do not save this field to the database". The Java transient keyword means "do not include this field during serialization". Different purposes.

Q1. What are the types of SQL commands?

Q2. Difference between a primary key and a foreign key?
  • Primary key: uniquely identifies each row in a table; cannot be null or duplicate.
  • Foreign key: a column that points to the primary key of another table, creating a relationship.
Example: In an Orders table, customer_id is a foreign key pointing to the id primary key in the Customers table.
Q3. Difference between unique key and primary key?
Both enforce uniqueness. A table has one primary key (not null). It can have many unique keys, and a unique key may allow one null.
Q4. What are SQL joins?
Joins combine rows from two or more tables based on a related column.
JoinReturns
INNER JOINOnly matching rows in both tables.
LEFT JOINAll rows from the left table + matches from the right.
RIGHT JOINAll rows from the right table + matches from the left.
FULL OUTER JOINAll rows from both tables, matched where possible.
Q5. Difference between a join and a union?
A join combines columns from tables side by side (horizontally). A union stacks rows from two queries on top of each other (vertically); both queries must have the same columns.
Q6. Difference between DELETE, DROP, and TRUNCATE?

Q7. Difference between WHERE and HAVING?
WHERE filters rows before grouping; HAVING filters groups after GROUP BY (often with aggregate functions like COUNT).
Q8. What are GROUP BY and ORDER BY?
GROUP BY groups rows that share a value so you can use aggregates (SUM, COUNT). ORDER BY sorts the result rows ascending or descending.
Q9. Sample queries: insert and delete.
Insert and deleteINSERT INTO students (id, name) VALUES (1, 'Raj'); DELETE FROM students WHERE id = 1;
Q10. What are ACID properties?
Atomicity (all or nothing), Consistency (valid state), Isolation (transactions do not interfere), Durability (committed data is saved permanently).
Q11. What is an index and why use it?
An index is a data structure that speeds up searching on a column, like a book's index. It makes reads faster but slightly slows down inserts/updates.

10. Spring & Spring Boot

Q1. What is Spring and why use it?
Spring is a Java framework that manages object creation and wiring through IoC/DI, reducing tight coupling and boilerplate, with modules for web, data, and security.
Q2. What are IoC and Dependency Injection?
IoC (Inversion of Control): the framework, not your code, creates and connects objects. DI (Dependency Injection): the way IoC is achieved — Spring supplies the objects a class needs.
Types of DI: constructor injection (preferred), setter injection, field injection.
Q3. What is Spring Boot and how is it different from Spring?
Spring Boot is built on Spring. It removes most manual configuration using auto-configuration, starters, and an embedded server. Spring Boot = Spring + auto-config + embedded server.
Q4. What are the stereotype annotations?
@Component (generic bean), @Service (business logic), @Repository (data access, adds DB exception translation), @Controller (web views), @RestController (REST/JSON).
Q5. Difference between @Component and @Bean?
@Component is put on your own class so Spring auto-detects it. @Bean is used inside a @Configuration class to register an object (often a third-party class you cannot annotate).
Q6. What do @Configuration, @Qualifier, @Primary, and @ComponentScan do?
  • @Configuration: marks a class that defines beans.
  • @Qualifier: picks a specific bean when several match.
  • @Primary: marks a default bean when several match.
  • @ComponentScan: tells Spring which packages to scan for components.
Q7. Difference between @Controller and @RestController?
@Controller returns a view name (HTML page). @RestController = @Controller + @ResponseBody, returning data (JSON) directly. Yes, you can use REST APIs in Spring Boot with @RestController.
Q8. Difference between @GetMapping, @PostMapping, @PutMapping, and @PatchMapping?
  • @GetMapping: read data (HTTP GET).
  • @PostMapping: create new data (HTTP POST).
  • @PutMapping: replace an entire resource (HTTP PUT).
  • @PatchMapping: update part of a resource (HTTP PATCH).
Q9. What are Spring bean scopes?
singleton (default, one shared instance), prototype (new each time), and web scopes request, session, application.
Q10. What is the bean lifecycle?
Spring creates the bean, injects dependencies, runs init callbacks (@PostConstruct), the bean is used, then destroy callbacks (@PreDestroy) run at shutdown.
Q11. How do you do global exception handling in Spring Boot?
Create a class annotated with @RestControllerAdvice and add @ExceptionHandler methods to handle exceptions across all controllers in one place.
Q12. How do you connect a database in Spring Boot?
Add the database driver and spring-boot-starter-data-jpa, then set the connection in application.properties (URL, username, password). Spring Boot auto-configures the connection.
Q13. What happens when a Spring Boot application starts?
main() calls SpringApplication.run(), which creates the application context, runs auto-configuration, scans components, creates beans, starts the embedded server, and the app is ready to handle requests.
Q14. What is the default embedded server and how do you change the port?
The default is Tomcat. Change the port with server.port=8088 in application.properties. The port number tells the browser which "door" of the server to connect to, e.g. http://localhost:8088.

11. HTML, CSS & JavaScript Basics

Q1. What is the difference between HTML, CSS, and JavaScript?
  • HTML = structure/content of a page (the skeleton).
  • CSS = styling and layout (colors, fonts, spacing).
  • JavaScript = behavior and interactivity (clicks, validation, dynamic updates).
Analogy: HTML is the building, CSS is the paint and decoration, JavaScript is the electricity that makes things work.

A tag that has no closing tag and no content, because it cannot contain anything. Examples: <br>, <hr>, <img>, <input>.
Q4. Difference between ordered and unordered lists?
<ol> shows numbered items (1, 2, 3) for steps in order; <ul> shows bullet points where order does not matter.

A popular CSS framework with ready-made styles and components (buttons, grids, forms) so you can build responsive, good-looking pages quickly without writing all the CSS yourself.

13. Agile, SOLID & Software Concepts

Q1. What is Agile methodology?
A way of building software in small, repeating cycles called sprints (often 2 weeks). The team delivers a working piece each cycle, gets feedback, and improves — instead of building everything at once.
Q2. What are common Agile terms?
TermMeaning
SprintA short, fixed period of work (e.g. 2 weeks).
User StoryA small feature described from the user's point of view.
BacklogThe prioritized list of work to be done.
Stand-upA short daily meeting about progress and blockers.
Scrum MasterThe person who helps the team follow Agile and removes blockers.
RetrospectiveA meeting to discuss what went well and what to improve.
Q3. What are the SOLID principles?
Five rules for clean, maintainable object-oriented code:
LetterPrincipleSimple meaning
SSingle ResponsibilityA class should do one job only.
OOpen/ClosedOpen to extend, closed to modify.
LLiskov SubstitutionA subclass should work wherever its parent is used.
IInterface SegregationMany small interfaces are better than one big one.
DDependency InversionDepend on abstractions, not concrete classes.
Q4. What is the difference between tight coupling and loose coupling?
Tight coupling: classes depend heavily on each other, so a change in one breaks the other. Loose coupling: classes depend on interfaces, so they can change independently. Spring's dependency injection helps achieve loose coupling.
Q5. Difference between a method and a function?
A function is a block of reusable code. A method is a function that belongs to a class/object. In Java everything is inside classes, so we usually say "method".

14. More Core Java (Tricky & Common)

Q1. What are the primitive data types in Java?
Eight: byte, short, int, long, float, double, char, boolean. Everything else (like String, arrays, objects) is a non-primitive (reference) type.
Q2. What is the static keyword?
It makes a field or method belong to the class itself, not to each object. You can use it without creating an object, e.g. Math.max(...).
Q3. Difference between static and non-static (instance) members?
Static members are shared by all objects and accessed via the class name. Non-static members belong to each object separately and need an object to access.
Q4. Difference between this and super?
this refers to the current object; super refers to the parent class (its constructor, methods, or fields).
Q5. What is the final keyword (with a class, method, variable)?
  • final variable: its value cannot change (a constant).
  • final method: cannot be overridden by a subclass.
  • final class: cannot be extended (e.g. String).
Q6. Can we extend the String class or the Exception class?
You cannot extend String because it is final. You can extend Exception to create your own custom exceptions.
Q7. What are the predefined methods in the Object class?
Common ones: equals(), hashCode(), toString(), getClass(), clone(), wait(), notify(), notifyAll(), and finalize().
Q8. What is a marker interface? Name a few.
An interface with no methods that simply "marks" a class to give it a capability. Examples: Serializable, Cloneable, and (legacy) RandomAccess.
Q9. What is serialization?
Converting an object into a stream of bytes so it can be saved to a file or sent over a network, and later restored (deserialization). The class must implement Serializable.
Q10. What is a generic type?
Generics let you write classes and methods that work with a type you specify later, giving type safety. List<String> means a list that only holds Strings, caught at compile time.
Q11. What is autoboxing and unboxing?
Autoboxing converts a primitive to its wrapper automatically (int → Integer). Unboxing is the reverse (Integer → int).
Q12. What is an immutable object and how do you create one?
An object whose state cannot change after creation. To make one: mark the class final, make fields private final, set them only in the constructor, and provide no setters.
Q13. Program: add the digits 1 to 9 (or a list of numbers) using Java.
Sum numbers in a loopint sum = 0; for (int i = 1; i <= 9; i++) { sum += i; } System.out.println(sum); // 45
Q14. Program: check if a number is prime.
Prime checkint n = 29; boolean prime = n > 1; for (int i = 2; i <= Math.sqrt(n); i++) { if (n % i == 0) { prime = false; break; } } System.out.println(prime ? "Prime" : "Not prime");
Q15. What does a++ + ++a evaluate to (with a = 2)?
Yes, it is valid in a print statement. Step by step with a = 2: a++ uses 2 (then a becomes 3), ++a makes a 4 and uses 4. So the result is 2 + 4 = 6.
Q16. Can A a = new D(); work if D is a subclass several levels below A?
Yes. A parent reference can point to any subclass object. Calling a.m1() works if m1() is defined in A (or inherited), and the actual D version runs at runtime (dynamic binding).
Q17. Have you seen StackOverflowError? How do you increase heap memory?
StackOverflowError usually comes from infinite recursion (a method calling itself with no end). To increase heap memory, use JVM flags like -Xms (initial) and -Xmx (maximum), e.g. java -Xmx512m MyApp.

15. JUnit, Mockito & Testing

Q1. What is JUnit?
A popular Java framework for writing and running unit tests — small tests that check one method or class behaves correctly.
Q2. What is the difference between unit testing and integration testing?
Unit testing checks one small part in isolation (one method/class). Integration testing checks that several parts work correctly together (e.g. controller + service + database).
Q3. Which JUnit method checks if two values are equal?
assertEquals(expected, actual). For Strings, it compares content. Other common ones: assertTrue, assertFalse, assertNull, assertNotNull.
A simple JUnit test@Test void testAdd() { assertEquals(5, calculator.add(2, 3)); }
Q4. What is Mockito and why is it used?
Mockito creates mock (fake) objects so you can test one class without needing its real dependencies (like a database). You tell the mock what to return, then test your class in isolation.
Example: Mock a repository to return a fixed user, so you can test the service without a real database.
Q5. What are common JUnit annotations?
@Test (marks a test method), @BeforeEach (runs before each test), @AfterEach (runs after each test), @BeforeAll/@AfterAll (run once for the whole class), and @Disabled (skip a test).

16. More Spring Boot & Microservices

Q1. Why do we need Spring Boot instead of plain Spring/Java?
It removes most manual setup: auto-configuration, starter dependencies, and a built-in (embedded) server. You can run a web app with a single main() method and almost no XML configuration.
Q2. What is @SpringBootApplication?
A single annotation that combines three: @Configuration, @EnableAutoConfiguration, and @ComponentScan. It marks the main class and starts the whole auto-configuration process.
Q3. What is @Autowired and what can we use instead?
@Autowired tells Spring to inject a dependency automatically. Instead of field injection, you can use constructor injection (preferred), which also works without writing @Autowired on a single constructor.
Q4. Difference between @Qualifier and @Primary?
When several beans of the same type exist: @Primary sets a default one; @Qualifier("name") picks a specific one by name at the injection point.
Q5. How do you validate incoming requests in Spring Boot?
Add validation annotations (@NotNull, @Size, @Email) on the request object and put @Valid before the parameter in the controller. Spring checks the rules and reports errors automatically.
Q6. What is @Transactional?
It wraps a method in a database transaction: if everything succeeds it commits; if an exception occurs it rolls back, keeping the data consistent (all-or-nothing).
Q7. What are microservices? (simple meaning)
An approach where a big application is split into many small, independent services, each doing one job (like login, payment, email). They run separately and talk to each other through APIs.
Analogy: Like departments in a school — teaching, accounts, canteen — each works independently but together they run the school.
Q8. How do microservices communicate?
Usually through REST APIs over HTTP (one service calls another's URL), or through a message queue (like RabbitMQ/Kafka) for asynchronous messages.
Q9. What happens when one microservice goes down?
Other services should keep working. Patterns like timeouts, retries, and a circuit breaker stop the failure from spreading, and a fallback response can be returned instead.
Q10. Difference between authentication and authorization?
Authentication = "Who are you?" (verifying identity, e.g. login). Authorization = "What are you allowed to do?" (checking permissions/roles).
Q11. Difference between HTTP 401 and 403?
401 Unauthorized: you are not logged in / identity not verified. 403 Forbidden: you are logged in but not allowed to access this resource.
Q12. What is a GlobalExceptionHandler in Spring Boot?
A class annotated with @RestControllerAdvice that catches exceptions from all controllers in one place using @ExceptionHandler methods, so you return clean, consistent error responses.

17. More SQL (Normalization, Views, Triggers)

Q1. What is normalization?
Organizing tables to reduce duplicate data and keep it consistent. You split big tables into smaller related ones and link them with keys. Common forms: 1NF, 2NF, 3NF.
Q2. Difference between CHAR and VARCHAR?
CHAR(n) is fixed length (always uses n characters, padded with spaces). VARCHAR(n) is variable length (uses only what is needed, up to n). Use VARCHAR for most text.
Q3. Difference between WHERE and HAVING (again, simply)?
WHERE filters individual rows before grouping. HAVING filters groups after GROUP BY, usually with aggregates like COUNT or SUM.
Q4. What are aggregate functions?
Functions that compute a single value from many rows: COUNT, SUM, AVG, MIN, MAX. Often used with GROUP BY.
Q5. What is a view?
A saved query that behaves like a virtual table. It does not store data itself but shows data from one or more tables, useful for simplifying complex queries and limiting access.
Q6. What is a subquery?
A query inside another query. The inner query runs first and its result is used by the outer query.
Subquery exampleSELECT name FROM students WHERE marks > (SELECT AVG(marks) FROM students);
Q7. What is a trigger?
A piece of SQL that runs automatically when an event happens on a table (INSERT, UPDATE, or DELETE). For example, automatically writing to an audit log whenever a row is updated.
Q8. Difference between INNER JOIN and OUTER JOIN?
INNER JOIN returns only matching rows from both tables. OUTER JOIN (LEFT/RIGHT/FULL) also returns non-matching rows, filling missing sides with NULL.
Q9. Difference between IN and EXISTS?
IN checks if a value is in a list/subquery result. EXISTS checks if a subquery returns any row at all. EXISTS is often faster for large subqueries.
Q10. What are COMMIT, ROLLBACK, and SAVEPOINT?
COMMIT saves all changes permanently. ROLLBACK undoes changes since the last commit. SAVEPOINT sets a marker you can roll back to partially.

18. Scenario-Based Questions (Beginner)

Q1. Scenario: your program crashes with NullPointerException. How do you find and fix it?
Read the stack trace to find the exact line, check which variable is null there, and make sure it is initialized before use. Using Optional or null checks helps prevent it.
Q2. Scenario: you need a list where you frequently add/remove items in the middle. Which collection?
LinkedList, because inserts and deletes in the middle are faster than in an ArrayList (which must shift elements).
Q3. Scenario: you must store unique usernames and check membership quickly. Which collection?
HashSet, because it stores only unique values and offers fast (near O(1)) lookups.
Q4. Scenario: you need to look up an employee by their ID very fast. Which collection?
HashMap with the ID as the key and the employee as the value, giving fast lookups by key.
Q5. Scenario: two threads update the same counter and the total is wrong. Why and how to fix?
It is a race condition — both threads change the value at the same time. Fix it with synchronized, an AtomicInteger, or a lock so only one thread updates at a time.
Q6. Scenario: a user submits a form with an empty required field. How do you stop bad data?
Validate the input. On the server, use Bean Validation (@NotNull, @NotBlank) with @Valid in the controller; show a clear error message back to the user.
Q7. Scenario: your Spring Boot app cannot connect to MySQL on startup. What do you check?
Check the database URL, username, and password in application.properties; confirm MySQL is running; confirm the database exists; and make sure the MySQL driver dependency is present.
Q8. Scenario: your REST API must create a new record. Which HTTP method and annotation?
Use POST with @PostMapping. Use GET to read, PUT to replace, PATCH to partially update, and DELETE to remove.
Q9. Scenario: you want the same error response format for all controllers. How?
Create a global handler with @RestControllerAdvice and @ExceptionHandler methods, returning a consistent error object for every controller.
Q10. Scenario: a query is slow on a large table searched by email. What helps?
Add an index on the email column. It makes searches much faster (at a small cost to insert/update speed).
Q11. Scenario: you must update two tables together, and either both succeed or neither. How?
Wrap the operation in a transaction using @Transactional, so if the second update fails, the first is rolled back automatically.
Q12. Scenario: you need different database settings for your laptop and the server. How?
Use Spring profiles: put values in application-dev.properties and application-prod.properties, and switch with spring.profiles.active.
