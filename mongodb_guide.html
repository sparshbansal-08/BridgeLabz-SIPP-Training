1. Core Concepts: MySQL vs MongoDB

MongoDB is a popular NoSQL database. Unlike traditional SQL databases (like MySQL) that store data in rigid tables with rows and columns, MongoDB stores data in flexible, JSON-like documents.

Key Terminology

SQL Term MongoDB Term Description
Database Database A top-level container for collections.
Table Collection A group of MongoDB documents. The equivalent of a table, but it does not enforce a schema.
Row / Record Document A single record, stored in BSON (Binary JSON) format. Documents are composed of field-value pairs.
Column Field A key-value pair within a document. The equivalent of a column.
Primary Key _id field Every document gets a unique _id automatically. It is like an auto-increment primary key, but it is a special value called an ObjectId.
JOIN $lookup / embedding Instead of joining tables, MongoDB often stores related data inside the same document (embedding), or uses $lookup when needed.

To picture the difference, here is the same data shown as a MySQL table row and as a MongoDB document.

MySQL — A row in a table

-- Fixed columns, every row is identical in shape
+------+--------------+-------------+--------+
| id   | name         | department  | salary |
+------+--------------+-------------+--------+
| 101  | Alice Johnson| Engineering | 80000  |
+------+--------------+-------------+--------+

MongoDB — A document in a collection

{
  "_id": ObjectId("64f1a2..."),
  "employee_id": 101,
  "name": "Alice Johnson",
  "department": "Engineering",
  "salary": 80000
}

No Schema Enforcement: A key feature of MongoDB is its flexibility. Documents within the same collection do not need to have the same structure or fields. In MySQL, every row must follow the table's fixed columns; in MongoDB, one document can have a skills field while another does not.

2. Setup and Installation

Setting up MongoDB involves installing the MongoDB Server and the MongoDB Shell. (If you only want the visual tool, you can skip ahead to the Compass section.)

  1. Download MongoDB Community Server: Go to the official MongoDB download page and select the version for your operating system.
  2. Install the Server: Follow the installation instructions for your OS. The installer will set up the MongoDB server, which is the background process that manages your data. On Windows, you can let it install as a "Service" so it starts automatically.
  3. Install MongoDB Shell (mongosh): This is the command-line tool you will use to interact with your database. Download it from the MongoDB Shell download page and follow its installation guide.
  4. (Optional) Install MongoDB Compass: This is the official graphical interface (GUI). It is the MongoDB equivalent of MySQL Workbench or phpMyAdmin. Download it from the Compass download page.

3. Connecting to MongoDB

Once installed, you can connect to your local running server.

MySQL — Connect

mysql -u root -p

MongoDB — Connect

mongosh

In MySQL you log in with a username and password. With a default local MongoDB, you simply run mongosh and it connects to mongodb://localhost:27017. You will then see a prompt, ready to accept commands.

4. Creating & Using a Database

This is the first big difference. In MySQL you must explicitly CREATE DATABASE before you can use it. In MongoDB, the database is created lazily — it does not actually exist until you put data into it, but you still "select" it with use.

MySQL — Create then select

CREATE DATABASE companyData;
USE companyData;

MongoDB — Just "use" it

use companyData
Step by step — what use companyData does:
  1. If a database named companyData already exists, MongoDB switches to it.
  2. If it does not exist, MongoDB prepares it in memory and switches to it, replying switched to db companyData.
  3. The database is only saved permanently once you insert your first document (next sections).

Checking the Current Database

To see which database you are currently using (like MySQL's SELECT DATABASE();):

MySQL

SELECT DATABASE();

MongoDB

db

Listing All Databases

MySQL

SHOW DATABASES;

MongoDB

show dbs

Your new database (e.g., companyData) will not appear in the show dbs list until you have inserted at least one document into a collection within it. This surprises many people coming from MySQL.

Dropping a Database

MySQL

DROP DATABASE companyData;

MongoDB

use companyData
db.dropDatabase()

Warning: This permanently deletes the entire database, including all its collections and documents. In MongoDB you must first use the database, because dropDatabase() always acts on the current database.

5. Tables vs Collections, Rows vs Documents

In MySQL, before inserting rows you must CREATE TABLE with a fixed list of columns and their types. In MongoDB, you normally do not create the collection in advance — it is created automatically the moment you insert your first document.

MySQL — Define columns first

CREATE TABLE employees (
  id INT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(100),
  department VARCHAR(50),
  salary INT
);

MongoDB — No definition needed

// Nothing to do here.
// The "employees" collection is
// created automatically on first insert.

If you ever want to create an empty collection on purpose (rare), you can:

db.createCollection("employees")

Listing Tables vs Listing Collections

MySQL

SHOW TABLES;

MongoDB

show collections

6. INSERT: Add One Row / Many Rows

"Create" in CRUD. In MongoDB you do not list columns — you just provide a JSON-like object. Any field is allowed.

Insert a Single Row / Document

MySQL — INSERT one row

INSERT INTO employees
  (name, department, salary)
VALUES
  ('Alice Johnson', 'Engineering', 80000);

MongoDB — insertOne()

db.employees.insertOne({
  employee_id: "E101",
  name: "Alice Johnson",
  department: "Engineering",
  salary: 80000,
  hire_date: new Date("2022-08-15")
})
Reading the MongoDB command piece by piece:
  • db = the current database (companyData).
  • .employees = the collection (table). Created now if it does not exist.
  • .insertOne({...}) = the method that adds exactly one document.
  • Inside the { } are the fields (columns) and their values.

MongoDB returns a response confirming the insert and shows the unique _id it generated (the automatic primary key):

{
  acknowledged: true,
  insertedId: ObjectId("64f1a2b9e13a4c0012ab34cd")
}

Insert Multiple Rows / Documents

MySQL — INSERT many rows

INSERT INTO employees
  (name, department, salary)
VALUES
  ('Bob Smith', 'Marketing', 65000),
  ('Charlie Brown', 'Engineering', 95000);

MongoDB — insertMany()

db.employees.insertMany([
  {
    employee_id: "E102",
    name: "Bob Smith",
    department: "Marketing",
    salary: 65000,
    skills: ["SEO", "Content Creation"]
  },
  {
    employee_id: "E103",
    name: "Charlie Brown",
    department: "Engineering",
    salary: 95000,
    manager_id: "E101"
  }
])

Notice that the MongoDB documents are not identical: Bob has a skills array and Charlie has a manager_id. MySQL cannot do this — every row must share the exact same columns. insertMany takes an array [ ... ] of documents separated by commas.

7. SELECT: Read One / Many with Conditions

"Read" in CRUD. MySQL uses SELECT; MongoDB uses find() (for many) and findOne() (for one).

Select All Rows / Documents

MySQL

SELECT * FROM employees;

MongoDB

db.employees.find({})

The empty {} means "no filter / match everything", exactly like having no WHERE clause in MySQL. In mongosh the output is already formatted nicely.

Select With a Condition (WHERE)

MySQL

SELECT * FROM employees
WHERE department = 'Engineering';

MongoDB

db.employees.find({ department: "Engineering" })

In MongoDB, the WHERE clause becomes the object you pass inside find(). { department: "Engineering" } means "where department equals Engineering".

Select Specific Columns (Projection)

MySQL — choose columns

SELECT name, salary
FROM employees;

MongoDB — projection

db.employees.find(
  {},
  { name: 1, salary: 1, _id: 0 }
)

The second object is the projection. 1 means "include this field", 0 means "hide it". Here we hide the _id which is shown by default.

Select One Row Only

MySQL

SELECT * FROM employees
WHERE name = 'Alice Johnson'
LIMIT 1;

MongoDB

db.employees.findOne({
  employee_id: "E101"
})

findOne() returns just the first matching document as a single object (not a list), similar to LIMIT 1.

Sorting and Limiting

MySQL

SELECT * FROM employees
ORDER BY salary DESC
LIMIT 5;

MongoDB

db.employees.find()
  .sort({ salary: -1 })
  .limit(5)

In sort(), -1 means descending (DESC) and 1 means ascending (ASC).

Counting Rows

MySQL

SELECT COUNT(*)
FROM employees
WHERE department = 'Engineering';

MongoDB

db.employees.countDocuments({
  department: "Engineering"
})

8. WHERE Conditions & Operators

This table maps the MySQL conditions you already know to their MongoDB operators. In MongoDB, operators start with a $ and go inside the value object.

Meaning MySQL MongoDB
Equals salary = 80000 { salary: 80000 }
Not equal salary <> 80000 { salary: { $ne: 80000 } }
Greater than salary > 70000 { salary: { $gt: 70000 } }
Greater or equal salary >= 70000 { salary: { $gte: 70000 } }
Less than salary < 70000 { salary: { $lt: 70000 } }
Less or equal salary <= 70000 { salary: { $lte: 70000 } }
AND dept='Engineering' AND salary>80000 { department: "Engineering", salary: { $gt: 80000 } }
OR dept='HR' OR dept='Marketing' { $or: [ { department: "HR" }, { department: "Marketing" } ] }
IN list department IN ('HR','IT') { department: { $in: ["HR", "IT"] } }
BETWEEN salary BETWEEN 60000 AND 90000 { salary: { $gte: 60000, $lte: 90000 } }
LIKE (contains) name LIKE '%John%' { name: /John/ }
IS NULL / missing manager_id IS NULL { manager_id: { $exists: false } }

Example combining conditions — Engineering employees earning more than 80,000:

MySQL

SELECT * FROM employees
WHERE department = 'Engineering'
  AND salary > 80000;

MongoDB

db.employees.find({
  department: "Engineering",
  salary: { $gt: 80000 }
})

9. UPDATE: Modify One / Many Rows

"Update" in CRUD. MongoDB needs two parts: a filter (which documents — like WHERE) and an update operator such as $set (what to change).

Update a Single Row / Document

MySQL

UPDATE employees
SET salary = 82000
WHERE name = 'Alice Johnson';

MongoDB — updateOne()

db.employees.updateOne(
  { employee_id: "E101" },
  { $set: { salary: 82000 } }
)

The $set operator updates the value of a field. If the field does not exist yet, $set will add it to that document. This is like adding a value without needing ALTER TABLE.

Update Multiple Rows / Documents

MySQL

UPDATE employees
SET salary = salary * 1.05
WHERE department = 'Marketing';

MongoDB — updateMany()

db.employees.updateMany(
  { department: "Marketing" },
  { $mul: { salary: 1.05 } }
)

Here $mul multiplies the field. Other handy update operators: $inc (add a number), $unset (remove a field, like dropping a value), and $rename (rename a field).

Useful Update Operators

MongoDB OperatorWhat it doesMySQL equivalent idea
$setSet/replace a field valueSET col = value
$incIncrease a number by NSET col = col + N
$mulMultiply a numberSET col = col * N
$unsetRemove a field from the document(no direct row-level equal)
$renameRename a fieldALTER TABLE ... CHANGE

10. DELETE: Remove One / Many Rows

"Delete" in CRUD. MySQL uses DELETE; MongoDB uses deleteOne() and deleteMany().

Delete a Single Row / Document

MySQL

DELETE FROM employees
WHERE name = 'Bob Smith'
LIMIT 1;

MongoDB

db.employees.deleteOne({
  employee_id: "E102"
})

Delete Multiple Rows / Documents

MySQL

DELETE FROM employees
WHERE salary < 70000;

MongoDB

db.employees.deleteMany({
  salary: { $lt: 70000 }
})

11. DROP & TRUNCATE

Dropping a Table / Collection

To permanently delete an entire collection (its documents and indexes), use drop().

MySQL

DROP TABLE employees;

MongoDB

db.employees.drop()

Truncating (Empty the Table, Keep It)

MySQL has TRUNCATE TABLE to quickly remove all rows but keep the empty table. MongoDB has no truncate command; the equivalent is deleteMany({}) with an empty filter.

MySQL

TRUNCATE TABLE employees;

MongoDB

db.employees.deleteMany({})

Difference between deleteMany({}) and drop():
• deleteMany({}) removes all documents but keeps the collection and its indexes (like TRUNCATE).
• drop() removes everything, including the collection itself and all indexes (like DROP TABLE). It is generally faster if you intend to recreate the collection from scratch.

13. Doing Everything in MongoDB Compass (GUI)

MongoDB Compass is the official graphical tool. If you are used to MySQL Workbench or phpMyAdmin, Compass is the same idea for MongoDB: you click buttons instead of typing commands. Below, every step shows what the screen looks like (a mock of the real Compass window) and what to click.

Open Compass. On the first screen it asks for a connection string. For a default local server, just use the one already filled in and click Connect.

14. Quick Recap

  • Database: MySQL needs CREATE DATABASE; MongoDB just uses use and creates it on first insert.
  • Table → Collection, Row → Document, Column → Field. No fixed schema in MongoDB.
  • CRUD: insertOne/insertMany, find/findOne, updateOne/updateMany, deleteOne/deleteMany.
  • Conditions: the SQL WHERE becomes a filter object with operators like $gt, $in, $or.
  • Drop vs Truncate: drop() removes the collection; deleteMany({}) empties it but keeps it.
  • Compass lets you do all of this visually, like MySQL Workbench does for MySQL.
