What We're Building

We'll build a simple Employee Management app. It lets you: add a new employee (name + department), list all employees from MySQL, and delete an employee by ID. This covers the full request-response lifecycle in Spring MVC with a Thymeleaf front end.

Why this architecture? Each layer has a single responsibility. The Controller only handles HTTP. The Service only handles business rules. The Repository only talks to the database. This makes the code easy to test and change without breaking everything else.

Maven Dependencies (pom.xml)

Add these four starters to your pom.xml. Spring Boot automatically configures everything when it sees these on the classpath.

XML pom.xml 
<dependencies>

    <!-- 1. Spring MVC web layer (controllers, views) -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>

    <!-- 2. Thymeleaf template engine -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-thymeleaf</artifactId>
    </dependency>

    <!-- 3. Spring Data JPA (Hibernate underneath) -->
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-data-jpa</artifactId>
    </dependency>

    <!-- 4. MySQL JDBC driver -->
    <dependency>
        <groupId>com.mysql</groupId>
        <artifactId>mysql-connector-j</artifactId>
        <scope>runtime</scope>
    </dependency>

    <!-- 5. Lombok — removes boilerplate getters/setters -->
    <dependency>
        <groupId>org.projectlombok</groupId>
        <artifactId>lombok</artifactId>
        <optional>true</optional>
    </dependency>

</dependencies>
Tip — Lombok Lombok is optional but recommended for beginners. It auto-generates getters, setters, constructors, and toString methods using annotations like @Data and @AllArgsConstructor, so you write much less boilerplate code.

application.properties — MySQL Configuration

This file tells Spring Boot how to connect to your MySQL database and how Hibernate should behave. It lives at src/main/resources/application.properties.

Properties application.properties 
# ─────────────────────────────────────────────────────
# DATABASE CONNECTION SETTINGS
# ─────────────────────────────────────────────────────

# The JDBC URL tells Spring where to find MySQL.
# Format: jdbc:mysql://HOST:PORT/DATABASE_NAME?options
spring.datasource.url=jdbc:mysql://localhost:3306/empdb?useSSL=false&serverTimezone=UTC

# Your MySQL username (default is 'root')
spring.datasource.username=root

# Your MySQL password
spring.datasource.password=yourpassword

# The JDBC driver class for MySQL 8+
spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver


# ─────────────────────────────────────────────────────
# JPA / HIBERNATE SETTINGS
# ─────────────────────────────────────────────────────

# Dialect tells Hibernate which SQL "flavor" to generate.
# Use MySQL8Dialect for MySQL 8.x
spring.jpa.properties.hibernate.dialect=org.hibernate.dialect.MySQL8Dialect

# DDL Auto Options:
#   create       — drops and recreates tables every startup (dev only!)
#   create-drop  — creates on start, drops on shutdown
#   update       — alters existing tables to match entities (careful!)
#   validate     — checks table matches entity, throws error if not
#   none         — does nothing (production default)
spring.jpa.hibernate.ddl-auto=update

# Prints every SQL query Hibernate runs (great for debugging)
spring.jpa.show-sql=true

# Formats the printed SQL so it's readable
spring.jpa.properties.hibernate.format_sql=true


# ─────────────────────────────────────────────────────
# SERVER SETTINGS
# ─────────────────────────────────────────────────────

# App runs on http://localhost:8080 by default
# Change this if port 8080 is taken:
server.port=8080

# Thymeleaf caching: false in dev so template changes show instantly
spring.thymeleaf.cache=false
Before you start Create the database in MySQL first: CREATE DATABASE empdb; Then update username/password above to match your local MySQL setup. Hibernate will auto-create the employee table thanks to ddl-auto=update.

04

Entity Class — Employee.java

An Entity is a Java class that is directly mapped to a database table. Each field in the class becomes a column. Each instance of the class represents one row in the table. Hibernate reads these annotations and creates the SQL table for you automatically.

Java entity/Employee.java 
package com.example.empapp.entity;

import jakarta.persistence.*;
import lombok.*;

/**
 * ENTITY — maps directly to the 'employee' table in MySQL.
 * Hibernate reads these annotations and generates SQL automatically.
 */

@Entity                      // Marks this class as a JPA entity (DB table)
@Table(name = "employee")  // The actual table name in MySQL
@Data                        // Lombok: auto-generates getters, setters, equals, toString
@NoArgsConstructor           // Lombok: creates Employee() empty constructor (required by JPA)
@AllArgsConstructor          // Lombok: creates Employee(id, name, dept) constructor
public class Employee {

    @Id                      // This field is the PRIMARY KEY in the table
    @GeneratedValue(strategy = GenerationType.IDENTITY)
        // AUTO_INCREMENT in MySQL: Hibernate never sets this,
    // MySQL assigns it automatically when a row is inserted
    private Long id;

    @Column(name = "name", nullable = false, length = 100)
        // Maps to the 'name' column. Cannot be NULL. Max 100 characters.
    private String name;

    @Column(name = "department", nullable = false, length = 80)
        // Maps to the 'department' column.
    private String department;

    @Column(name = "email", unique = true)
        // unique=true adds a UNIQUE constraint in MySQL
    private String email;
}

When the app starts, Hibernate runs something like this SQL behind the scenes (because of ddl-auto=update):

SQL Generated by Hibernate 
-- Hibernate generates this SQL from your Entity class automatically
CREATE TABLE employee (
    id         BIGINT       NOT NULL AUTO_INCREMENT,
    name       VARCHAR(100) NOT NULL,
    department VARCHAR(80)  NOT NULL,
    email      VARCHAR(255) UNIQUE,
    PRIMARY KEY (id)
);
Key Insight You never write CREATE TABLE yourself. You only write the Java class. Hibernate translates the annotations into SQL DDL automatically. This is the power of JPA.

Entity annotation reference

AnnotationWhat it does
@EntityMarks this class as a JPA-managed entity. Hibernate tracks instances of this class.
@Table(name=)Specifies the actual MySQL table name. If omitted, uses the class name in lowercase.
@IdMarks the primary key column. Every entity must have exactly one.
@GeneratedValueTells JPA how to generate the ID. IDENTITY delegates to MySQL's AUTO_INCREMENT.
@ColumnCustomizes column name, length, nullable constraint, uniqueness, etc.
@Data (Lombok)Generates all getters, setters, equals(), hashCode(), and toString().
@NoArgsConstructorJPA requires a no-argument constructor. Lombok generates it for you.

Repository Interface — EmployeeRepository.java

The Repository is the layer that directly communicates with the database. You don't write any SQL here. You just extend JpaRepository and Spring Data auto-generates all the common database operations for you (save, find, delete, list all, etc.).

Java repository/EmployeeRepository.java 
package com.example.empapp.repository;

import com.example.empapp.entity.Employee;
import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.data.jpa.repository.Query;
import org.springframework.stereotype.Repository;
import java.util.List;
import java.util.Optional;

/**
 * REPOSITORY — talks directly to the MySQL database.
 *
 * By extending JpaRepository<Employee, Long>, Spring Data
 * automatically provides:
 *   save(entity)         → INSERT or UPDATE
 *   findById(id)         → SELECT WHERE id = ?
 *   findAll()            → SELECT * FROM employee
 *   deleteById(id)       → DELETE WHERE id = ?
 *   count()              → SELECT COUNT(*)
 *   existsById(id)       → SELECT COUNT(*) > 0
 *
 * JpaRepository<Employee, Long>:
 *   First type  = The Entity class
 *   Second type = The type of the primary key (@Id field)
 */
@Repository  // Marks this as a Spring-managed repository bean
public interface EmployeeRepository extends JpaRepository<Employee, Long> {

    // ─── DERIVED QUERIES ─────────────────────────────────────────
    // Spring reads the method name and generates SQL automatically.
    // You just declare the method — no implementation needed!
    // ─────────────────────────────────────────────────────────────

    // SELECT * FROM employee WHERE department = ?
    List<Employee> findByDepartment(String department);

    // SELECT * FROM employee WHERE name LIKE '%keyword%'
    List<Employee> findByNameContainingIgnoreCase(String keyword);

    // SELECT * FROM employee WHERE email = ?
    Optional<Employee> findByEmail(String email);

    // ─── JPQL CUSTOM QUERY ───────────────────────────────────────
    // When derived queries get complex, write JPQL manually.
    // JPQL uses class names and field names (not table/column names).
    // ─────────────────────────────────────────────────────────────

    @Query("SELECT e FROM Employee e WHERE e.department = :dept ORDER BY e.name ASC")
    List<Employee> findByDeptSorted(@Param("dept") String dept);

    // ─── NATIVE SQL QUERY ────────────────────────────────────────
    // Use nativeQuery=true when you need raw MySQL SQL.
    // ─────────────────────────────────────────────────────────────

    @Query(value = "SELECT * FROM employee WHERE department = ?1 LIMIT 5",
           nativeQuery = true)
    List<Employee> findTop5ByDept(String dept);
}
How derived query names work Spring reads method names like findByDepartment and automatically generates SQL. The rule is: findBy + FieldName + optional keyword. Keywords include Containing, IgnoreCase, GreaterThan, Between, OrderByNameAsc, and many more. No SQL writing needed!

Built-in JpaRepository methods (free, no code needed)

MethodSQL Equivalent
save(employee)INSERT INTO employee ... or UPDATE employee SET ...
findById(1L)SELECT * FROM employee WHERE id = 1
findAll()SELECT * FROM employee
deleteById(1L)DELETE FROM employee WHERE id = 1
count()SELECT COUNT(*) FROM employee
existsById(1L)SELECT COUNT(*) > 0 FROM employee WHERE id = 1
findAll(Sort.by("name"))SELECT * FROM employee ORDER BY name

Service Layer — EmployeeService.java

The Service layer sits between the Controller and the Repository. It contains the business logic — rules like "you can't add a duplicate email" or "department name must not be empty". The Controller should never talk to the Repository directly; it always goes through the Service.

Why a separate Service layer? Imagine tomorrow you add a REST API alongside your web app. Both the REST Controller and the web Controller can reuse the same Service. Without a Service layer, you'd duplicate business logic in two places.
Java service/EmployeeService.java 
package com.example.empapp.service;

import com.example.empapp.entity.Employee;
import com.example.empapp.repository.EmployeeRepository;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;
import java.util.List;
import java.util.Optional;

/**
 * SERVICE — contains all business logic.
 *
 * Rules this service enforces:
 *  1. No duplicate email addresses allowed
 *  2. Name and department fields must not be blank
 *  3. Handles "not found" gracefully with exceptions
 */
@Service      // Marks this class as a Spring-managed Service bean
public class EmployeeService {

    // @Autowired tells Spring to inject the EmployeeRepository automatically.
    // Spring creates one instance of EmployeeRepository and hands it here.
    // This is called Dependency Injection (DI).
    @Autowired
    private EmployeeRepository employeeRepository;

    // ─── GET ALL EMPLOYEES ───────────────────────────────────────
    public List<Employee> getAllEmployees() {
        return employeeRepository.findAll();
        // Calls: SELECT * FROM employee
    }

    // ─── GET ONE EMPLOYEE BY ID ──────────────────────────────────
    public Employee getById(Long id) {
        // findById returns Optional<Employee> — it might be empty if ID doesn't exist
        return employeeRepository.findById(id)
            .orElseThrow(() ->
                new RuntimeException("Employee not found with id: " + id));
    }

    // ─── SAVE (INSERT OR UPDATE) ─────────────────────────────────
    // @Transactional: if any error happens during save, the whole
    // operation is rolled back. Database stays consistent.
    @Transactional
    public Employee saveEmployee(Employee employee) {

        // BUSINESS RULE 1: No blank name
        if (employee.getName() == null || employee.getName().isBlank()) {
            throw new IllegalArgumentException("Employee name cannot be blank");
        }

        // BUSINESS RULE 2: No duplicate email
        if (employee.getEmail() != null) {
            Optional<Employee> existing =
                employeeRepository.findByEmail(employee.getEmail());
            if (existing.isPresent() && !existing.get().getId().equals(employee.getId())) {
                throw new IllegalArgumentException("Email already in use: " + employee.getEmail());
            }
        }

        // If validation passes, save to DB.
        // save() does INSERT if id is null, UPDATE if id is set.
        return employeeRepository.save(employee);
    }

    // ─── DELETE ──────────────────────────────────────────────────
    @Transactional
    public void deleteEmployee(Long id) {
        // Check if employee exists before deleting
        if (!employeeRepository.existsById(id)) {
            throw new RuntimeException("Cannot delete — employee not found: " + id);
        }
        employeeRepository.deleteById(id);
    }

    // ─── SEARCH BY DEPARTMENT ────────────────────────────────────
    public List<Employee> getByDepartment(String dept) {
        return employeeRepository.findByDepartment(dept);
    }

    // ─── SEARCH BY NAME KEYWORD ──────────────────────────────────
    public List<Employee> searchByName(String keyword) {
        return employeeRepository.findByNameContainingIgnoreCase(keyword);
    }
}
@Transactional explained Imagine you're saving an employee and it fails halfway (e.g., due to a DB constraint). Without @Transactional, a partial save might corrupt your data. With it, if anything fails, the entire operation is undone (rolled back) automatically. Always annotate methods that write to the DB with @Transactional.

Controller — EmployeeController.java

The Controller is the entry point for every HTTP request. Spring MVC maps URL paths to controller methods. It's the traffic director — it receives a request, calls the Service to get data, puts data into a Model object, and returns the name of a Thymeleaf template to render.

Java controller/EmployeeController.java 
package com.example.empapp.controller;

import com.example.empapp.entity.Employee;
import com.example.empapp.service.EmployeeService;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.*;

/**
 * CONTROLLER — handles HTTP requests and maps them to service calls.
 *
 * URL routes handled here:
 *   GET  /employees           → list all employees
 *   GET  /employees/new       → show the "add employee" form
 *   POST /employees/save      → process the form submission
 *   GET  /employees/edit/{id} → show the "edit employee" form
 *   GET  /employees/delete/{id} → delete and redirect
 */
@Controller                    // Marks this as a Spring MVC Controller
@RequestMapping("/employees") // All URLs in this class start with /employees
public class EmployeeController {

    @Autowired
    private EmployeeService employeeService;

    // ─────────────────────────────────────────────────────────────
    // GET /employees
    // Lists all employees and puts them into the Model.
    // The Model is like a bag of data passed to the HTML template.
    // ─────────────────────────────────────────────────────────────
    @GetMapping
    public String listEmployees(Model model) {

        // Call service → gets all employees from DB
        model.addAttribute("employees", employeeService.getAllEmployees());

        // Also add total count for display in the view
        model.addAttribute("total", employeeService.getAllEmployees().size());

        // Return "employees" → Spring looks for templates/employees.html
        return "employees";
    }

    // ─────────────────────────────────────────────────────────────
    // GET /employees/new
    // Shows a blank form to add a new employee.
    // We add an empty Employee object so Thymeleaf can bind to its fields.
    // ─────────────────────────────────────────────────────────────
    @GetMapping("/new")
    public String showAddForm(Model model) {
        model.addAttribute("employee", new Employee());
        model.addAttribute("formTitle", "Add New Employee");
        return "employees";
    }

    // ─────────────────────────────────────────────────────────────
    // POST /employees/save
    // Processes form submission. Spring binds the form fields to
    // the Employee object automatically using @ModelAttribute.
    //
    // @ModelAttribute("employee") means:
    //   Look at the POST request body, find all fields named "name",
    //   "department", "email", etc., and fill the Employee object.
    // ─────────────────────────────────────────────────────────────
    @PostMapping("/save")
    public String saveEmployee(@ModelAttribute("employee") Employee employee,
                                Model model) {
        try {
            employeeService.saveEmployee(employee);
            // After successful save, redirect to list page.
            // "redirect:" tells Spring to send HTTP 302 to the browser.
            return "redirect:/employees";

        } catch (Exception e) {
            // If validation fails, show the form again with an error message
            model.addAttribute("error", e.getMessage());
            model.addAttribute("employee", employee);
            model.addAttribute("formTitle", "Add New Employee");
            model.addAttribute("employees", employeeService.getAllEmployees());
            return "employees";
        }
    }

    // ─────────────────────────────────────────────────────────────
    // GET /employees/edit/{id}
    // Shows a pre-filled edit form for an existing employee.
    // @PathVariable reads the {id} from the URL.
    // ─────────────────────────────────────────────────────────────
    @GetMapping("/edit/{id}")
    public String showEditForm(@PathVariable Long id, Model model) {
        model.addAttribute("employee", employeeService.getById(id));
        model.addAttribute("formTitle", "Edit Employee");
        model.addAttribute("employees", employeeService.getAllEmployees());
        return "employees";
    }

    // ─────────────────────────────────────────────────────────────
    // GET /employees/delete/{id}
    // Deletes the employee and redirects back to the list.
    // We use GET (not DELETE) because HTML forms only support GET/POST.
    // ─────────────────────────────────────────────────────────────
    @GetMapping("/delete/{id}")
    public String deleteEmployee(@PathVariable Long id) {
        employeeService.deleteEmployee(id);
        return "redirect:/employees";
    }

    // ─────────────────────────────────────────────────────────────
    // GET /employees/search?keyword=Alice
    // Searches employees by name keyword.
    // @RequestParam reads the query parameter from the URL.
    // ─────────────────────────────────────────────────────────────
    @GetMapping("/search")
    public String search(@RequestParam(required = false) String keyword, Model model) {
        List<Employee> results = (keyword != null && !keyword.isBlank())
            ? employeeService.searchByName(keyword)
            : employeeService.getAllEmployees();
        model.addAttribute("employees", results);
        model.addAttribute("keyword", keyword);
        model.addAttribute("employee", new Employee());
        return "employees";
    }
}

Thymeleaf HTML Template — employees.html

Thymeleaf is a server-side template engine. It processes your HTML on the server and replaces the th: attributes with real data from the Model before sending the final HTML to the browser. The file lives at src/main/resources/templates/employees.html.

Key Thymeleaf attributes th:text → replaces the element's content with a variable value.
th:each → loops over a list, like a for-each.
th:action → sets the form's submit URL.
th:object → binds a form to a Java object.
th:field → binds an input to a field on the bound object.
th:if / th:unless → conditional rendering.
th:href → generates a URL with @{/path}.
${variable} → reads a model attribute.
HTML + Thymeleaf templates/employees.html 
<!DOCTYPE html>
<!--
  xmlns:th="http://www.thymeleaf.org"
  This line activates Thymeleaf — it tells the HTML parser
  that "th:" is a valid custom attribute prefix.
-->
<html lang="en" xmlns:th="http://www.thymeleaf.org">
<head>
    <meta charset="UTF-8"/>
    <title>Employee Management</title>
    <link rel="stylesheet"
          href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.0/dist/css/bootstrap.min.css"/>
</head>
<body>
<div class="container mt-4">

    <!-- PAGE TITLE -->
    <h1>Employee Management</h1>

    <!--
      th:text = replaces the content of <span> with the value
      of the "total" model attribute.
      ${total} reads from Model.addAttribute("total", ...)
    -->
    <p>Total employees: <strong th:text="${total}">0</strong></p>

    <!-- ─────────────────────────────────────────
         ERROR MESSAGE — shown only when "error" exists in model
         th:if = renders this div only when ${error} is not null
    ───────────────────────────────────────── -->
    <div class="alert alert-danger"
         th:if="${error}"
         th:text="${error}">
    </div>

    <!-- ─────────────────────────────────────────
         ADD / EDIT FORM
         th:action = the URL where this form submits to
           @{/employees/save} generates: /employees/save
         th:object = binds the form to the "employee" model attribute
           (the Employee object from Model.addAttribute("employee", ...))
         method="post" = HTTP POST request
    ───────────────────────────────────────── -->
    <form th:action="@{/employees/save}"
          th:object="${employee}"
          method="post">

        <!--
          th:field = binds this input to the "id" field of the Employee object.
          This renders as: <input type="hidden" name="id" value="5">
          It's essential for UPDATE operations — tells the service "edit this id"
          instead of creating a new one.
        -->
        <input type="hidden" th:field="*{id}" />

        <div class="mb-3">
            <label class="form-label">Full Name</label>
            <!--
              *{name} — the * syntax means "field of th:object"
              So *{name} means employee.getName()
              This input will be pre-filled when editing an employee.
            -->
            <input type="text"
                   class="form-control"
                   th:field="*{name}"
                   placeholder="Enter employee name"
                   required />
        </div>

        <div class="mb-3">
            <label class="form-label">Department</label>
            <input type="text"
                   class="form-control"
                   th:field="*{department}"
                   placeholder="e.g., Engineering"
                   required />
        </div>

        <div class="mb-3">
            <label class="form-label">Email</label>
            <input type="email"
                   class="form-control"
                   th:field="*{email}"
                   placeholder="employee@example.com" />
        </div>

        <!--
          Dynamic button label:
          th:text shows "Update Employee" when editing (id not null),
          otherwise shows "Add Employee".
        -->
        <button type="submit"
                class="btn btn-primary"
                th:text="${employee.id != null} ? 'Update Employee' : 'Add Employee'">
            Save
        </button>

        <!-- Cancel link — only visible when editing -->
        <a th:if="${employee.id != null}"
           th:href="@{/employees}"
           class="btn btn-secondary ms-2">Cancel</a>
    </form>

    <!-- ─────────────────────────────────────────
         SEARCH FORM
    ───────────────────────────────────────── -->
    <form th:action="@{/employees/search}" method="get" class="mt-4 d-flex gap-2">
        <input type="text"
               name="keyword"
               class="form-control"
               placeholder="Search by name..."
               th:value="${keyword}" />
        <button type="submit" class="btn btn-outline-secondary">Search</button>
        <a th:href="@{/employees}" class="btn btn-outline-secondary">Reset</a>
    </form>

    <!-- ─────────────────────────────────────────
         EMPLOYEE TABLE
         th:each loops over the "employees" model attribute.
         "emp : ${employees}" means:
           for each Employee in the list, call it "emp"
           then use ${emp.name}, ${emp.department}, etc.
    ───────────────────────────────────────── -->
    <table class="table table-striped mt-4">
        <thead class="table-dark">
            <tr>
                <th>#</th>
                <th>Name</th>
                <th>Department</th>
                <th>Email</th>
                <th>Actions</th>
            </tr>
        </thead>
        <tbody>

            <!-- th:each iterates over the list -->
            <tr th:each="emp : ${employees}">

                <!-- th:text reads emp.id, emp.name, etc. -->
                <td th:text="${emp.id}"></td>
                <td th:text="${emp.name}"></td>
                <td th:text="${emp.department}"></td>
                <td th:text="${emp.email}"></td>

                <td>
                    <!--
                      th:href with @{} syntax for URL generation.
                      (emp.id) inserts the employee's actual ID.
                      Generates: /employees/edit/5
                    -->
                    <a th:href="@{/employees/edit/{id}(id=${emp.id})}"
                       class="btn btn-sm btn-warning">Edit</a>

                    <!-- Delete link generates: /employees/delete/5 -->
                    <a th:href="@{/employees/delete/{id}(id=${emp.id})}"
                       class="btn btn-sm btn-danger ms-1"
                       onclick="return confirm('Delete this employee?')">Delete</a>

How It All Connects — Step by Step

Scenario A: User opens the employee list page

  1. Browser sends GET /employees to your Spring Boot server on port 8080.

  2. Spring MVC finds EmployeeController.listEmployees() because it matches @GetMapping on /employees.

  3. Controller calls employeeService.getAllEmployees().

  4. Service calls employeeRepository.findAll() — no business logic needed for a simple list.

  5. Repository runs SELECT * FROM employee against MySQL and returns a List<Employee>.

  6. The list travels back: Repository → Service → Controller. Controller does model.addAttribute("employees", list).

  7. Controller returns the string "employees". Spring looks for templates/employees.html.

  8. Thymeleaf processes the template. It replaces th:each="emp : ${employees}" by rendering one <tr> per employee.

  9. The complete HTML page is sent to the browser. The user sees the table.

Scenario B: User submits the "Add Employee" form

  1. User fills in name, department, email and clicks "Add Employee". The browser sends POST /employees/save with form data in the request body.

  2. Spring finds EmployeeController.saveEmployee() via @PostMapping("/save").

  3. @ModelAttribute("employee") tells Spring to read the POST body fields (name, department, email) and fill an Employee object automatically.

  4. Controller calls employeeService.saveEmployee(employee).

  5. Service runs business rules: checks blank name, checks duplicate email. If invalid, throws an exception.

  6. If valid, Service calls employeeRepository.save(employee). Since employee.id is null (new employee), Hibernate runs INSERT INTO employee .... MySQL assigns an auto-incremented ID.

  7. Control returns to the Controller. It returns "redirect:/employees".

  8. Spring sends HTTP 302 to the browser. Browser automatically sends a new GET /employees request.

  9. The list page loads again, now showing the newly added employee.

Scenario C: User clicks "Edit"

  1. User clicks the Edit button next to employee ID 5. Browser sends GET /employees/edit/5.

  2. @PathVariable Long id captures the value 5 from the URL.

  3. Controller calls employeeService.getById(5) → Repository fetches SELECT * FROM employee WHERE id = 5.

  4. The existing Employee object (with all its field values) is added to the Model.

  5. Thymeleaf renders the form. Because th:field="*{name}" is bound to the employee object, the name input is pre-filled with "Alice". The hidden id field carries the value 5.

  6. User edits the name and submits. POST /employees/save runs again, but this time employee.id = 5 is not null.

  7. Repository's save() detects the existing ID and runs UPDATE employee SET name=... WHERE id=5 instead of INSERT.

The hidden ID field is crucial The hidden <input th:field="*{id}" type="hidden"> in the form carries the employee's ID from the edit page back to the save controller. Without it, employee.id would be null and Hibernate would INSERT a new row instead of updating the existing one.

Common beginner mistakes 1. Forgetting the hidden ID field in an edit form causes UPDATE to become INSERT.
2. Using @RestController instead of @Controller makes Spring return raw JSON/text, not HTML views.
3. ddl-auto=create in production will wipe your entire database on every restart.
4. Not using redirect after POST causes the form to re-submit if the user refreshes the page (the "double-submit" problem).
5. Not setting both sides of a bidirectional relationship in JPA can cause stale data in the second-level cache.
