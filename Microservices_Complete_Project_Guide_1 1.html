POINT 1

Eureka Server — Services Find Each Other by Name

Problem
Hardcoded URL: http://localhost:8081. If product-service moves port, scales to 3 instances, or restarts on a different port — all callers break immediately.
Solution
Every service registers with Eureka by name. Callers ask Eureka for the name. Eureka returns a current, live address. Services can scale or move without any config change.
Heartbeat
Every 30 seconds, each service sends a heartbeat to Eureka saying 'I am still alive.' If heartbeats stop, Eureka removes it after 90 seconds. Dead services are never returned.

POINT 2

API Gateway — One Entry Point for All Services

Problem
Without a Gateway, every client must know every port (8081, 8082, 8085). Add a new service and every mobile app, web app, and partner integration needs updating.
Solution
One address for everything: port 8080. The Gateway reads the URL path, finds the right service via Eureka, and forwards — all in under 5 milliseconds.
JWT check
When auth-service is added (Point 4), the Gateway filter checks the JWT token on every request. One check protects all services.

How Routes Are Checked — Order Matters

Gateway Route Matching Order
✓Request: GET /api/products/1checking...
✓routes[0]: Path=/api/products/**MATCH — use this route and stop
✓routes[1]: not checked (already matched)skipped
✓routes[2]: not checked (already matched)skipped
Rule: Gateway checks routes in index order. First match wins. If NO route matches: 404.

POINT 4

Spring Security + JWT — Protect Every API

Problem
All APIs are open. Anyone can call DELETE /api/products/1 without logging in.
Solution
auth-service handles login and issues JWT tokens. The Gateway checks the token on every request. Services behind the Gateway never need to check tokens themselves.
JWT structure
Three parts separated by dots: header (algorithm), payload (email + expiry), signature (proves not tampered). Verified instantly with the shared secret — no database call needed.

Docker — Package and Deploy Everything (Do This Later)

Remember: Complete all of Points 1–5 with a fully working and tested system before starting Docker. Adding Docker to a broken system makes every error harder to debug.

Docker packages each service into a container — an isolated unit that runs identically on any machine. Instead of starting 6 services manually, one command (docker-compose up) starts everything.

Key: Most important Docker concept: inside a Docker container, localhost means the container itself — NOT another container. All localhost references must change to Docker service names. http://localhost:8761/eureka/ becomes http://eureka-server:8761/eureka/.
